### D-08 运镜缺「起点—路径—终点」 —— **部分采纳**

| 建议方向 | 处置 |
| --- | --- |
| ① `camera` 增 `from` / `to` | **已采纳**：§3.6 增 `camera.from`（起幅，如「桥面高度、桥心偏左」）与 `camera.to`（落幅，如「落在眼部特写、直视镜头」） |
| ② 运镜项明确为「运动描述」而非「运动类型」 | **已采纳**：§3.7.2 明确 `camera.move` 是**内部语义标签**，运动描述由 `from` / `to` + `amplitude` / `speed` 共同承载 |
| ③ 简单运镜给起点终点；复杂运镜给「起点 → 中间 → 终点」 | **未逐字采纳**：V1.1 **只给两点**（`from` / `to`），不引入第三「中间点」字段 |

**未采纳理由**：①「中间点」不是 H3 等目标模型的表达单位，H3 运镜是**单句末句**，多写一个路径点只会稀释该句的语法完整性；② 复杂运动的「中段变化」在本规范中已有承载位——`action.change`（§4.6 动作三段状态）与 `shot_language.result`（画面结果）；③ 增加第三字段会让「简单运镜」也被迫填三点，与「按需填、不冗余」的编写纪律冲突。

**兜底**：§4.6 动作三段 + §3.6 `camera.from/to` 组合后，可等价表达评审要的「推到哪里停住」这类确定性结果；且 §6.6 明确「复杂运镜超时长上限 → 按语义边界拆镜」。

### D-09 缺光学维度（焦距/景深/焦点） —— **已采纳**

`camera.optics`（`deep_focus` / `shallow_focus` / `rack_focus` / `long_lens_compression` / `wide_angle_distortion`）已入 §3.6 与 §3.7.4，光学词表入 §3.7.4，并与 §4.2 质量门挂钩（光学覆盖 ≥30%）。**落点**：§3.6、§3.7.4、§4.2、schema、`config/CFG-002_shot_vocab.yaml`（`camera_optics`）。

### D-10 缺「动作起止状态」与「动作复杂度—时长预算」 —— **已采纳**

`action{start, change, end}` 已入 §3.6（必填）；动作复杂度—时长参考表入 §4.6（含「复合动作 ≥8s，**必须拆镜**」）；与 §6.6 时长上下限联动。schema：`action.required = [start, change, end]`。**落点**：§3.6、§4.6、§6.6、schema。

### D-11 缺「台词—时长」校验 —— **已采纳**

§4.5 增语速约束：`dialogue 字数 ÷ (duration_ms/1000) ≤ 9`，超标**提示并给出建议时长**，处置**限定为只延长时长、不改画面**。`validate_pack.py` 实测：`镜头 S01-SH002 台词 54 字 / 5s = 10.8 字/秒 > 9 → 须延长时长至 ≥ 6000ms`。**落点**：§4.5、§8.3、§11、`validate_pack.py`（`dialogue.rate`）。

### D-12 适配 10 维里没有「声音结构」 —— **部分采纳**

| 建议方向 | 处置 |
| --- | --- |
| ① §5.3 增第 11 维「声音组织方式」 | **已采纳**：§6.3 增第 11 维「声音组织方式」（单字段合并 / 分轨字段 / 逐镜标注） |
| ② 明确 H3 需跨镜聚合成两条音轨，并规定聚合规则 | **已采纳**：§6.4 P0-1 规定环境音取并集去重、配乐按段落归并 |
| ③ 在 `meta` 或新增块中增 `soundscape` / `music` 两个**包级**字段作为聚合容器 | **部分采纳**：聚合容器下沉到**单元级** `units[].soundscape` / `units[].music`，未设为**包级** |

**未采纳理由（落点调整）**：H3 的 `overall_soundscape` / `non_diegetic_music` 是**整条生成单元的**音轨，而一个交付包可含**多个生成单元**。若设为包级字段，多单元音轨会互相覆盖；设为单元级，恰好与「**一次生成 = 一个单元**」的粒度对齐（§3.5、§4.3 已确立单元为生成粒度）。语义等价、粒度更准。

**兜底**：schema `unit.required` 已含 `soundscape` / `music`；§6.4 P0-1 给出「单元音轨 → H3 三字段」的投影规则。

## 3 P2 质量提升（8 条）逐条复查

### D-16 负向词表缺视频专属项 —— **已采纳**

按**三类组织**：通用图像项 + **视频时域项**（`flicker` / `temporal jitter` / 帧间不一致）+ **场景专属项**（`clipping` / `morphing` / 肢体跨帧跳变）。**落点**：§3.3、§6.4、§10、`config/CFG-002_shot_vocab.yaml`（`negative_categories` 四类）。

### D-17 风格锚点缺「数量规则」 —— **已采纳**

`style_bible.style_anchors[]`（**3–5 条**）已入 §3.3，并规定「`prompt_*` 中不得出现锚点清单之外的风格词」（锚点封闭规则）。schema：`styleBible.required` 含 `style_anchors`，`minItems 3 / maxItems 5`；`validate_pack.py` 有 `style.anchors` / `style.drift` 校验。**落点**：§3.3、§4、schema、`validate_pack.py`。

### D-18 `camera.angle` 混装两个正交维度 —— **已采纳**

拆为 `camera.height`（`eye_level` / `low` / `high` / `overhead` / `ground`）与 `camera.roll`（`level` / `dutch` / `roll_cw` / `roll_ccw`）；§3.7.3 说明 H3 侧 `Roll Clockwise` / `Roll Counterclockwise` 为**独立运镜类型**及**归并规则**；`validate_pack.py` 有 `camera.roll_dup` 校验（避免 roll 与 move 重复表达）。**落点**：§3.6、§3.7.3、§3.7.7、schema、`config/CFG-002_shot_vocab.yaml`（`camera_height` / `camera_roll`）。

### D-19 适配文件的「首行标识」与「可投喂性」冲突 —— **已采纳**

§6.8 改为**两段式**：标识区（标注「请勿复制」）+ 分隔线「以下为提示词区，请从此行以下复制」+ 提示词区；**两段都保留**。§9.2 各格式标识注入同步。**落点**：§6.8、§9.2、§1.4、`config/CFG-001_model_adapters.yaml`（`two_section_output` / `mark_section` / `mark_divider` / `copy_hint`）、`schemas/CFG-005_manifest.v1.schema.json`（`fileEntry.two_section`）。

### D-20 缺「枚举 — 中文字面 — 英文句法」三向映射表 —— **已采纳**

§3.7.7 新增**三向映射表**（内部枚举 ↔ 中文用词 ↔ H3 英文句法 ↔ Seedance / 可灵 / 即梦 ↔ 不支持时降级），以 `CFG-002_shot_vocab.yaml` 为源。**落点**：§3.7.7、§6.5、`config/CFG-002_shot_vocab.yaml`。

### D-21 缺「任务类型」维度 —— **部分采纳**

| 建议方向 | 处置 |
| --- | --- |
| ① `meta` 增 `task_type` | **已采纳**：§3.2 增 `meta.task_type`（6 个任务类型）+ 任务类型表（§6.3） |
| ② 补 Ref2VA 分支结构（六段）与素材上限表 | **部分采纳**：**H3 的 Ref2VA 六段式与素材上限已在 §6.4 写明**（`subject_definitions → summary → retention_analysis → detailed_description → overall_soundscape → non_diegetic_music`；图 ≤9 / 视频 ≤3 / 音频 ≤3）；但**本期未把「参考生成 / 续写 / 编辑 / 音频复用」做成可交付分支** |
| ③ 若本期只做文生，也应显式声明「暂不支持哪些任务类型及理由」 | **已采纳**：§3.2 增 `meta.unsupported_task_types`，逐项声明不支持及其理由 |

**未完全采纳理由**：本期交付范围（SYS-Q4 基线）为**文生 / 首帧**一种形态；把参考生成 / 续写 / 编辑 / 音频复用做成完整可交付分支，属于**功能范围扩张**，不是本次修订可承载的改动。V1.1 采取的处置是：**把六段式骨架与素材上限写进适配层备用（不丢失知识），但把任务类型选择权显式收敛并留痕**（`unsupported_task_types`），避免评审担心的「留空会让客户以为支持」。排期已记入 §13 **NT-08**。

> 这与评审「留空会让客户以为支持」的诉求**方向一致**——用**显式声明不支持**代替**沉默**。

### D-22 多主体镜次缺约束（主体唯一性） —— **已采纳**

§4.4「单人替身法则与主体唯一性」：规定**单镜主体上限**与**多主体区隔要求**（前后景分离 / 左右分侧 / 一主一虚），沿用项目已确立的**单人替身法则**。**落点**：§4.4、§3.4、§3.6（`character_refs`）。

### D-23 「人工核对」项未闭环进自检清单 —— **已采纳**

「**角色一致性 / 跨镜连续性**」列为 §8.3 自检清单**独立检查项**，记录**结果 + 检查时间 + 检查人**，纳入 §8.4 留档（≥6 个月）。**落点**：§8.3（第 18 项）、§8.4、`templates/AST-004_compliance_statement_v1.md`（自检表含「检查人」列）、`schemas/CFG-005_manifest.v1.schema.json`（`human_review`）。
