### 0.2 总判断

> **这份模板把「不编造」立成了纪律，把「叙事骨架」给齐了；但它没有为「视觉」留下任何一个字段——于是下游拿到的是一份"叙事上完整、视觉上全空"的梗概；而这份空白既不可见（没有缺口标记），也不可追溯（没有字段路径），只能由下游自行填充。**

更锋利的一句：

> 模板的硬约束「客户未提供的关键信息写『未指定』」（模板 L47）**只对叙事层生效**——因为视觉层在本模板里**连一个能写"未指定"的字段都没有**。约束的容器不在，约束就落不了地。

**这不是模型能力问题，是字段设计问题。** 且这笔债不会在链路中途消失：它会在第 4 段（v1.1 的 `characters` / `style_bible`）一次性还本付息。

## 2 P0 阻断级（2 条）

> 这 2 条的共同特征：**不是"缺功能"，而是"缺容器"**——模板承诺了不编造，却没有能承载"视觉未知"的地方，于是下游必然编造。

### R-01 视觉一致性锚在模板中无字段容器，链路上亦无明确首次定义责任段 ★

| 项 | 内容 |
| --- | --- |
| 位置 | 模板 L79–84（`protagonist`）、L85–89（`world`）、L95–97（`supporting`）；用例 L34–39、L40–44、L50–52 |
| 下游对照 | v1.1 §3.4 L357–366（`characters[]`：`character_id` / `appearance_lock_zh` / `appearance_lock_en` / `ref_image` / `forbidden`）；§3.3 L324–331（`style_bible`：`style_id` / `style_prompt_zh` 30–80 字 / `style_anchors` **固定 3–5 条**）；§3.1 L269（一致性锚为何要独立） |

**问题（导演视角）**：本模板对角色只给了 `name` / `identity` / `goal` / `flaw` 四个字段（L79–84），对 `supporting[]` 只给了 `name` / `role` / `relation`（L95–97）——**没有稳定标识，也没有任何外观字段**。而 v1.1 要求角色外观"**只在此处定义一次**"（L368），位置在交付包的 `characters` 数组。

**证据**：

- 模板 L79–84 与 L95–97 的字段清单中，不存在任何形如 `appearance` / `look` / `ref_id` 的承载位；
- 用例 L35 与 L51 的 `name` 值**均为「未指定」**——即在实例中，连"名字"这个最基本的标识都是空的；
- 用例 L41 `world.setting` 给了一处物理信息（"当代城市，暴雨夜的居民区与次日清晨的街巷"），但它停留在 `world` 层，**未投影到任何一场**（见 R-03）；
- 用例 L42 `world.tone` = "克制温情"（**4 字**），距 v1.1 §3.3 L329 / L331 要求的 30–80 字风格串与 3–5 条风格锚之间，**没有任何中间承载**。

**影响**（逐条对应承继四问）：

1. **角色锚悬空**：外观的**首次定义责任在链路中没有归属**。本模板无字段 → SW-005 剧本阶段的验收标准只写"角色/设定与梗概一致"（软件级需求文档 L51），**未要求外观** → SW-006 只做"景别/机位/运镜/时长/构图"标注（同 L52），**不含外观** → 直到第 4 段 `characters` 才被要求定义外观，**此时已历经 3 次生成**，漂移风险最大。
2. **「零漂移」失去比对基准**：SW-002 要求"数字/专名/设定零漂移"（同 L43），而本模板产出的专名在用例中恰为「未指定」——**上游没有稳定标识，下游无从校验漂移**。一致性校验需要有"锚"可比，锚为空则校验退化为形式动作。
3. **风格锚断层**：`genre`（L78）+ `world.tone`（L87）是**情绪/题材词**，不是**视觉词**；v1.1 §3.3 L344 要求"锚点封闭"（`prompt_*` 中不得出现锚点清单之外的风格词），而锚点清单在上游根本没被孕育出来。

**建议方向**（不代拟修订稿，只给方向）：

- 为 `protagonist` 与 `supporting[]` 增加 **稳定标识 + 外观占位**两类字段，**允许整体取值为"未指定"**——关键在于使"外观待定"成为一个**被记录的字段状态**，而非一片空白；
- 把 `world.setting` 中的物理信息**结构化下沉**到 `scenes_outline` 每一场（配合 R-03 的最小可拍集）；
- 为 `world.tone` 增加约束：要求给出**视觉形容词**（而非纯情绪词），或**显式声明"风格串在剧本阶段定义、本阶段只给气质"**——两种情况都必须写清楚，不能留空。

> **需责任方先拍板一件事**：外观与风格串的**首次定义**放在链路的哪一段（建议不晚于剧本层）。这个决定必须写进模板注释，否则每次换模板都会重现同一个洞。

### R-02 `unspecified` 只覆盖叙事层，且为自由文本数组——视觉层缺口在链路中既不可见也不可追溯 ★

| 项 | 内容 |
| --- | --- |
| 位置 | 模板 L108（字段定义）、L47（硬约束 1）、L134–135（guards）、L139（fallback） |
| 实例 | 用例 L68 |
| 对应判据 | 承继四问第 **④ 问**（请求书 §2 称"本次评审最要紧的一问"） |

**问题（导演视角）**：模板为**叙事层**的缺失设计了双机制——字段内写"未指定"（L47 硬约束 1 + L79 示例）+ 顶层 `unspecified` 汇总；但**视觉层根本没有字段**，因此：

- **写不了"未指定"**：没有容器（见 R-01）；
- **进不了 `unspecified`**：`unspecified` 的定义是"客户未提供、**但下游需要确认**的关键信息"（L108）——而视觉维度未被建模，不会被识别为"关键信息"；
- **下游机器读不到**：`unspecified` 是 `string[]`，元素是**人名式短串**，没有字段路径、没有责任阶段、没有降级值。

**证据**：

- 模板 L108 仅给出类型与一句话释义，**未规定元素结构**；
- 用例 L68 的实际取值是 `["主角姓名", "妹妹姓名", "失联的具体年数", "失联原因"]`——**四项全部是叙事层信息，无一项涉及视觉**（外观、光线、场景物理特征、镜头偏好一项未列）；
- 模板 L135 要求"要点若无法融入故事…须写入 `unspecified` 并说明原因"，但**数组元素如何同时承载"信息系统"与"原因"未作规定**——即规则本身不可执行。

**影响**：

1. **自动化链路中缺失项不可枚举**：下游 SW-005~007 无法用脚本判断"视觉层是否待补"，只能靠人读 JSON；这与模板"供机器核查"的设计意图（manifest.yaml L38 明写 `covered_points` 用于"供机器核查"）**形成对比**——同一份输出里，叙事层为机器可读、视觉层为人读。
2. **视觉空白不可见**：下游默认"梗概已完整"，直接开始编造角色长相与场景细节。
3. **与模板自身约束精神冲突**：模板第 1 条硬约束的立意是"不得用看起来合理的虚构值填充"（L45–47）。该约束**只约束了第 1 段的模型**；第 1 段之后的编造，**没有任何机制记录、也没有任何人被通知**。

**直接回答请求书 §2 的设问**：

> 这份梗概**不是**"下游拿到后必须自己编造才能用"的产物——因为叙事层确实给全了；
> 但它**也不是**"下游明确知道缺什么"的产物——因为视觉层的缺口没有任何机器可读的表达。
> 它是**第三种**："下游必须自己补一层视觉描述，而**无人告知哪些是补的、哪些是原生的**"。

**建议方向**：

- 把 `unspecified` 从"人名清单"升级为**可机器读的缺口记录**，每条至少三项：`field`（缺哪一层/哪个字段）、`fill_stage`（应由剧本 / 分镜 / 提示词哪一段补）、`fill_fallback`（补不上时降级为什么）；
- 明确规定 **`unspecified` 与各字段内"未指定"的一致性规则**（例如：凡字段值为"未指定"者，必须存在对应 `unspecified` 条目），使两者互为校验、不留盲区。用例 L35/L38/L51 与 L68 之间目前是"作者自觉对齐"，**模板未强制**。

## 3 P1 妨碍可用（6 条）

### R-03 `scenes_outline` 提供的是叙事事件而非可拍场景；场景物理锚未落到场级，场号映射亦无约定

| 项 | 内容 |
| --- | --- |
| 位置 | 模板 L98–100；用例 L54–58 |
| 下游对照 | v1.1 §3.6 L419（`shots[].scene_no`）、§3.5 L388（`units[].scene_no`）、§3.5 L407（拆单元须保持锚点）、§3.4 L376–377（单镜主体上限与同框区隔） |

**问题**：请求书第 ③ 问直指此处——`scenes_outline` 提供的是**叙事事件**（发生了什么），不是**可拍场景**（在哪、什么时相、谁在场、有哪些可见动作）。四项中只有第一项被承载。

**证据**：

- 模板 L99 字段集为 `no` / `beat`(≤40 字) / `purpose`——**无 `location`、无 `time_of_day`、无 `present`（在场角色）**；
- 用例 L54–58 五条 beat 中，唯二含物理信息的是第 1 场"暴雨夜送单途中，主角在**楼道口**发现…"（L54）与第 3 场"次日清晨…找到对方**住处**"（L56）——地点以**短语形式嵌在事件句里**，未被结构化为可索引的参数；
- 用例 L41 的 `world.setting` 提供了"居民区与次日清晨的街巷"这类物理信息，但**未投影到任何一场**；
- 下游 v1.1 以场号索引（L388、L419），但**模板未约定下游必须沿用本模板的 `no`**。

**影响**：

1. SW-005（需求 L51）要把每条 ≤40 字 beat 膨胀为带对白与场景的剧本，**每场的地点名、时相、在场角色需自行发明**；这些发明**不会回写梗概**，导致梗概 `scenes_outline` 与最终镜头之间**缺少可校验的对应链**——`covered_points.covered_in` 只追到"第几场"（用例 L65），追不到"哪一镜"；
2. 跨场空间连续性在梗概层**无锚可依**：v1.1 §3.5 L407 要求拆单元时保持锚点，前提是锚存在；
3. "谁在场"缺失，直接影响 v1.1 §3.4 L376–377 的**主体唯一性与同框区隔**判断——这项约束在分镜阶段才落地，而判断依据（在场者）在源头未给。

**建议方向**：为 `scenes_outline` 每条补一个**最小可拍集**（建议 ≤3 项，避免把梗概写成分镜）：`location`（可识别地点标识）、`time_of_day`（时相）、`present`（在场角色引用，可为"未指定"）；同时补一条**接缝约定**——下游 `scene_no` 沿用本模板 `no`，否则 `covered_points.covered_in` 的追溯能力会在链路中失效。

### R-04 `target_duration` 变量已接收，但未分配到场景/镜头，下游无时长预算依据

| 项 | 内容 |
| --- | --- |
| 位置 | 模板 L16–19（变量定义）、L61（注入 task）、L74–109（output 结构） |
| 下游对照 | v1.1 §3.6 L430（`duration_ms` **必须为整秒**，受模型上下限双重约束）、§3.5 L398–399（单元 **2–3 镜**） |

**问题**：模板把 `target_duration`（默认 60–90 秒）收下了，也写进了 task，但 **output 结构里没有任何时长字段**——既无每场配额，也无总时长确认。

### R-06 场次数量规则的时间区间边界重叠，且用例评测引用了错误档位

| 项 | 内容 |
| --- | --- |
| 位置 | 模板 L112；用例 L20、L81 |

**问题**：模板 L112 规定"**≤60 秒 3–5 场；60–180 秒 5–8 场；>180 秒 8–12 场**"——**60 秒整同时落在第一、二档**（`≤60` 与 `60–180` 在 60 处重叠），区间不互斥。

**证据**：用例 L20 `target_duration = 60-90秒`，按模板应属"60–180 秒 → **5–8 场**"；但用例 L81 判定写"`scenes_outline` 5 条在 **60–90 秒区间（3–5 场）**"——**引用了第一档的口径**。5 条恰是两档交集（3–5 ∩ 5–8 = {5}），因此本用例"看起来对"，**但判据是错的**。

**影响**：

1. 在 60 / 180 两个节点上，"几场"**无唯一解**，同一份输入可被判合格也可被判不合格；
2. 用例 §4 第 4 项是"评测口径的第一版定义"，**口径本身引错档位**，会把错误固化进后续评测；
3. 下游若据 `target_duration` 反推节奏，会拿到互相矛盾的场数预期（同一句输入，两档给出不同场数区间）。

**建议方向**：把区间改为**无重叠的半开区间**（如 `≤60` / `60<t≤180` / `>180`），并写明边界闭合方向；同步修正用例 L81 的判定表述。

### R-13 `guards` 中直接插值客户输入，使唯一的约束段语义随输入漂移

| --- | --- |
| 位置 | 模板 L135；依据 `SCHEMA.md` L31 |

## 5 承继四问的逐条回应（请求书 §2 指定，四问全覆盖）

### ① 可承继性（← 可投喂性）

**问**：下游为了做出剧本→分镜→镜头提示词**必须**知道的信息里，有多少是它给的？未给的部分，下游要额外做多少翻译工作，由谁承担、在哪个模板完成？

**答**：

| 类别 | 内容 |
| --- | --- |
| **已给** | 故事骨架（`logline` / `conflict` / `ending`）、场次与节拍（`scenes_outline`）、题材与气质（`genre` / `world.tone`）、要点覆盖（`covered_points`）、**叙事层**缺口清单（`unspecified`） |
| **未给** | ① 三类一致性锚（角色标识与外观、场景物理锚、风格串）；② 时长预算；③ 在场角色；④ 客户禁止项的传递（`must_avoid`） |

其中 **①** 属于最危险的一类——**"没给、且责任不明"**。② ③ ④ 是"没给但下游可自行决定"，代价是各段自由发挥；而 ① 是"没人负责给"：模板无字段、SW-005 的验收标准不含外观（需求 L51）、SW-006 只做镜头参数（L52），**责任在链路上是悬空的**。

**必须在链路设计层面拍板**：外观与风格串的**首次定义**放在哪一段（建议不晚于剧本层），并在本模板为其**预留占位字段**，使下沉承接有源。

### ② 可锚定性（← 可控性）

**答**：三类锚**全部缺失稳定标识**。

| 锚 | 本模板现状 | 下游要求 | 后果 |
| --- | --- | --- | --- |
| **角色锚** | 只有 `name`（L79–84 / L95–97），用例中为「未指定」（L35 / L51）；无 ID、无外观 | v1.1 §3.4 L361 `character_id` + L363 `appearance_lock_zh`；镜头用 `character_refs` 引用 | **无可引用之物**；v1.1 L368"外观只定义一次"**无源可定义** |
| **场景锚** | `scenes_outline.no` 存在但无地点/时相（L98–100）；未约定下游沿用 | v1.1 L388 / L419 以场号索引 | 场号可对上，**物理锚对不上**（R-03） |
| **风格锚** | `genre` + `world.tone`（用例仅 4 字，L42） | v1.1 §3.3 L331：3–5 条风格锚 + L329 30–80 字风格串 | **无中间承载**；L344"锚点封闭"无法执行（R-01） |

**缺锚的传导路径**：v1.1 §3.1 L269 已明确——"跨镜头角色/风格漂移"是 AI 视频最常见的失败，故把一致性锚提升为顶层独立结构。**上游无锚 → 第 4 段无源可定义 → SW-002 的"零漂移"（需求 L43）失去比对基准 → 最终交付物的一致性只能靠人工目检**（v1.1 §8.3 第 18 项规定人工核对角色一致性，L1407）。

### ③ 可拍摄性（← 可拍摄性）

**答**：`scenes_outline` 提供的是**叙事事件**（发生了什么），不是**可拍场景**——四项可拍要素（在哪 / 什么时相 / 谁在场 / 有哪些可见动作）中**只有第一项被承载**，且以 ≤40 字的短语形式。

**对下游的代价**：SW-005 需将每条 beat 膨胀为可拍场景，每场的地点名 / 时相 / 在场角色**均需自造**，且**不回写梗概**——梗概与最终镜头之间因此没有可校验的对应链。此外缺时间维度预算（R-04），使"节拍数"与"可拍秒数"在本层无法对齐。

### ④ 缺口可追溯性（本模板特有，请求书称"最要紧的一问"）

**答**：**叙事层做到了，视觉层没有。**

- 叙事层：字段内"未指定"（L47）+ 顶层 `unspecified`（L108）+ guards 强制不得静默丢弃（L135），三层齐备，且用例已验证有效（L68 列出 4 项）——**这部分设计是对的，应予保留**；
- 视觉层：**没有字段** → 写不了"未指定"（无容器）→ 进不了 `unspecified`（未被识别为关键信息）→ 下游机器读不到（自由文本、无字段路径 / 责任阶段 / 降级值）。

**结论**（直接回答请求书 §2 的设问）：这份梗概**不是**"下游拿到后必须自己编造才能用"的产物，**也不是**"下游明确知道缺什么"的产物——它是**"下游必须自己补一层视觉描述、且无人告知哪些是补的、哪些是原生的"**产物。**这不是模型能力问题，是字段设计问题**（R-01、R-02）。
