## 1 P0 阻断级（4 条）逐条复查

### PR-01 承继守恒出现「第 5 类差异」：`prop_refs` 整字段丢失 —— **部分采纳（事实成立，归因更正）**

**评审主张**：本层 `system` 硬性约束 1 与 `guards` 均把 `prop_refs` 列入承继清单，但交付包 14 镜**都没有这个键** → 「整字段丢失」「道具锚在最后一公里断链」，且「上游有、本层无」属承继守恒的**第 5 类差异**。

**我方独立复核（可复现）**：

| 复核项 | 结果 |
| --- | --- |
| 交付包 `shots[]` 是否含 `prop_refs` | **不含**（键集合差：上游有、本层无） |
| 上游 `CASE-003_storyboard-case01.md` 是否含该字段 | **含**（14 镜逐镜有值，`["PRP-01"]` 或 `[]`） |
| **交付规范 v1.3 全文是否有 `prop_refs`** | **没有**——且**全文无「道具」二字**（已逐字 grep 核对） |
| 规范 §3.6 镜头字段集是否含该字段 | **不含**（§3.6 的「必须/应当/可」字段表共 24 项，无 `prop_refs`） |
| 交付 schema `shot.properties` | **无该键**，且 `additionalProperties: false` |

**结论：评审的「事实」成立（交付包确无该键），但「归因」不成立。** 这不是「本层漏承继」，而是——

> **`prop_refs` 是上游 `storyboard_v1` v2.0.0 随 `script_v1` v2.0.0 机械承接而新增的字段，它从未进入交付规范 §3.6 的字段集。** 本层若「忠实承继」，产出会被 schema 的 `additionalProperties:false` **判为多余属性并阻断交付**。

**落点（本层处置）**：

1. **承继清单更正**（模板 `system` 硬性约束 1 / `variables` 描述 / 版本说明 / `output` 口径 / `guards` diff 清单——**五处统一**，把评审指出的「三处清单不一致」一并消除）；
2. **交付包侧明确「本层不输出该结构键」**，并写明原因（规范 §3.6 与 schema 均无此字段）；
3. **新增判据 R35 `NO_PROP_REFS`**——把「上游有、本层不该有」从「写在说明里」升级为**机器可见**；
4. **登记规范层缺口 `ISSUE-011`**：「规范 §3.6 字段集缺道具维度 → 道具锚的结构化落地在交付包层无容器」，**提请契约责任方定案**（本轮**不改契约**，因为改规范 §3.6 + schema 会连带影响 `SW-014` / `SW-025` / `SW-026` 与规范 V1.3 的刚定案状态）；
5. **道具的可见信息由正文承载**（已在模板写明：只写瞬时状态与动作关系，**不得重述外观**）。

**为何不判「已采纳」**：评审建议「本层补回该字段」**在本层不可执行**（补了就不合法）；其建议的第二半（「请契约责任方在 schema 补该键」）**我方同意并已登记**，但落点在别人手里。

### PR-02 「投影规则③产出的空串在交付契约下不合法」——**已采纳（本层内解）**

**评审主张**：投影规则③把 `medium`／`normal` 规范化为**空串**，但交付 schema 的枚举**不含空串** → 同一份产物不可能同时过两个校验器。

**我方独立复核（可复现，且比评审描述更严重）**：

- 把用例包投喂带 schema 校验的门禁脚本 → **24 条 BLOCK**（评审只说「1 处」，实测是**系统性**的）；
- 分类：`transition_out=""` **9** 条、`camera.amplitude=""` **5** 条、`camera.optics=""` **5** 条、`camera.speed=""` **2** 条、`characters[].ref_image=null` **2** 条、`prompt_en` 超长 **1** 条（后者属 PR-07）。

**落点**：**留空一律改为「省略该键」**——JSON Schema 里「键缺失」与「值为空」是两件事，而**可选字段的键缺失天然合法**。本次用例 **41 处留空改省略键**（`ref_image` 16 / `transition_out` 9 / `amplitude` 5 / `optics` 5 / `dialogue` 3 / `speed` 2 + `characters` 2）；模板投影规则③**改写为「省略键」口径**，并**扩至所有可选字段**；新增判据 **R33 `NO_EMPTY_STRING`**（与门禁**严格对齐**——`shots[].ref_image=null` 在 schema 合法，故**刻意不报**，并登记为已知盲区）。

**结果**：门禁 BLOCK **24 → 1**（余 1 条属 PR-07 的契约级缺陷）。

## 6 本次处置中的四处自查发现（**均非评审提出**）

### 6.1 门禁脚本⑯ 的「风格漂移」子串误报（**本次新发现**）

**现象**：带 schema 跑门禁时，**9 镜**被报「出现锚点清单之外的风格词 `['赛璐璐上色']`」——而正文**逐字复述的正是锚点**（`柔和赛璐璐上色`）。

**根因**：判据用 `w in v`（**子串包含**）比对；词表 `style_tags` 含「赛璐璐上色」、本片锚点是「**柔和**赛璐璐上色」→ 正文写锚点反被判违规。**与本层 R28 的中英尺度错配同源：字符串粒度 ≠ 语义粒度。**

**修复**：① 清单词若被任一锚点**包含**则不视为「清单外」；② 比对前先把正文里的**锚点原文剔除**再找剩余文本。修正后误报**归零**。

### 6.2 R26 的「上游侧 / 交付包侧」口径分叉（**本次新发现**）

`R26` 原口径是「`amplitude` ∈ {空串, small, large}」——**允许空串**。这在**上游侧**成立，在**交付包侧**与 schema 冲突。故本次**不是改 R26**，而是**新增 R33 专管交付包侧**，并在 `CFG-007_SCHEMA.md` 写明「两条合读」。**这是「同一语义在不同层有不同合法表达」的一次显式建模**。

### 6.3 `CFG-008_manifest.yaml` 的「可直接过 `validate_pack.py` 门禁」失实表述（**本次发现并修正**）

`CFG-008_manifest.yaml` 的 `shot_prompt_v1.notes` 原文写「**可直接过 `validate_pack.py` 门禁**」——而实测该包**从来不能**（24 条 BLOCK）。**该类表述正是 PR-02 的技术根源：把「应该能过」写成了「能过」。** 已改为如实表述（产物侧全通过、交付门禁尚余 1 条契约级 BLOCK）。**同类修正也做了 4 处**：模板门外说明、用例 §3／§6、`DEV-20261013-022`。

### 6.4 判据只查「必备」不查「多余」→ 清单外字段无人管（**本次新发现，直接承接 PR-14**）

**触发**：为落实 `PR-14`「两处清单不一致会留下『**清单外字段无人管**』的漏洞」，回头**逐处核对模板自身的承继清单**，发现**第 6 处**不一致——模板头部注释的承继清单（`# 承继不改：…／music／forbidden_items。`）列 `forbidden_items` 而**漏 `notes`**，与 `system` 硬性约束 1 及 `guards` 的 diff 清单（两处均以 `notes` 收尾）**不符**。三处清单的**其余 17 项逐字相同**，差异**只在末项**。

**顺着再查判据侧**，发现**更结构性的缺口**：`R27 PACK_REQUIRED` 只校「**必备字段是否齐备**」（顶层六段 + 逐镜 13 字段），**完全不校「是否多出契约外的字段」**。后果是——任何上游带来的、规范里没有的字段都能**悄悄进入交付包**，一路走到门禁才被 `additionalProperties:false` 拦下：**拦得太晚，而且只看得到一条汇总报错**（本次 24 条 BLOCK 里，23 条是空串族，`prop_refs` 若真被承继进去，只会表现成又多一类「多余属性」）。

**连带查出一个真实的契约缺口 —— `ISSUE-012`**：上游 `script_v1` 与 `storyboard_v1` **都有顶层 `forbidden_items`**，但交付包**没有它的容器**——

| 可能容器 | 能否承载「内容层禁忌」（如「禁止出现真实人名」） |
| --- | --- |
| 规范 §3.1 顶层六段 | **无此段**（`meta`／`style_bible`／`characters`／`units`／`shots`／`aigc_meta`） |
| §3.3 `negative_global` 四类组织 | **不能**——四类是**通用图像项／视频时域项／形变延续项／场景专属项**，覆盖的是**画质与伪影** |
| `meta.compliance` | **不能**——只含 `safety_check`／`copyright_check`／`marking_check`／`statement_id` |
| `characters[].forbidden` | **不同语义**——那是**角色**不变要素（规范 §3.4），非全片内容禁忌 |

而 `CFG-008_manifest.yaml` 却写着「**禁止项承接：剧本 forbidden_items 须原样承继**」——**与模板正文、投影映射表均不符**（模板正文从未说明搬运到哪，映射表根本没有该行）。**这是本次发现的第 2 处失实表述**（第 1 处见 §6.3）。

**处置（两侧都补）**：

1. **模板侧**：三处承继清单**逐项对齐**（末项统一为 `notes`），并在头部显式写明「**上游「顶层」字段不在本承继清单内**，按 `context` 的投影映射表逐项处理」；
2. **投影映射表补全**：新增三行——「上游顶层 `title`／`genre`／`style_ref`／`aspect_ratio_default`／`total_duration_ms`／`quality_gate`」（不搬入，作用已由 `meta` 对应字段承担）／「上游顶层 `forbidden_items`」（**无容器**，登记 `ISSUE-012`）／「上游顶层 `unspecified`」（**无此段**，缺口可见性改由 `meta.notes` 登记），并加一句总则：「凡上游出现而本表无对应投影行的字段，均属**契约缺口**，须登记规范层 `ISSUE`，**不得默认照抄**」；
3. **`CFG-008_manifest.yaml` 更正**：该行改为「剧本层与分镜层的顶层 `forbidden_items` **均不在交付包内** → 本层不搬运 + 登记 `ISSUE-012`；⚠️ 与 `characters[].forbidden` 区分（后者是交付包**内建**字段，照常产出）」；
4. **新增判据 `R36 NO_EXTRA_KEY`**——检查**七处**（顶层／`shots[]`／`units[]`／`characters[]`／`meta`／`style_bible`／`aigc_meta`）是否出现契约外键。⚠️ **字段集直接读交付 schema**（`delivery/schemas/CFG-006_shot_prompt_pack.v1.schema.json` 的 `properties` 与 `$defs`），**刻意不另写一份会陈旧的清单**——因为 PR-14 的病根正是「**再写一份清单就又多一个会不一致的地方**」；schema 不可读时**跳过（不伪判）**，与 R33 的取舍一致；
5. **负向样本 +3**（顶层 `forbidden_items` / `shots[].continuity_note` / `meta.director_intent`），越界样本 28 → **31**；
6. **登记 `ISSUE-012`**（见 §7 第 1-b 项）。

> **教训**：判据只管「**该有的在不在**」、不管「**不该有的在不在**」，漏洞就一定从后门进来。这与 PR-02 的留空口径是**同一枚硬币的两面**——PR-02 是「**显式的空**不合法」，本条是「**多余的键**不合法」；前者靠枚举比对发现，后者靠**字段集封闭**发现。**而字段集的唯一真值来源只能是交付 schema 本身。**
