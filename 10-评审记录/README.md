> **本目录存放各专项文档的「评审意见 / 修改意见」——即评审方对某份交付物正面提出的问题清单与处置建议，不是被评审文档本身，也不是修改后的新版本。**
>
> 工程根目录中编号为 **`10-评审记录`**（**收**：他人 → 我方）；与其配对的是 `11-过程文档`（**发**：我方 → 他人）。
>
> **文件名编号**：`REV-<对象标号>-<两位序号>`（`-01` 请求书 / `-02…` 意见 / 末位 复查记录）。
> 编号规则、全工程取号明细与「做到哪一步」专表见 **`13-项目配置管理/CM-002_文件取号表.md`**；

## 一、目录用途（为什么单独建这个目录）

本工程此前把「文档」与「对文档的意见」混在一处，导致两个问题：

| 问题 | 后果 |
| --- | --- |
| 意见散落在对话、临时文件、或文档内部的批注里 | 备案或交接时**拿不出"评审过程"的留痕** |
| 意见与被评审文档同目录 | 容易误把意见当正文，或修订后**丢失原始意见** |

**因此约定**：

1. **被评审文档**留在原归属目录（如 `01-架构设计/`），**不移动**；
2. **评审意见**一律进本目录，**一评一份独立文件**；
3. 文件名格式：**`<编号>_<被评审文档名>-<评审视角>-评审意见.md`**——**编号 = `REV-<对象标号>-<两位序号>`**（`-01` 请求书 / `-02…` 意见 / 末位 复查记录），对象标号取该对象所承载的**需求编号**（`synopsis_v1` → `SW-004`）或**交付物编号**（规范 → `D-017`、硬件文档 → `D-014`）；**编号规则与全工程取号明细见 `13-项目配置管理/CM-002_文件取号表.md`**；
4. 意见**永久保留，不随被评审文档的修订而删除或覆盖**——它是修订的依据，也是过程证据。

## 二、归档要求

| 项 | 要求 |
| --- | --- |
| 评审视角 | 必须写明（如「导演视角」「安全视角」「工程视角」）；同一文档可有多份不同视角的意见 |
| 事实依据 | 必须列出——引用的原文位置、实测数据、规则来源。**不得凭印象出意见** |
| 问题分级 | 必须分级（P0 阻断 / P1 妨碍可用 / P2 质量提升），便于排期 |
| 处置建议 | 必须给优先级建议，并注明「建议保留 / 通过」的部分 |
| 立场声明 | 必须写明「只出意见、不改正文」——**修订责任归被评审文档的责任方** |
| 复查对应 | 修订后应在本目录留一份**复查记录**，逐条标注「已采纳 / 未采纳 / 部分采纳 + 理由」 |

### 2.1 两类意见的区分与命名（2026-10-13 定案）

同一对象可能有**两类**评审意见，**分列、互不覆盖**：

| 类别 | 生成方式 | 命名（**2026-10-13 起加 `REV-` 编号前缀**） | 举证效力 | 用途 |
| --- | --- | --- | --- | --- |
| **预评审** | 本会话内加载同一份专家定义另起实例（**路径 A**） | `REV-<对象>-<序号>_<对象文档名>-<评审视角>评审意见.md` | 低 | 设计期快查，不进入举证链 |
| **独立评审** | **真实独立会话**（**路径 B**，经评审请求书委托） | `REV-<对象>-<序号>_<对象文档名>-<评审视角>评审意见-独立会话.md` | **高** | 备案举证「多视角评审」的凭据 |
| 对照复核（可选） | 由独立会话比照两份意见 | `REV-<对象>-<序号>_…-独立会话-对照复核.md` | 中 | 互校，暴露两份都漏的问题 |
| 复查记录（我方） | 修订后逐条闭环 | `REV-<对象>-<序号>_…-独立会话-复查记录.md` | — | 证明「意见已处置」 |

> **文件名编号（`REV-<对象>-<序号>`，全工程配置项标识）与本节的「问题编号前缀」是两件不同的事**：
> 前者标识**文件**（用于目录导航与跨文件引用），后者标识**文件内的条目**（`R-01` / `SR-01` / `BR-01` / `PR-01`…，用于逐条复查）。

**编号前缀分配（防撞号，2026-10-13 二次细化）**：`D-` = 路径 A 预评审 · 导演视角；`RV-P0/P1/P2-` = 硬件系统设计视角。**导演视角内部再按「视角 × 对象」细分**——因同一视角将评多个对象，共用前缀会使跨文件引用无法分辨对象：

| 前缀 | 对象 | 状态 |
| --- | --- | --- |
| `R-` | `synopsis_v1`（SW-004） | **已封存**，不再分配 |
| `SR-` | `script_v1`（SW-005） | 归档 7 已用 |
| `BR-` | `storyboard_v1`（SW-006） | **归档 9 已用**（`BR-01`…`BR-13`） |
| `PR-` | `shot_prompt_v1`（SW-007） | **归档 11 已用**（意见，`PR-01`…`PR-15`）＋ **归档 12**（复查记录）——⚠️ **该意见独立性未满足，须连同降级结论一并引用** |

> **两条硬规则**：① 编号在**各文件内独立从 `01` 起**，引用时**必带对象语境**；② **后续新视角 / 新对象须用新前缀，不得复用**。

> **2026-10-13 起：对外评审一律走路径 B**。完整规程见 `11-过程文档/PRO-001_评审接力协作规程.md`（`PROC-RELAY-001`）。
>
> ⚠️ **原名政策已废止（2026-10-13）**：本目录曾约定「**既有文件不改名**（改名会破坏既有引用）」，现已**由项目方指令推翻**——为消除「不知道评审做到哪一步」的问题，全工程文件统一按 `13-项目配置管理/CM-002_文件取号表.md` **取号并改名**（本目录 **12 份**评审文件改为 `REV-<对象>-<序号>_…`），**全工程引用已同步**（142 文件 / 1996 处）。
>
