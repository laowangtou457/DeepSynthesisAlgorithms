## 1 定位与边界

本表回答三个问题：

1. **今天实际做成了什么** —— 只列**有证据**的产出（提交哈希 / 留痕编号 / 命令输出）；
2. **明天做什么** —— **只引用 `T-` 编号**，不在此处重新定义任务；
3. **还没了的 ISSUE 卡在谁那里** —— 按**处置路径**归类，标明「等决策 / 可即办 / 需外部动作」。

**三条边界**（避免与既有文档重复）：

| 不做什么 | 因为 |
| --- | --- |
| 不定义任务内容 | 任务定义唯一在 `PM-001_任务清单.md` §1~§7 |
| 不重新登记 ISSUE | ISSUE 台账唯一在 `PM-001_任务清单.md` §8；本表 §3 是**聚焦视图**，每条注明编号与**当前卡点**，并给出处置建议 |
| 不重述留痕事实 | 逐动作留痕在 `11-过程文档/开发历史/`；本表只做**当日汇总与引用** |

> 一句话：**`PM-001` 是账本，`PM-002` 是排期图，本表是「当日对账 + 明日安排 + 悬账催办」。**

## 5 维护规则

1. **每个工作日收尾时新增一节**（倒序，最新在上），结构固定为「当日进展（含统计与回归基线）+ 次日计划（四组：主线 / 清账 / 待决策输入 / 项目方动作）」。
2. **§3 ISSUE 遗留总览为滚动视图**，每日随日报更新状态；**新增/闭环 ISSUE 一律先改 `PM-001` §8，再回填本表**——⚠️ **顺序不可颠倒**（本表不是事实来源）。
3. **无证据不写**：进展项必须附提交哈希 / 留痕编号 / 命令输出摘要；未验证的产出标「**未验证**」。
4. **不预测未拍板的事**：需人工输入才能确定的事项只列在「待决策输入」组，**不计入可执行任务**。
5. **脱敏纪律同 `PM-001`**：不出现真实企业名与人名，人员一律写角色；受控类只记计数变化、不落明文。
