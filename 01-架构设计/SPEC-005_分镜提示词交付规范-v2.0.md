## 0 文档说明

### 0.1 目的

本系统只生成**文本**（分镜提示词集），最终对外传播的却是**视频**，标识义务因此跨主体。本规范解决四个问题：

| 问题 | 本规范的解法 |
| --- | --- |
| **提示词本身写得好不好，没人量** | 定义**八维镜头语言 + 11 项质量门**，可工具化复现（**第 4 章**，V1.1 新增） |
| 客户拿到提示词后不知道怎么用、格式对不上 | 定义**通用规范 + 多模型适配**的提示词包结构（第 3、6 章） |
| 视频侧标识义务落在下游工具，本系统如何尽责 | 交付**标识素材包 + AIGC 元数据块 + 合规声明**（第 5、7、8 章） |
| 备案需要「安全能力与安全机制的实物证据」 | 交付前**自检 + 留档 + 声明**（第 8 章），并可用第 11 章验收标准逐条举证 |

### 0.2 适用范围

| 范围 | 说明 |
| --- | --- |
| **适用** | 本系统向客户交付的所有产物：梗概、剧本、分镜脚本、**分镜提示词集**及其导出文件 |
| **不适用** | 文生视频生成本身（本系统不做）；客户使用下游工具后的成片（本系统不接触、不核验） |
| **约束对象** | 工程实现（SW-007/014/022/025/026/SW-I04）、交付物本身、交付流程 |

### 0.3 规范用语（强制等级）

| 用语 | 含义 | 违反后果 |
| --- | --- | --- |
| **必须（MUST）** | 法规强制项或合规红线，不可协商 | **阻断交付**，记录并告警 |
| **应当（SHOULD）** | 强推荐，偏离须在交付记录中写明理由 | 记录偏离说明 |
| **宜（MAY）** | 建议做法，可按场景取舍 | 无 |
| **可（CAN）** | 可选增强能力 | 无 |

> **重要区分**：法规原文中的「应当/应」是**法定义务**（如《标识办法》§8 要求协议写明标识规范）；本规范中的「必须」用于标注**实现层面的强制校验点**（如导出文件缺显式标识则阻断导出）。两者不可混用，写备案材料时须分开表述。

### 0.4 三层结构与本规范的编写纪律（V1.1 新增）

V1.1 按**三层结构**组织。三层职责不得混写，**第 3 层不得出现模型参数数值**（须由第 2 层定义、第 3 层只做引用）。

```
┌──────────────────────────────────────────────────────────────────────┐
│ 第 1 层 · 内容质量层      提示词本身写得好不好                        │
│   与模型无关，可跨模型复用                                            │
│   → 本规范 第 3 章（字段承载）+ 第 4 章（八维 · 质量门 · 单元 · 语速） │
│   → V1.0 完全空白；V1.1 新增                                          │
├──────────────────────────────────────────────────────────────────────┤
│ 第 2 层 · 模型适配层      同一内容投影到具体模型                       │
│   与模型强相关，换模型须重建                                          │
│   → 本规范 第 6 章（骨架 · 引用语法 · 运镜句法 · 负向归位 · 边界数值） │
│   → V1.0 为占位内容；V1.1 按实测规则重写                              │
├──────────────────────────────────────────────────────────────────────┤
│ 第 3 层 · 交付形态层      打包 · 标识 · 声明 · 导出                   │
│   与模型无关                                                          │
│   → 本规范 第 1、5、7、8、9、10、11 章                                │
│   → V1.0 已完备；V1.1 保留并补 4 项增强（见 §0.6）                    │
└──────────────────────────────────────────────────────────────────────┘
```

**编写纪律**（对实现与后续修订同等约束）：

| # | 纪律 | 说明 |
| --- | --- | --- |
| 1 | **参数不得凭记忆** | 每个数字必须带来源（官方文档链接/版本号，或本项目实测文件路径） |
| 2 | **不得自造枚举** | 枚举一律以官方能力清单为准；内部语义标签须与官方类型分离标注（见 §3.7.2） |
| 3 | **冲突时以实测为准，但并列出差异** | 官方文档与本项目实测冲突时，两者并列写出，不得静默取舍 |
| 4 | **三层不交叉引用数值** | 第 3 层不得出现「H3 单块 7,000 字符」这类模型参数 |
| 5 | **规范是移动靶** | 适配参数须附「版本快照 + 复核清单 + 复核周期」，标注为快照而非恒定 |

## 1 交付形态总览

### 1.1 交付四件套

每次交付**必须**同时包含以下四项，缺一不可（SW-014）：

```
交付四件套
├── ① 分镜提示词集（shot prompt pack）
│      通用规范 JSON（基准） + 目标模型适配格式（按需）
├── ② AIGC 元数据块（aigc_meta）
│      GB 45438—2025 附录 E 规范格式，随包一份
├── ③ 标识素材包（overlay assets）
│      片头卡 / 角标素材（横版 + 竖版），满足 GB 45438 §5.4 硬指标
└── ④ 交付合规声明（compliance statement）
       标识方法说明 + 客户标识义务提示 + 禁止删改告知 + 自检结论
```

> **为什么是「四件套」而不是「提示词 + 说明」**：因为本系统与下游脱钩（不 API 直连、不回传成片），**「客户照做即合规」**是唯一可控的合规路径。要素齐全才能让客户不需要理解法规也能正确落地。

> **V1.1 附注**：交付包内**另附** `qa/audit_report.txt`（镜头语言质量门报告，见 §4.8）。它是随包留档的**过程证据**，不计入四件套定义，但**缺失即阻断交付**（§8.3 第 13 项）。

### 1.2 三条不可变原则

| 原则 | 内容 | 法规/需求依据 |
| --- | --- | --- |
| **① 脱钩** | 本系统**不**对接任何下游平台 API、**不**代客户调用生成、**不**托管下游密钥、**不**接触成片；交付物为**产物 + 说明**，不做系统集成 | SYS-018 |
| **② 无去标识** | 系统内**不得存在**任何「去除 / 关闭 / 隐藏 AI 标识」的功能、开关或接口——包括管理控制台不得提供一键剥离标识 | 《标识办法》§10 |
| **③ 文本侧标识自控** | 本系统对**自己生成的文本**负有标识义务，必须全量落地（显式 + 隐式 + 界面提示），不得以「反正下游会标」为由省略 | 《标识办法》§4·§5；《深度合成规定》§16~§18 |

### 1.3 责任边界（谁对视频标识负责）

```
① 本系统（生成合成服务提供者 · 文本侧）
   │  义务：文本显式标识 + 隐式元数据 + 界面显著提示 + 协议告知 + 素材与声明传递
   │  交付：四件套
   ↓
② 客户（内容使用者 / 制作方）
   │  义务：按声明与协议落地标识（服务协议已明确其标识义务与使用责任 —— §8、§9）
   ↓
③ 下游 AI 视频工具（生成合成服务提供者 · 视频侧）
   │  义务：对视频本身的标识义务由其自身合规义务承担（本系统不代其履职）
   ↓
④ 内容传播平台（内容传播服务提供者）
   └  义务：核验元数据 → 在内容周边添加显著提示标识（§7，最后一环兜底）
```

**写进备案材料的定位口径**：本系统**不是**视频的生成合成服务提供者；视频侧标识第一责任主体为下游 AI 视频工具。本系统义务收敛为**文本侧标识 + 协议告知 + 提示与素材传递**。此口径可避免自我加码，也经得起审查询问。

> **风险知情**：选择脱钩即意味着本系统**无法验证**客户最终是否落地标识。缓释机制见 §8.3（自检）+ §7.6（照做即合规）+ §1.3 ④（平台兜底）。该风险已在 SYS-Q4 决策文档中留痕。

## 2 术语与缩写

| 术语 | 说明 |
| --- | --- |
| 提示词包 / pack | 一次交付的分镜提示词集，含全局锚点、生成单元与镜头列表，对应一个 `pack_id` |
| **生成单元 / unit** | **一次生成调用所提交的完整分镜块**，含 2–3 个镜头；是「运镜丰富度」的责任单位（V1.1 新增，见 §3.5、§4.3） |
| 镜头 / shot | 视频的**画面最小单位**，包含画面提示词与镜头语言参数 |
| **八维镜头语言** | 景别 / 运镜 / 角度 / 光学 / 构图 / 轴线 / 光线 / 画面结果；与模型无关，可跨模型复用（第 4 章） |
| **质量门** | 11 项量化阈值（覆盖率 + 占比 + 类型数），交付前**必须全通过**（§4.2） |
| **三把尺子** | ① 规范合规（按模型重建）② 镜头语言八维（跨模型复用）③ 语义合规（须人工）；三者互不替代（§4.7） |
| 全局锚点 | 跨镜头复用的风格串（`style_bible`）与角色串（`characters`），用于解决 AI 视频的**一致性**问题 |
| **风格锚点** | `style_bible.style_anchors[]`，3–5 条固定词条；`prompt_*` 中不得出现锚点清单之外的风格词（§3.3） |
| **单人替身法则** | 单角色镜头**必须**用具名锚点指向，不得用「他/她」隐含指代（§4.4） |
| 正/负向提示词 | positive（要什么）/ negative（避免什么）；**负向词是否可独立成字段，由目标模型决定**（§6.4） |
| AIGC 元数据块 | 写入文件元数据的隐式标识，字段名含 `AIGC`，值 JSON 字符串（GB 45438 附录 E） |
| 显式标识 | 用户可感知的标识（画面上的文字、文件首尾标注）（《标识办法》§4） |
| 隐式标识 | 用户不易感知的技术标识（元数据）（《标识办法》§5） |
| **任务类型 / task_type** | 文生 / 首帧 / 首尾帧 / 尾帧 / 参考生成 / 续写 / 编辑 / 音频复用等生成形态（§3.2、§6.4） |
| 适配投影 | 把通用规范提示词集「投影」到某个下游模型的写法与导入格式（SW-025） |
| **内部语义标签** | 本规范 `camera.move` 等枚举值——**不是任何模型的语法**，仅供映射；交付文本中**不得直接出现**（§3.7.2） |
| 交付合规声明 | 随交付物出具的合规说明文件（SW-026、SYS-019） |
| 提供者编码 | 服务提供者在标识体系中的唯一编码，写入 `ContentProducer`（**待分配**，见 §13） |

## 3 提示词包结构与字段规范（第 1 层 · 字段承载）

> 配套工程文件：[`03-工程代码/delivery/schemas/CFG-006_shot_prompt_pack.v1.schema.json`](../../03-工程代码/delivery/schemas/CFG-006_shot_prompt_pack.v1.schema.json)
> **本章只负责「字段怎么放」；「内容写得好不好」由第 4 章负责。**

### 3.1 整体结构

提示词包为**单个 JSON 对象**，顶层**八段**（含 `schema_version` 共 **9 个顶层键**；「段」只数业务段、不数 `schema_version`——此为 V1.0 起的既有口径）：

```
{
  "schema_version": "2.0.0",    // 必须：结构版本，与 Schema 对应（V2.0 起为 2.0.0）
  "meta":           { ... },     // 必须：包元信息、生成溯源、合规状态、任务类型
  "style_bible":    { ... },     // 必须：全局风格锚点（仅一份）
  "characters":     [ ... ],     // 应当：角色锚点列表（无角色可空数组，见 §3.4）
  "props":          [ ... ],     // 应当：道具锚点列表（无道具可空数组，见 §3.4.1；V2.0 新增）
  "units":          [ ... ],     // 必须：生成单元列表（每个 2–3 镜，V1.1 新增）
  "shots":          [ ... ],     // 必须：镜头列表（≥2）
  "forbidden_items": [ ... ],    // 应当：客户侧「禁止出现的元素」原样承继（V2.0 新增）
  "aigc_meta":      { ... }      // 必须：AIGC 元数据块（仅一份，见第 5 章）
}
```

**为什么这样分层**：

| 层 | 解决的问题 |
| --- | --- |
| `style_bible` / `characters` | 把「不变的」与「变的」分开——AI 视频最常见的失败是**跨镜头角色/风格漂移**，因此把一致性锚点提升为顶层独立结构 |
| **`props[]`（V2.0 新增）** | **道具是第三类跨镜一致性来源**（与角色、风格并列）。上游 `storyboard_v1` 逐镜给 `prop_refs`，但交付包若**只有引用、没有定义**，道具外观就无处锁定、跨镜一致性也无从校验（§3.4.1） |
| **`units`（V1.1 新增）** | **每个生成单元至少 2 镜**。质量门的「运镜类型数」门槛分母是**镜数**（`min(5, max(2, ⌈镜数/4⌉))`），因此 **1 镜单元在数学上必然不达标**——这是结构性失败，不是建议（§4.3） |
| `shots` | 逐镜参数。**结构上平铺、由 `units[].shot_ids` 索引**，以保持全片镜序为唯一真值来源 |
| **`forbidden_items`（V2.0 新增）** | **客户侧「禁止出现的元素」的结构化容器**（上游输入变量名即 `must_avoid`，synopsis → script → storyboard **逐层原样透传**）。它必须是**顶层独立段**而非塞进别处：① §3.3 `negative_global` 是**质量层**（画质伪影）容器，② `meta.compliance` 只承载**检测结论**（`safety_check` 等），二者都不是**内容层禁忌**的容器（§3.1.1） |

> **镜数下限（必须）**：`shots` ≥ 2；每个 `units[].shot_ids` 的成员数 ∈ **[2, 3]**。

#### 3.1.1 三层「禁忌/负向」边界（V2.0 新增 · 必须分清，不得合并）

「禁止什么」在本规范里有**三个互不相通的层**，混用会造成**合规举证失据**或**新增泄漏面**：

| 层 | 载体 | 是什么 | 谁消费 | 是否进交付包 |
| --- | --- | --- | --- | --- |
| **客户业务层** | **顶层 `forbidden_items`**（V2.0 新增） | **客户合同的「禁止出现元素」**（如「血腥画面」「真实人名」），上游变量名 `must_avoid` | 客户 / 人工核对 | ✅ **进包、可举证** |
| **质量层** | §3.3 `style_bible.negative_global` / `shots[].negative_prompt` | **画质与伪影**（通用图像项 / 视频时域项 / 形变延续项） | 目标模型（按能力） | ✅ 进包（容器字段，不得进正文） |
| **法定合规层** | 受控词库**分类码**（`A1-01`~`A1-08`）与词条 | **一票否决类合规词**，由 **SW-009/010 双闸**（AC 自动机）承载 | 内容安全检测 | ❌ **绝不进包** |

> ⚠️ **写死一条边界**：`forbidden_items` **只承接客户侧的「禁止出现的元素」**，**不得**写入受控词库的任何分类码或词条——后者在工程内属「**严格受控、不明文留痕**」，明文入包即**新增泄漏面**。三层口径的澄清过程见 `PM-001` §8 的 `ISSUE-012` 行。
>
> ⚠️ **与 `characters[].forbidden` 的区别（不得合并）**：`characters[].forbidden` 是**交付包内建**字段（§3.4），语义是「**该角色禁止变化的要素**」（如「服装颜色」「发型」），生成后人工核对用；顶层 `forbidden_items` 是**承继**字段，语义是「**整片禁止出现的元素**」。两者**作用域不同**（角色级 vs 全片级）、**来源不同**（本层定义 vs 上游透传）。

### 3.3 全局风格锚点 `style_bible`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `style_id` | string | **必须** | 风格唯一标识，如 `STYLE-ANIME-CN-A`；各镜头 `style_ref` 引用此值 |
| `style_prompt_zh` | string | **必须** | 风格串（中文），描述画风/质感/时代/色调 |

| **`style_anchors`** | string[] | **必须** | **风格锚点清单（V1.1 新增）**，**固定 3–5 条**，全片唯一、不增不减 |
| `color_palette` | string[] | 可 | 主色板（HEX），用于后续滤镜/调色对齐 |
| `lighting_default` | string | 应当 | 默认光照，取值见词表 |
| `film_grain` | string | 可 | 颗粒感：`none` / `light` / `medium` / `heavy` |
| `negative_global` | string[] | **必须** | 全局负向词，**按三类组织**（见下） |

**填写规则（必须）**：

| 规则 | 说明 |
| --- | --- |
| 长度 | `style_prompt_zh` / `style_prompt_en` 控制在 **30–80 字**；过短无约束力，过长会被模型截断或稀释主体描述 |
| 全片唯一 | 风格串**全片唯一**，不得逐镜头改风格——需要风格差异时用 `lighting` 与 `camera.height` 表达 |
| **数量规则（V1.1 新增）** | `style_anchors` **固定 3–5 条**（例：`["日式动画电影质感","柔和赛璐璐上色","冷蓝色调","细腻雨丝质感"]`） |
| **锚点封闭（V1.1 新增）** | `prompt_zh` / `prompt_en` 中**不得出现锚点清单之外的风格词**——否则第 3 镜说「赛璐璐」、第 7 镜说「厚涂」，风格就散了 |

**`negative_global` 三类组织（V1.1 新增，对应评审 D-16）**：

| 类别 | 建议默认值 | 说明 |
| --- | --- | --- |
| **通用图像项** | `lowres` `blurry` `watermark` `text` `extra fingers` `deformed` `extra limbs` | 图像时代的伪影 |
| **视频时域项** | `flicker`（闪烁）`temporal jitter`（抖动）`frame inconsistency`（帧间不一致） | **视频专属**，V1.0 完全缺失 |
| **形变延续项** | `clipping`（穿模）`morphing`（物体形变/融化）`limb popping`（肢体跨帧跳变） | **视频专属**，V1.0 完全缺失 |
| 场景专属项 | 逐片填写（如「现代护栏与钢缆结构」「额外人物」） | 与具体场景绑定 |

> ⚠️ **`negative_global` 是「负向意图的容器」，不是「一定会被投喂的文本」**。目标模型不支持负向字段时（如 H3 基础模式），适配层**必须**把它转写为正向约束句，且**交付文本中不得残留任何形式的负向字段**（§6.4、§8.3 第 17 项）。

### 3.4 角色锚点 `characters[]`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `character_id` | string | **必须** | 角色标识，如 `CHR-01`；镜头用 `character_refs` 引用 |
| `name` | string | **必须** | 角色名 |
| `appearance_lock_zh` | string | **必须** | 外观锁定串（中文）：发型/发色/瞳色/服装/体态/年龄感 |
| `appearance_lock_en` | string | 应当 | 同上英文 |
| `ref_image` | string | 可 | 参考图相对路径（如 `refs/CHR-01.png`）——有参考图机制的下游模型优先使用 |
| `forbidden` | string[] | 应当 | 该角色**禁止变化**的要素（如「服装颜色」「发型」），生成后人工核对用 |

> **一致性关键（保留 V1.0 正确设计）**：角色外观**只在此处定义一次**，镜头内**不得**重复描述角色外观细节，只引用 `character_refs`。这是避免「同一角色在不同镜头长得不一样」的结构性手段。
>
> **V1.1 补充**：外观只定义一次**不等于镜头里不写主语**——单角色镜头**必须**用具名锚点指向（单人替身法则，§4.4）。

**主体唯一性与多主体区隔（V1.1 新增，对应评审 D-22）**：

| 规则 | 要求 |
| --- | --- |
| 单镜主体上限 | **`character_refs` 建议 ≤ 2**；确需 3 人以上应拆镜 |
| 多主体区隔 | 同框时**必须**写出画面区隔：前后景分离 / 左右分侧 / 一主一虚（焦点在谁身上） |
| 禁止 | 不得出现「多名角色同处一层景深且无位置分工」的写法——这会引发**身份互相污染**（两个角色的脸互相借特征），一旦出现整段报废 |
| 单人镜 | 单人镜**必须**遵守单人替身法则（§4.4） |

#### 3.4.1 道具锚点 `props[]`（V2.0 新增 · 与 `characters[]` 同构）

「道具／关键物件」是**与角色、风格并列的第三类跨镜一致性来源**——一把伞、一辆车的颜色与款式在不同镜头里必须一致，否则观众会读成「换了物件」。本段与 §3.4 `characters[]` **结构同构**，由上游 `script_v1` **首次定义**（首定义责任在剧本层，见 `CFG-007_SCHEMA.md` 的业务链路约定）、逐层**原样承继**至本层。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `prop_id` | string | **必须** | 道具标识，如 `PRP-01`；镜头用 `prop_refs` 引用 |
| `name` | string | **必须** | 道具名（如「折叠伞」） |
| `role` | string | 应当 | 叙事作用（如「男主标志物」／「关键信物」） |
| `appearance_lock_zh` | string | **必须** | 外观锁定串（中文）：颜色／材质／饰件／磨损／款式 |
| `appearance_lock_en` | string | 应当 | 同上英文 |

> **一致性关键（与 §3.4 同口径）**：道具外观**只在此处定义一次**，镜头内**不得**重复描述道具外观细节，只引用 `prop_refs`。
>
> **与「只写瞬时状态」的分工（必须）**：镜头的逐镜语义字段（`action.*`／`shot_language.*`／`camera.from|to`／`notes`）**允许**写道具的**瞬时状态与动作关系**（如「伞被风吹翻」），**不得**写外观**特征词**（颜色／材质／饰件／磨损／款式）。该判据已脚本化（`validate_output.py` **R23**，需 `--script` 提供上游）——**道具与角色适用同一把尺子**。
>
> **无道具时**：`props[]` 为空数组（`[]`），各镜 `prop_refs` 亦为空数组——**不得写成空串**（判据 R33）。

**`props[]` ↔ `shots[].prop_refs` 的守恒律（必须）**：

| 方向 | 要求 | 判据 |
| --- | --- | --- |
| 引用有效性 | 每镜 `prop_refs` 的每一项**必须**命中 `props[].prop_id` | 交付门禁 `validate_pack.py`「道具锚一致性」 |
| 入画可追溯 | 上游某一镜已标出道具入画 → 本层**必须**逐镜保留该引用 | 承继守恒（判据 R31） |
| 外观零重述 | 正文与逐镜语义字段**不得**复述 `props[].appearance_lock_*` 的特征词 | 判据 R23（3-gram 比对） |

> ⚠️ **为什么必须是「顶层定义 + 逐镜引用」两件套（不可只留其一）**：只有顶层 `props[]` 而无逐镜 `prop_refs`，**无法机器校验「哪一镜带哪个道具」**；只有逐镜引用而无顶层定义，则道具**外观无处锁定**、跨镜一致性无从比对。缺一即无法把上游的 `prop_refs` 承接下来——这正是 `ISSUE-011` 取处置 (a) 的核心理由（评估期曾倾向「不逐镜引用」，因其**无法机器校验**而弃）。

### 3.5 生成单元 `units[]`（V1.1 新增，对应评审 D-05）

「生成单元」= **一次生成调用所提交的完整分镜块**。它是「运镜丰富度」与「音轨组织」的责任单位，也是适配输出的分组单位。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `unit_id` | string | **必须** | 单元编号，建议 `U01`、`U02`…，一个包内唯一 |
| `scene_no` | integer | **必须** | 所属场景号（≥1） |
| `shot_ids` | string[] | **必须** | 成员镜头编号，**长度 ∈ [2, 3]**，顺序即镜序 |
| `soundscape` | string | **必须** | **本单元环境音**（H3 `overall_soundscape` 的投影源）；由成员镜 `sfx` 聚合并去重 |
| `music` | string | **必须** | **本单元画外配乐**（H3 `non_diegetic_music` 的投影源）；无则填 `N/A`，**不得写抽象情绪词** |
| `notes` | string | 可 | 单元备注（如「本单元为单人戏，按单人替身法则处理」） |

**三类约束（必须）**：

| # | 约束 | 数值 | 依据 |
| --- | --- | --- | --- |
| 1 | **每单元最少镜数** | **≥ 2 镜** | `min(5, max(2, ⌈镜数/4⌉))` 中分母是**镜数**；1 镜单元结构性不合格 |
| 2 | **每单元最多镜数** | **≤ 3 镜** | 八维全开比纯画面描述费字约 +47%（实测 4,724 → 6,933 字符 / 14 秒 4 镜）；**4 镜已到 7,000 字符极限** |
| 3 | **单元内运镜类型不得重复** | — | 由单元承担「运镜丰富度」责任；重复即浪费单元内唯一的多样性额度 |

**拆单元规则（必须）**：

| 规则 | 说明 |
| --- | --- |
| 超限处置 | **先拆单元，再上八维**——不得靠压缩描述省字数（会牺牲「画面结果」维度） |
| 保持锚点 | 拆单元时**必须**保持 `style_ref` 与 `character_refs` 不变——否则跨单元一致性断裂 |
| 禁止拆到 1 镜 | 4 镜拆成 2+2 可以；拆成 3+1 **不行** |
| 编号 | 拆出的单元按镜序重新编号（`U01`、`U02`…），不沿用旧号 |

**单元 ↔ 镜头关系（必须）**：每个镜头**必须**属于且仅属于一个单元（`shots[].unit_id` 指向 `units[].unit_id`）。

### 3.7 字段取值规则

#### 3.7.1 景别 `shot_size`

| 枚举值 | 中文 | 英文标准术语 | 画面范围 |
| --- | --- | --- | --- |
| `extreme_wide` | 大远景 | extreme long shot / establishing shot | 环境为主，人物极小 |
| `wide` | 远景 | long shot / wide shot | 人物全身 + 大量环境 |
| `full` | 全景 | full shot | 人物全身 |
| `medium` | 中景 | medium shot | 人物半身（腰以上） |
| `close_up` | 近景 / 特写 | close-up | 面部或关键物件 |
| `extreme_close_up` | 大特写 | extreme close-up | 局部细节（眼神、手部） |

> **必须**：`prompt_*` 中使用**标准术语**，不得自造词。**应当**：景别不得连续三镜同级（同级连切＝视觉停滞），推荐递进或跳级。

#### 3.7.2 运镜 `camera.move` —— 内部语义标签（V1.1 重写，对应评审 D-01/D-15）

> ⚠️ **本节是 V1.1 最重要的口径修正。**
>
> **`camera.move` 是「内部语义标签」，不是任何模型的语法。** 它的取值集合**对齐 MiniMax H3 官方 20 类运镜**（以其为规范集，因为它是四家中唯一可程序化校验、且本项目已实测核实的词表），但**交付文本中不得直接出现内部标签**——由第 2 层（第 6 章）投影为目标模型的写法。
>
> **V1.0 的错误做法（已废止）**：V1.0 §5.4 规定「支持显式镜头指令（**方括号形式**，如 `[Push in]`）」，并自造 17 个枚举。实测结论：**H3 不使用方括号指令**，其运镜是**英文自然语言末句**；客户照抄 `[Push in]` 会被模型当作画面正文处理——轻则忽略运镜，重则把方括号内容理解成「画面里要出现的文字」。

**规范集：20 类（与官方一一对应）**

| 类别 | 内部标签 | 中文用词 |
| --- | --- | --- |
| 固定 | `static` | 固定机位 |
| 推拉 | `push_in` / `pull_out` | 前推 / 后拉 |
| 变焦 | `zoom_in` / `zoom_out` | 变焦推近 / 变焦拉远 |
| 摇 | `pan_left` / `pan_right` / `tilt_up` / `tilt_down` | 左摇 / 右摇 / 上摇 / 下摇 |
| 移 | `truck_left` / `truck_right` | 左移 / 右移 |
| 升降 | `pedestal_up` / `pedestal_down` | 升 / 降 |
| 环绕 | `arc` | 弧形环绕 |
| 跟 | `tracking` | 跟拍 |
| 晃动 | `shake_slight` / `shake_strong` | 轻微晃动 / 剧烈晃动 |
| 主观 | `pov` | 主观视角 |
| 滚转 | `roll_cw` / `roll_ccw` | 顺时针滚转 / 逆时针滚转 |

**已弃用别名（必须迁移，不得继续使用）**：

| 弃用标签 | 迁移为 | 依据 |
| --- | --- | --- |
| `follow` | `tracking` | H3 官方为 `Tracking Shot` |
| `handheld` | `shake_slight`（纪实感）或 `shake_strong` | H3 用 `Shake Slightly` / `Shake Strongly`，**无 Handheld** |
| `crane_up` | `pedestal_up` | H3 用 `Pedestal Up` |
| `crane_down` | `pedestal_down` | H3 用 `Pedestal Down` |
| `orbit` | `arc` | H3 用 `Arc Shot` |

**运镜三要素（必须）**：**运镜 = 类型 + 幅度 + 速度**。

| 规则 | 说明 |
| --- | --- |
| 幅度 | `small` / `medium` / `large`；**`medium` 通常省略**（官方建议仅在需要强调时出现） |
| 速度 | `slow` / `normal` / `fast`；**`normal` 通常省略** |
| 例外 | `static` 与 `pov` **不得携带幅度与速度**（无此概念） |
| 起止 | **简单运镜至少给起点与终点（`camera.from` / `camera.to`）；复杂运镜给起点 → 中间 → 终点** |
| 独立成句 | 运镜**应当**独立成句，不藏在从句里、不在同句写两次运镜 |

> 「推 ≠ 猛推」——同一个 `push_in`，可以是从容缓推，也可以是骤然急推，画面情绪完全不同。这就是**幅度**必须与**类型**、**速度**并列的原因。

#### 3.7.3 角度 `camera.height` + `camera.roll`（V1.1 拆分，对应评审 D-18）

V1.0 的 `camera.angle` 把**机位高度角**与**摄影机轴向（roll）**混装在同一枚举里，导致**无法同时表达「低角度 + 荷兰角」**——而这恰是武侠与悬疑最常用的组合（仰拍 + 倾斜 = 压迫与失衡）。V1.1 拆为两个正交维度：

| 维度 | 取值 | 说明 |
| --- | --- | --- |
| **`camera.height`**（机位高度角） | `eye_level` 平视 / `low` 仰视 / `high` 俯视 / `overhead` 顶视 / `ground` 贴地 | 决定权力关系与情绪倾向 |
| **`camera.roll`**（摄影机滚转） | `level` 正常 / `dutch` 荷兰角（画面倾斜）/ `roll_cw` 顺时针 / `roll_ccw` 逆时针 | `dutch` 制造失衡与不安 |

**归并规则（必须）**：H3 侧 `Roll Clockwise` / `Roll Counterclockwise` 是**独立的运镜类型**，不是角度。因此：

| 情形 | 写法 |
| --- | --- |
| 只要「画面倾斜但不旋转」 | `camera.roll = dutch`，`camera.move` 取其它值（英文描述里写 `dutch angle`） |
| 要「镜头真的滚转一圈」 | `camera.move = roll_cw` 或 `roll_ccw`，`camera.roll` 不再重复填 |
| **禁止** | `camera.move = roll_cw` 与 `camera.roll = roll_cw` **同时出现**（重复计一次运镜类型） |

#### 3.7.4 光学 `camera.optics`（V1.1 新增，对应评审 D-09）

V1.0 全文**检索「光学」0 次**——不是写漏，而是**结构上没地方写**。后果可预测：客户按 V1.0 产出的包，必然复现原始稿「光学 0%」的分布。

| 枚举值 | 中文 | 说明 |
| --- | --- | --- |
| `deep_focus` | 大景深 | 前后景均清晰，交代空间关系 |
| `shallow_focus` | 浅景深 | 背景虚化，隔离主体 |
| `rack_focus` | 焦点转移 | 焦点从 A 移到 B——**等于剪了一刀但没切镜头** |
| `long_lens_compression` | 长焦压缩 | 空间被压扁，人物被「贴」到背景上 |
| `wide_angle_distortion` | 广角畸变 | 空间被拉伸，边缘变形，压迫感强 |

> **必须**：光学是**八维之一**，覆盖率门槛 **≥ 30%**（§4.2）。「构图 / 轴线 / 光线」同属此列，V1.0 分别为 2% / 0% / 20%（原始稿实测）。

**转场（V1.1 补 `transition_out`，对应评审 D-13）**

| 项 | 规则 |
| --- | --- |
| 值域 | `cut` / `fade_in` / `fade_out` / `dissolve` / `wipe` |
| **单侧表达（必须）——仅约束单元内部** | **同一生成单元内部**相邻两镜之间的衔接，**由后一镜的 `transition_in` 单侧表达**：单元内**非末镜一律不得**填 `transition_out`（即 `transition_out` 只出现在**单元末镜**，用于交代该单元的出点）。**禁止在单元内部「两头都写」**（同一处衔接被描述两次、取值可能互相矛盾）**或「两头都不写」**（衔接丢失） |
| **单元边界＝两半段（必须，V1.3 澄清）** | 相邻两个**生成单元**之间的衔接按**两个半段**表达——前一单元**末镜**用 `transition_out` 交代**出点**、后一单元**首镜**用 `transition_in` 承接**入点**；二者是同一次衔接的**两个方向**（「怎么出去」与「怎么进来」），**不构成上行的「两头都写」**。<br>⇒ **「单侧表达」与「两半段」是两条并行规则，不是矛盾**：前者约束**单元内部**的镜间衔接，后者约束**单元之间**的边界。本规范中未加限定的「相邻两镜」，**指同一单元内的相邻两镜**；「单元末镜与其下一单元首镜也属相邻两镜」的字面读法**不成立**。<br>⚠️ 单元边界两侧的**取值搭配**（如 `fade_out`＋`fade_in`、`dissolve`＋`dissolve`）属**导演创作判断**，本规范不规定唯一搭配；校验只保证「不缺失」与「单元内不双写」 |
| **跨模型映射（必须）** | 通用值 → 各模型字面 → **不支持的降级写法**：见 §6.5 |
| **H3 硬约束** | H3 **只有 5 条官方剪切短语**，且都属「切」类（见 §6.4 P0-1）；**不得出现官方 5 条之外的自造剪切短语**。`fade_in` / `dissolve` / `wipe` 在 H3 无对应写法，**降级为 `the shot transitions to`** |

**声音（V1.1 新增，对应评审 D-12）**

| 层级 | 字段 | 说明 |
| --- | --- | --- |
| 单元级 | `units[].soundscape` | 环境音（H3 `overall_soundscape` 投影源）。聚合规则：成员镜 `sfx` **取并集去重** |
| 单元级 | `units[].music` | 画外配乐（H3 `non_diegetic_music` 投影源）。**按段落归并**，**禁抽象情绪词** |
| 镜头级 | `shots[].sfx` | 原始音效提示，向上聚合 |
| 镜头级 | `shots[].dialogue` | 台词，须过语速校验（§4.5） |

> **为什么放在单元级而不是包级**：H3 是**三字段结构**，`overall_soundscape` 与 `non_diegetic_music` 是**每条提示词各自携带**的字段。若做成包级容器，投影时无法与生成单元一对一对应，两条音轨会丢失或全空。因此容器的粒度必须与**生成调用的粒度**一致。

#### 3.7.6 中英双写规则（V1.1 修正，对应评审 D-03）

| 规则 | 说明 |
| --- | --- |
| **语言倾向不是自由选项** | **当目标模型对语言位置有硬约束时，语言倾向不得覆盖该约束**（§6.3 第 1 维） |
| **英文优先模型** | 以 `prompt_en` 为**投喂源**。例：**H3 以英文为基底**，中文仅允许出现在 `<d>…</d>`（台词）与英文双引号内的画面可见文字 |
| **中文优先模型** | 以 `prompt_zh` 为投喂源（如 Seedance / 即梦 / 可灵，中文是工作语言，无位置限制） |
| 语义对齐 | `prompt_en` 不是逐字翻译，而是**面向模型优化的英文表达**；两者语义必须一致 |
| 要素顺序 | 统一按「主体 → 动作 → 环境 → 光线 → 镜头语言 → 风格」书写，降低模型理解成本 |
| 禁止项 | `prompt_zh` / `prompt_en` 内**不得**写模型参数指令（如 `--ar 16:9`），参数一律走结构化字段 |
| 画面可见文字 | **必须**加引号原样写出、不翻译；**H3 必须用英文双引号** `"…"`，中文引号违规 |
| 长度 | 单镜头建议 **90–280 字（中文）/ 450–1200 字符（英文）**（**V2.0 上修**，依据见下）；**超长优先拆镜**——**不得**靠压缩描述省字数（会牺牲「画面结果」维度，§3.5） |

> **长度建议值的上修依据（V2.0，依 `ISSUE-015`）**：V1.1 起的建议值「40–120 字（中文）/ 30–90 词（英文）」与本规范 §4.1「**八维双落地**」（每一维都须写进正文）在**长镜**下**无法同时满足**——长镜正文天然超出建议区间，两条要求**互斥**。
>
> **实测数据（17 镜样本，`CASE-002` 等）**：`prompt_en` 最长 **1113** 字符 / p95 **941** / p90 **897** / 均值 778 / 中位 804 / 最短 453；`prompt_zh` 最长 **265** 字 / p95 **252**。
>
> **新上限的定值口径＝「目标模型可接受输入上限」与「本项目实测分布」两者取小**（⚠️ **不得随意加位数**）：目标模型 H3 的 `max_prompt_chars` = **7000**（**不构成约束**），故取实测侧 ⇒ `CFG-006` schema 的 `prompt_en.maxLength` 上修为 **1200**（1113 + ≈8% 余量）、`prompt_zh` 上限**保持 600**（余量充足）。
>
> ⚠️ 实测 `prompt_en` 长度与镜长 `duration_ms` 相关性仅 **0.315**（`prompt_zh` 0.447，**均属弱相关**）⇒ **不可按镜长压缩**；长度由「本镜需落地的维度数量」决定，不由秒数决定。

### 4.1 八维镜头语言

八个维度**必须逐一覆盖**，且**同时满足两个条件**：

1. **有字段承载**（结构可校验，见 §3.6）；
2. **写进镜头描述正文**（`prompt_zh` / `prompt_en`；因为模型读到的是文本，不是字段）。

| # | 维度 | 字段承载 | 必须出现的内容 | 合格示例（H3 英文口径） | 缺失后果 |
| --- | --- | --- | --- | --- | --- |
| 1 | **景别** | `shot_size` | 标准术语之一 | `A medium close-up of …` | 观众无法建立空间尺度 |
| 2 | **运镜** | `camera.move/amplitude/speed/from/to` | **类型 + 幅度 + 速度** | `The camera pushes in with small amplitude at slow speed.` | 画面呆滞，模型默认静止 |
| 3 | **角度** | `camera.height`（+ `camera.roll`） | 机位高度／俯仰角，写出**谁高谁低** | `from a low angle so the table edge cuts across his chest` | 丢失权力关系与情绪倾向 |
| 4 | **光学** | `camera.optics` | 焦段／景深／焦点，写出**观众该看哪里** | `with a shallow depth of field, the lantern out of focus` | 视觉重点无法引导 |
| 5 | **构图** | `shot_language.composition` | 前中后景层次 + 主体在画框中的位置 | `she sits in the left third with the empty bench filling the foreground` | 画面扁平，无纵深 |
| 6 | **轴线** | `shot_language.axis` | 对手戏**必须**写屏幕方位，保证不跳轴 | `she stays on the right of the frame, he on the left, their eyelines meeting` | 对手戏跳轴，观众空间感错乱 |
| 7 | **光线** | `lighting` | **逐镜**光位／光质／光比，不是只在风格句里写一次 | `the lamp light falls on one side of his face only` | 光影扁平，无质感 |
| 8 | **画面结果** | `shot_language.result` | 动作/环境在画面上留下的**可见改变** | `the wine spreads across the wet floor and the nearest men flinch back` | **空气挥拳**——动作无反馈 |

**第 8 维「画面结果」是本项目的高频缺陷项（必须强调）**：武术／动作类镜头若只写「挥拳」而不写「击中后对方的反应或环境变化」，模型会生成**无接触的空挥动作**。

**运镜句的独立成句要求**：运镜要写成**独立句或镜头内的自然英语动作**，不藏在从句里，也不在同一句里写两次运镜。H3 的校验器**只认 `The camera` 起句**；其他模型虽不强制，但这仍是提高可控性的最佳实践。

**切镜与运镜的取舍（必须）**：切镜应带来**新信息**（新主体/空间/状态/视角/时间）；如果只是距离或轻微角度变化，**优先用运镜而不是切镜**。

### 4.2 质量门：11 项量化阈值与容差算法（V1.1 新增，对应评审 D-06）

> **阈值与公式必须直接引用 `audit_shots.py` 的 `GATE`，不得另立一套。**

| # | 指标 | 阈值 | 性质 |
| --- | --- | --- | --- |
| 1 | **运镜覆盖** | **100%** | 每镜必须有 |
| 2 | **景别覆盖** | **100%** | 每镜必须有 |
| 3 | **静止镜占比** | **≤ 40%** | 上限 |
| 4 | **运镜类型数** | **≥ `min(5, max(2, ⌈镜数/4⌉))`** | 下限 |
| 5 | **单一运镜占比** | **≤ 35%** | 上限 |
| 6 | 角度覆盖 | ≥ 40% | — |
| 7 | 光学覆盖 | ≥ 30% | — |
| 8 | 构图覆盖 | ≥ 50% | — |
| 9 | 轴线覆盖 | ≥ 30% | 有对手戏时强制 |
| 10 | 光线覆盖 | ≥ 40% | — |
| 11 | 画面结果覆盖 | ≥ 60% | — |

**两条算法规则（必须，否则阈值无法正确实现）**：

```
① 容差算法：允许条数 = max(1, ceil(比值 × 镜数))
   —— 任何比例类阈值至少允许 1 条，避免短单元被机械判死
   例：静止镜上限在 1/2/4/22 镜时分别为 1/1/2/9 条

② 运镜类型数下限的分母是「镜数」，不是「单元数」
   —— 因此 1 镜单元在数学上无法通过：min(5, max(2, ceil(1/4))) = 2 > 1
   —— 这是「每个生成单元 ≥ 2 镜」这条硬约束的数学来源（§4.3）
```

**判定口径（必须）**：

| 项 | 规则 |
| --- | --- |
| 作用范围 | 质量门**逐生成单元**判定（`--per-entry`），同时**整片**也须全通过 |
| 统计文本 | 对**目标模型的适配投喂文本**统计（英文优先模型用 `prompt_en`；中文优先模型用 `prompt_zh`） |
| 静止镜计数 | **含静止镜**——静止镜也是导演的主动选择，排除它会让「1 推镜 + 1 静止」的 2 镜单元被误判 |
| 全通过才交付 | **11 项全通过**，任一不通过即**阻断交付** |

### 4.3 生成单元划分三类约束（V1.1 新增，对应评审 D-05）

| # | 约束 | 数值 | 依据 |
| --- | --- | --- | --- |
| 1 | **每单元最少镜数** | **≥ 2 镜** | 由 §4.2 公式②推出——**1 镜单元结构性不合格** |
| 2 | **每单元最多镜数（八维版）** | **≤ 3 镜** | 3 镜是八维的天花板；4 镜实测必超字符上限（H3 单块 7,000 字符） |
| 3 | **单元内运镜类型不得重复** | — | 由单元承担「运镜丰富度」责任 |
| 4 | 超限处置 | **先拆单元，再上八维** | 不得靠压缩描述省字数（会牺牲「画面结果」维度） |
| 5 | 拆单元保持锚点 | — | `style_ref` 与 `character_refs` **不变**，否则跨单元一致性断裂 |
| 6 | 禁止拆到 1 镜 | — | 4 镜拆 2+2 可以；拆 3+1 **不行** |

> **字预算的实测依据**：八维全开比纯画面描述费字约 **+47%**（实测 4,724 → 6,933 字符 / 14 秒 4 镜）。**7,000 字符是真正的约束**，因此八维版单单元应压到 3 镜以内。
> **压缩优先级**：① 外观/场景在锚点里写过就不再抄一遍；② 音轨描述不复述外观；③ 删冗余定语；④ 对白密集段**优先保台词**，八维只保留轴线 + 景别 + 运镜，其余五维分配到别的镜头——**单元级达标，不是每镜都要八维全开**。

### 4.4 单人替身法则与主体唯一性（V1.1 新增，对应评审 D-22）

**单人替身法则（必须，这是最易违反的一条）**：

> 当镜头中**只有一名角色**时，**不得**使用「他／她」隐含指代或省略主语，**必须**用该角色的**具名锚点**（角色名或稳定 ID）明确指向。
>
> **原因**：多角色同框时模型可依上下文区分；**单角色时若省略主语，模型会引入第二个人物或改变角色外观**——这是单人镜头出现「多出一个人」的直接原因。

**主体唯一性（必须）**：

| 规则 | 要求 |
| --- | --- |
| 单镜主体上限 | `character_refs` 建议 ≤ 2 |
| 多主体区隔 | 同框必须写前后景分离 / 左右分侧 / 一主一虚 |
| 画面主体 | **画面主体必须唯一且明确**——多主体同框若不做区隔，AI 视频会**身份互相污染**（两个角色的脸互相借特征），**一旦出现就是整段报废** |

**单人戏（无对手单元）的八维替代律（应当）**：双人戏的八维本质是一套**关系学**；单人戏把「另一个人」抽走后，照双人模板硬填的结果是「一个不动的人在一个不动的房间里——八个格子全填了，但全是空的」。替代关系如下：

| 双人戏的参数 | 单人戏的替代物 | 怎么写 |
| --- | --- | --- |
| **视线轴**（A→B） | **空间轴**（场景自身的两个方向，如「窗 ↔ 门」） | 用场景的方向做轴；摄像机永不越线 |
| **对手**（第二个人） | **光** | 光是唯一在场的另一个角色；**每镜都要说出「这一镜的光在干什么」，且必须是变化** |
| **正反打**（切另一边） | **焦点对切**（`rack_focus`） | 换一次焦点＝换一次注意力，等于剪了一刀但没切镜头 |
| **台词**（两人对话） | **身体** | 画外音必须嘴唇闭合，「他在说什么」先由身体说一遍（喉头吞咽／手指收紧／肩线沉下／呼吸停半拍） |
| **角度** | 不受对切约束 | 角度就是最直接的内心外化工具：`high`＝被压着、`eye_level`＝中性、`low`＝顶着 |
| **景别** | 不受对切约束 | 可以**跳级**（`wide` → `close_up`） |

**两条禁律（必须）**：① **禁「无光的镜头」**——光若没有任务，这一镜就是空的；② **禁「无结果的静止」**——静止镜里必须有一样东西在动，**而且必须被写出来**（**静止镜 ≠ 空镜**）。

**总纲**：**以动写静**——单人戏的「表演」不在人身上，在**场**上；找**最小的在动的东西**当主角（雨丝/一滴水/灯焰/汗珠），**人反而是那个不动的**。

### 4.5 台词—时长（语速）约束（V1.1 新增，对应评审 D-11）

| 项 | 数值 | 说明 |
| --- | --- | --- |
| 中文基准语速 | **≈ 6.5 字/秒** | 正常播报语速 |
| **不可行阈值** | **> 9 字/秒** | 超出即无法自然念完（配音赶不上，或必须变速导致失真） |
| 判据公式 | 台词字数 ÷ (duration_ms / 1000) ≤ 9 | 逐镜计算 |
| **处置原则（必须）** | **只延长镜头时长，不改画面内容** | 改画面会破坏已通过的镜头语言 |

**必须**强调：

| 禁止的绕过方式 | 为什么不行 |
| --- | --- |
| 「删台词」 | 破坏叙事 |
| 「加快语速」 | 配音语速不可调 |
| 「改画面」 | 回改意味着**动画面**，是所有处置里成本最高的一种 |
| **唯一正确处置** | **延长该镜时长**——延长窗口是唯一低成本的解法。需同时校验不超过模型时长上限，超限则按 §4.3 拆单元 |

> 台词念不完，**客户一投喂就发现，只能回改**——这是所有失败中返工代价最高的一种，因为回改要动画面。因此它必须是**交付前的门禁**，不是交付后的救火。

### 4.6 动作复杂度—时长预算（V1.1 新增，对应评审 D-10）

**结构化字段 `action`（必须）**：

```
"action": {
  "start":  "起始状态：古月白独立桥中央偏左，苗刀横于胸前",
  "change": "核心变化：拧腰转身，刀身贴刀背缠绕下压",
  "end":    "结束状态：两刀分离，各退半步，刀锋仍指向对方"
}
```

**导演的基本功是：一个镜头只服务一个核心动作**，且**必须写清「开始 / 核心变化 / 结束」三段状态**。缺了它，最常见的翻车是——**3 秒里写了一个 8 秒才能完成的动作**，模型只能给你一个糊掉的中段。

**动作复杂度—时长参考表（建议口径）**：

| 动作类型 | 建议最短时长 | 超出时处置 |
| --- | --- | --- |
| 单一姿态或表情变化 | 2–3s | — |
| 单一位移（走、转身） | 3–5s | 拆镜 |
| 位移 + 情绪变化 | ≥ 6s | 拆镜 |
| 复合动作（转身 + 出手 + 落地） | ≥ 8s | **必须拆镜** |

> **必须**与 §6.6 的时长上下限校验联动。**应当**：相邻单元之间做一次「**重复动作排查**」——把跨单元的连续动作逐条列出，确认每一格只被拍一次（这是纯文本校验查不出、只有跨单元比对才能发现的硬伤；本项目实测曾抓到一处真重复）。

### 4.7 三把尺子（V1.1 新增）

规范**必须**声明本项目存在三把独立的质量尺子，且说明哪些可跨模型复用：

| 尺子 | 量什么 | 换模型时 | 可否工具化 |
| --- | --- | --- | --- |
| ① **规范合规** | 是否满足目标模型的格式与语法约束 | **必须重建** | 可（每家一套规则集，H3 侧为 `h3_compiler.py`） |
| ② **镜头语言八维** | 镜头语言是否丰富（§4.1 + §4.2） | **可直接复用** | 可（与模型无关，`audit_shots.py`） |
| ③ **语义合规** | 是否满足内容安全与语义保真要求 | 可直接复用 | **不可**——须人工 |

> **必须写进交付说明的一句话**：**「规范合规」不等于「镜头拍得好」。** 一套提示词可以 100% 满足模型格式约束，同时八维中六维覆盖率为 0。**两把尺子必须分别校验。**

### 4.8 质量门的执行与留档（V1.1 新增）

| 项 | 要求 |
| --- | --- |
| 执行时机 | 每次交付前，作为 §8.3 门禁的**第 13 项** |
| 执行对象 | 该交付包的目标模型适配投喂文本（逐单元 + 整片） |
| 命令 | `python audit_shots.py <适配文本> --gate`；逐单元用 `-u`；机器可读用 `--json` |
| 留档 | 报告落盘为交付包内 `qa/audit_report.txt`，留存 **≥ 6 个月**（§8.4） |
| 阻断 | 任一单元或整片未达标即**阻断交付**，不得以「客户急着要」为由放行 |

> **为什么必须留档**：备案材料需要「安全能力与安全机制的实物证据」。一张能跑出结论的质量门报告，比一句「我们很重视质量」有力得多；而 **D-23 的教训是「靠人记着做的事，等于没人做」**——因此质量门是**脚本产出物**，不是承诺。

## 5 AIGC 元数据块规范

> 对应需求：SW-013（隐式生成标识）、SW-014（元数据传递）；法规依据：《标识办法》§5、GB 45438—2025 §6.1 与附录 E

### 5.1 字段定义

元数据块**必须**为**单个 JSON 对象**，顶层键为 `AIGC`，取值规则见下表：

```json
{
  "AIGC": {
    "Label": "1",
    "ContentProducer": "{{PROVIDER_NAME}}/{{PROVIDER_CODE}}",
    "ProduceID": "FR-PK-20261012-7K2M9XQ4",
    "ReservedCode1": "",
    "ContentPropagator": "{{PROVIDER_NAME}}/{{PROVIDER_CODE}}",
    "PropagateID": "FR-PK-20261012-7K2M9XQ4",
    "ReservedCode2": ""
  }
}
```

| 字段 | 取值规则 | 本项目填写 |
| --- | --- | --- |
| `Label` | 生成合成标签 | 固定 `"1"`（表示人工智能生成合成内容） |
| `ContentProducer` | 内容制作方（生成合成服务提供者）标识：`<名称>/<提供者编码>` | `{{PROVIDER_NAME}}/{{PROVIDER_CODE}}` |
| `ProduceID` | 内容编号，**全局唯一**，编码规则见 §5.2 | 与 `meta.pack_id` 同值 |
| `ReservedCode1` | 预留字段 | 留空字符串 `""` |
| `ContentPropagator` | 内容传播方标识，格式同 `ContentProducer` | **首次写入时与 `ContentProducer` 完全同值**（本系统即传播起点；后续被他人传播时，由传播方按标准自行追加/更新） |
| `PropagateID` | 传播编号 | **首次写入时与 `ProduceID` 同值** |
| `ReservedCode2` | 预留字段 | 留空字符串 `""` |

> ⚠️ **字段语义与取值以 GB 45438—2025 附录 E 正式文本为准**。本规范采用其规范格式；`ContentProducer` 的具体组成（是否需要附带统一社会信用代码、编码由谁分配）**须在备案前核对标准原文与主管部门口径后回填**（§13 待明确事项 **NT-02**）。**回填前不得用于正式交付**，用占位符 `{{PROVIDER_CODE}}` 仅作结构演示。

### 5.2 内容编号（`ProduceID`）编码规则

编号**必须**满足：全局唯一、可反查生成记录、无歧义字符、长度可控。

```
<企业码>-<产物类型码>-<YYYYMMDD>-<8位任务短码>

示例：FR-PK-20261012-7K2M9XQ4
      │  │   │           └ 任务短码：任务 ID 经 Crockford Base32 编码后取前 8 位
      │  │   └ 生成日期（UTC+8）
      │  └ 产物类型码（见下表）
      └ 企业码（{{PROVIDER_NAME}}，FR）
```

| 产物类型码 | 含义 | 产物类型码 | 含义 |
| --- | --- | --- | --- |
| `GR` | 故事梗概 | `SB` | 分镜脚本 |
| `SC` | 剧本 | `PK` | 分镜提示词包 |
| `EX` | 导出包 | | |

**规则**：

| 规则 | 说明 |
| --- | --- |
| **必须** | 字符集限定为 `A-Z0-9-`；大小写按 Crockford Base32 规则（排除易混字母 `I` `L` `O` `U`） |
| **必须** | 同一 `pack_id` 在同一交付包内**只出现一次** |
| **必须** | 编号写入生成记录（`SW-D02` / `SW-D03`），支持「编号 → 生成记录」反查 |
| 应当 | 重新生成（改稿）不沿用旧编号，生成新编号并保留旧编号的历史记录 |
| 应当 | 编号长度固定为 24 字符（企业码 2 + 分隔 1 + 类型 2 + 分隔 1 + 日期 8 + 分隔 1 + 短码 8 ≈ 23–24），便于校验 |

### 5.3 写入位置与唯一性

| 载体 | 写入方式 | 唯一性要求 |
| --- | --- | --- |
| `shot_prompt_pack.json` | 顶层 `aigc_meta` 键 | **仅一份** |
| 导出 JSON | 顶层 `AIGC` 键（导出文件为独立文件时写一份） | **仅一份** |
| 导出 XLSX | 文档属性（自定义属性）+ 首行标识行的元数据列 | **仅一处**（以文档属性为准） |
| 导出 MD / TXT | 文件末尾「元数据块」段落（与首部显式标识区分） | **仅一份** |
| 导出 CSV | 表尾注释行（`#AIGC:` 前缀） | **仅一份** |
| **模型适配文本** | **不写入**（避免污染提示词，见 §6.8） | — |
| 视频侧（由客户落地） | 提示客户写入成片容器元数据 | 由下游工具/客户负责 |

> **GB 45438 明确要求「文件中仅保留一份」隐式标识**。实现时须做**去重校验**：同一文件内出现 ≥2 个 `AIGC` 元数据块即**阻断交付**。

### 5.4 防删改与校验

| 措施 | 说明 | 对应需求 |
| --- | --- | --- |
| 解析校验 | 交付前校验元数据块可被 JSON 解析、字段齐全、`Label` 合法 | SW-013 |
| 一致性校验 | `ProduceID` 与 `meta.pack_id`、`statement_id` 三者互相关联且可对上 | SW-016 |
| 变更留痕 | 任何对元数据块的改写（如回填提供者编码）都记录变更时间与操作者 | SW-016 |
| 无去标识功能 | 系统**不得**提供移除/隐藏/伪造元数据的功能；管理控制台同样禁止 | 《标识办法》§10 |
| 交付声明告知 | 在 `COMPLIANCE.md` 中告知：删除、篡改、隐匿标识属法规禁止行为 | §8.2 |

## 6 多模型适配规范（第 2 层 · V1.1 重写）

> 对应需求：SW-007（提示词生成 + 按优先级适配）、SW-025（多模型适配）；决策依据：SYS-Q4（通用规范为基准）、SYS-Q17（优先级）
> **V1.1 变化**：V1.0 的 §5.4 是**按公共印象写的占位内容**，与官方规范存在系统性冲突（详见 §6.4 各条目的「V1.0 错在哪」）。本章按**项目已实测核实的规则实现**重写。

### 6.1 适配原则：基准 + 单向投影

```
        ┌──────────────────────────────┐
        │  通用规范提示词包（基准）      │  ← 唯一真值来源（shot_prompt_pack.json）
        │  schema 固定、字段完整、可校验  │
        │  含：内容质量层（第 4 章）      │
        └───────────────┬──────────────┘
                        │  单向投影（只读，不回写）
```

#### P0-1 MiniMax H3（海螺）· `verify_status: verified`

**V1.0 错在哪（必须先看清，否则会照抄错的）**：

| # | V1.0 的写法 | 实测事实 |
| --- | --- | --- |
| 1 | 运镜用**方括号指令** `[Push in]`、`[Static shot]` | **H3 不使用方括号指令**；运镜是**英文自然语言末句**，必须写成「类型 + 幅度 + 速度」三元组 |
| 2 | 「中英双写并**以中文为主**」 | H3 硬约束：**框架描述里中文只允许出现在 `<d>…</d>` 与英文双引号内**。按「以中文为主」投影会**整段判违规** |
| 3 | 时长只设上限 | H3 时长为 **4–15 秒整数**，**下限同样是硬约束**；V1.0 示例包的 3000ms 已低于下限 |
| 4 | 负向词写成 `（负向：雨势过大）` | **H3 基础模式（三字段）没有 Negative 字段**。原样粘贴会被理解成「画面里要出现雨势过大」——**负向词直接变成正向指令** |

**适配规则（11 维）**：

| 维度 | 适配规则 |
| --- | --- |
| 语言倾向 | **英文为基底**（`prompt_en` 为投喂源）。**中文仅允许出现在 `<d>[Chinese]…</d>`（台词）与英文双引号内的画面可见文字**；框架描述不得出现中文 |
| 组织顺序 | 主体 → 动作 → 环境 → 光线 → 镜头语言 → 风格；**风格句写在 `[Shot 1]` 之内**（六段式则写在 `[Shot 1]` 之前，最易搞混） |
| 运镜表达 | **英文自然语言末句**，**必须以 `The camera` 起句、独立成句**，写成三元组：`The camera pushes in with small amplitude at slow speed.`<br>**仅当需要强调时**才出现幅度/速度（`small`/`large`、`slow`/`fast`；`medium`/`normal` 省略）；`Static Shot` / `POV` **不带**幅度与速度<br>**禁止**方括号指令、禁止把运镜藏在从句里 |
| 负向提示词 | **不支持独立字段**。**必须**把 `negative_global` / `negative_prompt` 转写为**正向约束句**（如「保持雨势中等」「画面无字幕与水印」「建筑保持年代感」）；<br>**交付文本中不得存在任何形式的负向残留**——包括用中文括号伪装的「（负向：…）」 |
| 参考图 | 支持首帧（I2VA）/ 首末帧（FL2VA）/ 尾帧（L2VA）/ 全参考（Ref2VA）<br>**素材上限：图 ≤ 9、视频 ≤ 3、音频 ≤ 3**；标签 `<Subject N>` / `<Picture N>` / `<Video N>` / `<Audio N>`（编号唯一、正文标签必须已定义） |
| **时长上下限** | **4–15 秒整数**（`MIN_DUR, MAX_DUR = 4, 15`）。毫秒精度无意义，**必须整秒** |
| 画幅与分辨率 | 由平台参数控制，提示词内不写；`aspect_ratio` 仅作目标值提示 |
| **输入长度上限** | **单块 ≤ 7,000 字符**（`MAX_CHARS = 7000`）。**八维版单单元 ≤ 3 镜**（§4.3） |
| 导入格式 | 纯文本提示词，逐生成单元一块（三字段 / 六段式）；提供 `exports/minimax_h3/minimax_h3.txt` |
| 特殊约束 | 避免真实人物姓名与肖像描述；避免平台禁用词（走词库校验）<br>**切镜措辞只有 5 条**（见下）；`<d>` 与 `</d>` 数量必须配对；对白不得复述进 `overall_soundscape`；`non_diegetic_music` 禁抽象情绪词<br>**运镜句必须独立成句**，且排版换行时**不得把 `The camera` 拆到两行**（校验器只认连续字符串，拆开后该镜被判「缺少运镜句」，人眼看不出） |
| **声音组织** | **分轨字段**：`overall_soundscape`（1–4 句）+ `non_diegetic_music`（1–3 句），**每条提示词各自携带**。<br>投影源：该生成单元的 `units[].soundscape` / `units[].music`；**跨镜聚合**：环境音取并集去重、配乐按段落归并 |

**H3 官方切镜短语（只有这 5 条，不得自造）**：

```
the camera cuts to     /  the shot cuts to     /  the shot transitions to
the shot changes to    /  the shot switches to
```

> **必须**：`[Shot 2]` 起每一镜都要使用上述 5 条之一。`fade_in` / `dissolve` / `wipe` 在 H3 **无对应写法**，**降级为 `the shot transitions to`**（§6.5）。

**适配输出样例（V1.1 重写，注意：无方括号指令、无负向残留、英文基底、末句三元组）**

```
integrated_multimodal_description:
  [Shot 1] A wide shot of a rainy old alley in Jiangnan at dusk. Wet cobblestone
  reflects a lantern glow; a girl with an umbrella stands small in frame right.
  The camera holds a static shot at eye level. Warm lamplight rims her shoulders
  while the walls stay half in shadow; rain streaks left to right across the frame.

  At 0:04.00, the camera cuts to:
  [Shot 2] A close-up of the girl as she slowly raises her head. Rain beads roll
  down her hair tips and fall past her collar.
  The camera pushes in with small amplitude at slow speed toward her eyes, holding
  a shallow depth of field so the rain curtain behind her stays out of focus.
  The rain stays moderate and the architecture remains period Jiangnan, with no
  modern structures and no on-screen text.

overall_soundscape:
  Steady rain on roof tiles, a distant bicycle bell, water dripping from the eaves.

non_diegetic_music:
  A sparse solo erhu line, slow and low, over a faint sustained pad.
```

> ⚠️ **换行陷阱（必须遵守）**：H3 校验器只认**连续字符串** `The camera`。适配文本做硬换行排版时，**不得把 `The camera` 拆到两行**（如行末 `The`、下行开头 `camera`）——拆开后该镜会被判「缺少运镜句」，而人眼看不出问题。同理，运镜句**必须独立成句**、**不得藏在从句里**。
>
> **注意第二镜末句**：`The rain stays moderate and the architecture remains period Jiangnan, with no modern structures and no on-screen text.` —— 这就是「**负向词转写为正向约束句**」的正确姿势。**不得**写成 `（负向：现代建筑、文字）`。

| 导入格式 | 文本 + 运镜选项 / 六轴参数；提供 `exports/kling/kling.txt` |
| 特殊约束 | **禁止相互冲突的指令**（如「晴朗的日子 + 暴雨」）；图生视频时**只描述动作与镜头，不描述画面**（模型已看到起始帧）；「2500 是天花板不是目标」——**60–100 字精炼提示词效果几乎总是优于 2000 字堆砌** |
| 声音组织 | 原生音频（2.6+）可指定对白/环境声/音效；由 `units[].soundscape` / `units[].music` 映射 |

**模糊词 → 明确术语对照（改造时最常用）**

| 模糊词汇 | 明确镜头语言 |
| --- | --- |
| 电影感运动 | 缓慢推近，浅景深 |
| 让画面动起来 | 快速横摇跟拍主体 |
| 不错的角度 | 低角度跟踪拍摄，35mm 镜头 |
| 绕着它拍 | 向左环绕，平滑的 180 度弧形运镜 |
| 加点运动感 | 手持推近，伴随细微抖动 |

#### P3 其余模型（Vidu / 通义万相 / Pika / Runway 等）

**降级策略**：输出**通用规范提示词文本**（按 §3.7.6 要素顺序书写的中文完整描述）+ **《通用使用说明》**（说明如何把结构化字段人工填入该平台）。除非客户明确要求，不单独定制。

### 6.5 镜头语言与转场的跨模型映射（V1.1 新增，对应评审 D-13/D-20）

**转场映射表（必须）**

| 通用值 | H3 | Seedance | 可灵 | 即梦 | 不支持时降级 |
| --- | --- | --- | --- | --- | --- |
| `cut` | `the camera cuts to` / `the shot cuts to` | 时间区间直接分段 | 多镜头模式切分 | `镜头切换` | 分段 |
| `fade_in` | **无对应** → `the shot transitions to` | `fade in from black` | 自然语言「淡入」 | 自然语言「淡入」 | 通用：淡入 |
| `fade_out` | **无对应** → `the shot transitions to` | `fade to black` | 自然语言「淡出」 | 自然语言「淡出」 | 通用：淡出 |
| `dissolve` | **无对应** → `the shot transitions to` | `natural dissolve` | 自然语言「叠化」 | 自然语言「叠化」 | 通用：叠化 |
| `wipe` | **无对应** → `the shot transitions to` | `wipe`（可点名方向） | 自然语言「划像」 | 自然语言「划像」 | 通用：划像 |

> **H3 的硬约束**：**不得出现官方 5 条之外的自造剪切短语**。所有非「切」类转场在 H3 一律降级为 `the shot transitions to`（或 `the shot changes to`）。

**景别 / 光学 / 光照的映射**见 `config/CFG-002_shot_vocab.yaml` 的 `model_map` 字段。**新增模型必须先把这三张表补全**，再写适配代码。

### 6.6 降级与拆分策略（V1.1 补充下限，对应评审 D-04）

| 场景 | 处置 |
| --- | --- |
| 未知模型或无适配配置 | 输出通用规范 + 使用说明（**必须**，不得阻断交付） |
| **单镜头时长 > 模型上限** | 按语义边界**拆分**为多个连续镜头（`shot_id` 加后缀 `-a`/`-b`），保持 `style_ref`、`character_refs`、`unit_id` 不变 |
| **单镜头时长 < 模型下限（V1.1 新增）** | **合并相邻镜头，或延长至下限**——**只延长时长，不改画面**。不得靠压缩描述或删减动作凑时长 |
| **`duration_ms` 非整秒（V1.1 新增）** | **必须**取整——模型侧不接受毫秒精度，毫秒只会制造虚假的精细感 |
| 提示词长度 > 模型输入上限 | 按优先级裁剪：删除修饰性形容词 → 精简环境描述 → 缩短风格串（**禁止**删除主体动作与镜头语言） |
| 单元内运镜类型重复 | 回到 §4.3 重新切分单元（**先拆单元，再上八维**） |
| 适配配置未核对（`pending` / `partial`） | 输出时附「适配参数待核对」提示，**不得**标记为已验证 |
| 平台不支持负向提示词 | 转写为**正向约束句**；同时在交付说明中标注该转换，并确认**文本中无负向残留** |

> **下限为什么比上限更容易踩**：分镜习惯天然写短镜（2–3 秒切一次），而视频模型的下限普遍在 3–4 秒。V1.0 防住了「太长」，漏掉了「太短」——**示例包的第一镜因此直接失败**。

```
② 填写 11 个适配维度；无法确认的项置 verify_status: pending
③ 先在 CFG-002_shot_vocab.yaml 的 model_map 补齐该模型的运镜/景别/光学/光照字面
```

### 6.8 适配输出格式规范（V1.1 改两段式，对应评审 D-19）

| 要求 | 说明 |
| --- | --- |
| **两段式（必须，V1.1 新增）** | 文件分**标识区**与**提示词区**，中间用固定分隔行隔开（见下）。**两段都保留**——合规不掉、可投喂性也保住 |
| **文件头复制说明（必须）** | 用一句话写清「请从分隔行以下复制」，避免客户全选复制时把标识粘进模型 |
| 分组 | 以**生成单元**为单位分块（每个单元一个 `<model> 块`），单元内再分镜 |
| 分隔 | 单元之间用 `━━━ 单元 U01（3 镜 · 14s）━━━` 之类**固定分隔行**，便于人工逐条复制 |
| 顺序 | 严格按 `unit_id` → `scene_no` → `shot_no` 升序 |
| 完整性 | 每个镜头**必须**至少含：画面描述文本 + 时长 + 画幅（缺失时长/画幅时用 `meta` 默认值补齐并标注） |
| **不含元数据** | 模型适配文本**不含** AIGC 元数据块（避免污染提示词）——但**必须含显式标识区**（§9.2） |
| 编码 | UTF-8 无 BOM |

**两段式结构（必须）**：

```
【AI生成内容】本文件由AI生成，已经过合规验证        ← 标识区（此处标注「请勿复制」）
════════════ 以下为提示词区，请从此行以下复制 ════════════
━━━ 单元 U01（3 镜 · 15s · MiniMax H3）━━━
（纯提示词内容）
```

> **为什么必须两段式**：客户要投喂，最自然的动作是**全选复制**。V1.0 的单段式会让 `【AI生成内容】…` 一起被粘进模型——**生成出来的画面里会真的出现这行字**。合规做对了，可用性做没了。

## 7 标识素材规范

> 对应需求：SW-014（标识素材包）；法规依据：《标识办法》§4(四)、GB 45438—2025 §5.4

### 7.1 法规硬指标（GB 45438—2025 §5.4）

视频显式标识**必须**同时满足：

| # | 硬指标 | 要求 |
| --- | --- | --- |
| 1 | 文字内容 | 含「**人工智能**」或「**AI**」，且含「**生成**」和/或「**合成**」 |
| 2 | 位置（时间） | 位于**起始画面**；**可**在末尾或中间适当位置添加 |
| 3 | 位置（空间） | 位于画面**边或角** |
| 4 | 字号 | **文字高度 ≥ 画面最短边 5%** |
| 5 | 时长 | 正常播放速度下**持续 ≥ 2 秒** |

### 7.2 本项目规格（建议值，含余量）

| 参数 | 法规下限 | **本项目取值** | 取此值的原因 |
| --- | --- | --- | --- |
| 文字高度 | ≥ 最短边 5% | **≥ 最短边 6%** | 预留缩放/转码/裁切损耗余量 |
| 持续时长 | ≥ 2s | **3s** | 视频平台转码可能裁头尾，留 1s 余量 |
| 位置 | 边或角 | **横版：右下角；竖版：底部居中偏下** | 避开平台 UI 遮挡区（进度条、按钮） |
| 安全边距 | 无规定 | **≥ 最短边 4%** | 防裁切 |
| 对比度 | 无规定 | 文字与背景对比度 **≥ 4.5:1**，加深色半透明底衬 | 保证可辨识（低对比度是常见被驳回原因） |

**尺寸换算表**（字高按本项目 6% 计）

| 画面规格 | 最短边 | 法规下限 (5%) | **本项目字高 (6%)** |
| --- | --- | --- | --- |
| 1920×1080（横版 1080p） | 1080 | 54 px | **65 px** |
| 1080×1920（竖版 1080p） | 1080 | 54 px | **65 px** |
| 1280×720（横版 720p） | 720 | 36 px | **43 px** |
| 720×1280（竖版 720p） | 720 | 36 px | **43 px** |
| 3840×2160（横版 4K） | 2160 | 108 px | **130 px** |

| 文件 | 类型 | 用途 | 展示要求 |

### 7.4 文案规范

| 项 | 文案 |
| --- | --- |
| **本期定稿（SYS-Q15）** | `本文件由AI生成，已经过合规验证` |
| 建议替换（见下风险提示） | `本文件由人工智能（AI）生成，请注意甄别` |

**合规要素核对**（定稿文案）：

| 硬指标 | 核对结果 |
| --- | --- |
| 含「AI」 | 是 |
| 含「生成」 | 是 |
| 长度可控 | 是，14 字，单行可容纳 |
| 可辨识 | 是，需配合底衬保证对比度 |

> ⚠️ **风险提示（重申）**：标识的立法目的是**提示公众甄别**，不是给内容做真实性背书。「已经过合规验证」后六字若日后内容被认定违规，可能被作为「已自认完成验证」的不利证据。因此：
> - 文案已做成**集中配置项**，替换不需改代码；
> - 若保留原文案，**应当**在用户服务协议与交付声明中写明：「本标识仅声明内容由 AI 生成，不构成对内容真实性、准确性或合法性的承诺」；
> - 素材会**同时提供两套文案版本**，便于随时切换。

### 7.5 字体与版权注意事项

| 注意点 | 说明 |
| --- | --- |
| **必须** | 正式交付素材使用的字体须具备**商用授权**。推荐免费商用中文字体：思源黑体（SIL OFL）、阿里巴巴普惠体、HarmonyOS Sans |

| 禁止 | 不得使用微软雅黑、方正系列等**需授权**字体投入正式交付 |
| 说明 | `assets/` 中的候选样式**若使用系统字体，仅作视觉预览**，正式素材须替换为授权字体后重新生成 |

> 这一点在备案与商业使用中都会涉及——**字体侵权**是短视频/漫剧领域被索赔的高频风险点，务必在素材生成管线中固定为「授权字体白名单」。

| 10 | 交付包内无密钥、无外部依赖、离线可用 | SYS-018 | **阻断交付** |

> **实现要求**：该清单应作为**交付前的强制门禁**（工程侧为一次校验过程，见 `03-工程代码/delivery/validate_pack.py`），任一「阻断」项不通过即不允许生成交付包——这既是合规要求，也是备案材料中「安全控制机制」的核心举证点。
>
> **第 18 项的由来**：V1.0 的 `notes` 示例写着「需人工核对角色一致性」，但自检清单里**没有这一项**。**靠人记着做的事，等于没人做**；而且这一条对备案尤其重要——「我们设计了人工核对环节」如果拿不出记录，等于没设计。

| 留档内容 | 留存期 | 说明 |
| --- | --- | --- |
| 交付合规声明副本 | **≥ 6 个月** | 每次交付一份，编号唯一 |

## 9 导出与文件格式规范

> 对应需求：SW-022（内容导出含导出文件显式标识）、SW-I04、SW-020（导出鉴权）；法规依据：《标识办法》§4 末段

### 9.1 支持格式与用途

| 格式 | 用途 | 对应文件 |
| --- | --- | --- |
| **JSON** | 机器可读的完整提示词包（四件套之一） | `shot_prompt_pack.json` |
| **CSV** | 分镜表，表格软件直接打开，便于批量复制 | `exports/shot_prompt_pack.csv` |
| **XLSX** | 分镜表（含标识行与文档属性），商务协作常用 | `exports/shot_prompt_pack.xlsx` |
| **Markdown** | 可读文本稿，便于阅读与二次编辑 | `exports/shot_prompt_pack.md` |
| **TXT** | 各模型适配格式（纯文本，**两段式**，便于逐条投喂） | `exports/<model>/*.txt` |
| **TXT（质量门报告）** | 镜头语言质量门结论 | `qa/audit_report.txt` |
| **PDF**（可） | 归档与打印版 | `exports/shot_prompt_pack.pdf` |

### 9.2 各格式的标识注入方式（差异化，必须）

> 依据《标识办法》§4 末段：「提供下载、复制、导出等功能时，应当确保文件中含有满足要求的显式标识。」

| 格式 | 显式标识注入位置 | 隐式标识注入位置 |
| --- | --- | --- |
| **TXT（适配）** | **首段标识区**（`【AI生成内容】…`）+ **末行**重复标注；**提示词区以固定分隔行起始**（§6.8 两段式） | 文件末尾元数据块段落 |
| **MD** | **文首引用块**（`> 【AI生成内容】…`）+ **文末**标注 | 文末 `## 元数据` 小节 |
| **JSON** | 顶层 `explicit_mark` 字段（文案 + 位置说明） | 顶层 `AIGC` 键 |
| **CSV** | **首行注释行**（`#AI生成内容…`）+ **末行**重复 | 末行 `#AIGC:` 前缀的 JSON |
| **XLSX** | **首行合并单元格标识行**（醒目填充色）+ **工作簿自定义属性**（标题/备注） | 工作簿自定义属性（`AIGC_*`） |
| **PDF** | **页眉或页脚**固定标识（每页可见） | 文档属性（Key/Value） |

**必须**：任一格式的标识注入失败 → **阻断导出并告警**，不得出现「导出成功但无标识」。
**必须**：标识文案与实际配置一致（集中配置项，不得硬编码在多个位置）。
**必须（V1.1）**：适配 TXT 中，标识区与提示词区**必须**由固定分隔行隔开，且文件头含一行复制说明——防止客户全选复制把标识粘进模型。
**应当**：导出文件**不**包含用户隐私信息与内部调试字段。

### 9.3 文件命名规范

```
<pack_id>_<内容类型>_v<版本>.<扩展名>

示例：
FR-PK-20261012-7K2M9XQ4_分镜提示词集_v1.1.json
FR-PK-20261012-7K2M9XQ4_分镜表_v1.1.xlsx
FR-PK-20261012-7K2M9XQ4_适配_MiniMaxH3_v1.1.txt
```

| 规则 | 说明 |
| --- | --- |
| **必须** | 文件名以 `pack_id` 开头，保证与元数据可互相检索 |
| **必须** | 不含空格与特殊字符（反斜杠、正斜杠、冒号、星号、问号、英文双引号、尖括号、竖线） |
| 应当 | 内容类型用中文（客户可读） |
| 应当 | 同一包多次导出时版本号递增，不覆盖旧文件 |

### 9.4 导出鉴权与留痕

| 项 | 要求 | 依据 |
| --- | --- | --- |
| 鉴权 | 导出前**必须**校验真实身份认证状态，未认证**拒绝**导出 | SYS-003、SW-020 |
| 留痕 | 每次导出记录：时间、操作者、`pack_id`、格式、文件校验和 | SW-016 |
| 留存 | 导出留痕 **≥ 6 个月** | 《标识办法》§9 |
