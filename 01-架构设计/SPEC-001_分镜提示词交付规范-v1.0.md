## 0 文档说明

### 0.1 目的

本系统只生成**文本**（分镜提示词集），最终对外传播的却是**视频**，标识义务因此跨主体。本规范解决三个问题：

| 问题 | 本规范的解法 |
| --- | --- |
| 客户拿到提示词后不知道怎么用、格式对不上 | 定义**通用规范 + 多模型适配**的提示词包结构（第 3、5 章） |
| 视频侧标识义务落在下游工具，本系统如何尽责 | 交付**标识素材包 + AIGC 元数据块 + 合规声明**（第 4、6、7 章） |
| 备案需要「安全能力与安全机制的实物证据」 | 交付前**自检 + 留档 + 声明**（第 7 章），并可用第 10 章验收标准逐条举证 |

### 0.2 适用范围

| 范围 | 说明 |
| --- | --- |
| **适用** | 本系统向客户交付的所有产物：梗概、剧本、分镜脚本、**分镜提示词集**及其导出文件 |
| **不适用** | 文生视频生成本身（本系统不做）；客户使用下游工具后的成片（本系统不接触、不核验） |
| **约束对象** | 工程实现（SW-007/014/022/025/026/SW-I04）、交付物本身、交付流程 |

### 0.3 规范用语（强制等级）

| 用语 | 含义 | 违反后果 |
| --- | --- | --- |
| **必须（MUST）** | 法规强制项或合规红线，不可协商 | **阻断交付**，记录并告警 |
| **应当（SHOULD）** | 强推荐，偏离须在交付记录中写明理由 | 记录偏离说明 |
| **宜（MAY）** | 建议做法，可按场景取舍 | 无 |
| **可（CAN）** | 可选增强能力 | 无 |

> **重要区分**：法规原文中的「应当/应」是**法定义务**（如《标识办法》§8 要求协议写明标识规范）；本规范中的「必须」用于标注**实现层面的强制校验点**（如导出文件缺显式标识则阻断导出）。两者不可混用，写备案材料时须分开表述。

## 1 交付形态总览

### 1.1 交付四件套

每次交付**必须**同时包含以下四项，缺一不可（SW-014）：

```
交付四件套
├── ① 分镜提示词集（shot prompt pack）
│      通用规范 JSON（基准） + 目标模型适配格式（按需）
├── ② AIGC 元数据块（aigc_meta）
│      GB 45438—2025 附录 E 规范格式，随包一份
├── ③ 标识素材包（overlay assets）
│      片头卡 / 角标素材（横版 + 竖版），满足 GB 45438 §5.4 硬指标
└── ④ 交付合规声明（compliance statement）
       标识方法说明 + 客户标识义务提示 + 禁止删改告知 + 自检结论
```

> **为什么是「四件套」而不是「提示词 + 说明」**：因为本系统与下游脱钩（不 API 直连、不回传成片），**「客户照做即合规」**是唯一可控的合规路径。要素齐全才能让客户不需要理解法规也能正确落地。

### 1.2 三条不可变原则

| 原则 | 内容 | 法规/需求依据 |
| --- | --- | --- |
| **① 脱钩** | 本系统**不**对接任何下游平台 API、**不**代客户调用生成、**不**托管下游密钥、**不**接触成片；交付物为**产物 + 说明**，不做系统集成 | SYS-018 |
| **② 无去标识** | 系统内**不得存在**任何「去除 / 关闭 / 隐藏 AI 标识」的功能、开关或接口——包括管理控制台不得提供一键剥离标识 | 《标识办法》§10 |
| **③ 文本侧标识自控** | 本系统对**自己生成的文本**负有标识义务，必须全量落地（显式 + 隐式 + 界面提示），不得以「反正下游会标」为由省略 | 《标识办法》§4·§5；《深度合成规定》§16~§18 |

### 1.3 责任边界（谁对视频标识负责）

```
① 本系统（生成合成服务提供者 · 文本侧）
   │  义务：文本显式标识 + 隐式元数据 + 界面显著提示 + 协议告知 + 素材与声明传递
   │  交付：四件套
   ↓
② 客户（内容使用者 / 制作方）
   │  义务：按声明与协议落地标识（服务协议已明确其标识义务与使用责任 —— §8、§9）
   ↓
③ 下游 AI 视频工具（生成合成服务提供者 · 视频侧）
   │  义务：对视频本身的标识义务由其自身合规义务承担（本系统不代其履职）
   ↓
④ 内容传播平台（内容传播服务提供者）
   └  义务：核验元数据 → 在内容周边添加显著提示标识（§6，最后一环兜底）
```

**写进备案材料的定位口径**：本系统**不是**视频的生成合成服务提供者；视频侧标识第一责任主体为下游 AI 视频工具。本系统义务收敛为**文本侧标识 + 协议告知 + 提示与素材传递**。此口径可避免自我加码，也经得起审查询问。

> **风险知情**：选择脱钩即意味着本系统**无法验证**客户最终是否落地标识。缓释机制见 §7.3（自检）+ §6.6（照做即合规）+ §1.3 ④（平台兜底）。该风险已在 SYS-Q4 决策文档中留痕。

### 1.4 交付包目录结构（标准形态）

```
delivery-<pack_id>/
├── manifest.json                 交付清单（四件套索引 + 校验和）
├── shot_prompt_pack.json         ① 提示词集（通用规范，基准）
├── exports/
│   ├── shot_prompt_pack.csv      分镜表（表格软件可直接打开）
│   ├── shot_prompt_pack.xlsx     分镜表（含标识行与文档属性）
│   ├── shot_prompt_pack.md       可读文本稿（首尾含显式标识）
│   └── <model>/                  ② 各模型适配格式（目录名 = 模型代号）
│       └── minimax_h3.txt        例：MiniMax H3 适配文本
├── assets/
│   ├── overlay_intro_16x9.png    ③ 标识素材：片头卡（横版）
│   ├── overlay_intro_9x16.png    ③ 标识素材：片头卡（竖版）
│   ├── overlay_corner_16x9.png   ③ 标识素材：角标（横版，含透明度）
│   ├── overlay_corner_9x16.png   ③ 标识素材：角标（竖版）
│   └── AST-002_overlay_spec.json         素材规格与使用说明（含 GB 指标与建议值）
├── refs/                         角色/风格参考图（如有）
│   └── CHR-01.png
└── COMPLIANCE.md                 ④ 交付合规声明（另附 .pdf 可选）
```

**必须**：`manifest.json` 存在且列出全部文件；`shot_prompt_pack.json` 与 `COMPLIANCE.md` 不可缺失。
**必须**：交付包为**离线可用**（解压即用，不依赖本系统在线服务）。

| 术语 | 说明 |
| --- | --- |

## 3 提示词包结构规范

> 配套工程文件：[`03-工程代码/delivery/schemas/CFG-006_shot_prompt_pack.v1.schema.json`](../../03-工程代码/delivery/schemas/CFG-006_shot_prompt_pack.v1.schema.json)

### 3.1 整体结构

提示词包为**单个 JSON 对象**，顶层五段：

```
{
  "schema_version": "1.0.0",   // 必须：结构版本，与 Schema 对应
  "meta":          { ... },     // 必须：包元信息、生成溯源、合规状态
  "style_bible":   { ... },     // 必须：全局风格锚点（仅一份）
  "characters":    [ ... ],     // 应当：角色锚点列表（无角色可空数组）
  "shots":         [ ... ],     // 必须：镜头列表（≥1）
  "aigc_meta":     { ... }      // 必须：AIGC 元数据块（仅一份，见第 4 章）
}
```

**为什么这样分层**：把「不变的」与「变的」分开——`style_bible` / `characters` 是跨镜头复用的**一致性约束**，`shots` 是逐镜头参数。AI 视频最常见的失败是**跨镜头角色/风格漂移**，因此把一致性锚点提升为顶层独立结构，而不是在每个镜头里重复描述。

### 3.2 包元信息 `meta`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `pack_id` | string | **必须** | 包唯一编号，编码规则见 §4.2（与 `ProduceID` 同值） |
| `title` | string | **必须** | 作品/项目标题 |
| `created_at` | string | **必须** | ISO 8601 带时区，如 `2026-10-12T16:30:00+08:00` |
| `generator.system` | string | **必须** | 生成系统名称（固定值） |
| `generator.version` | string | **必须** | 系统版本 |
| `generator.provider` | string | **必须** | 服务提供者名称：`{{PROVIDER_NAME}}` |
| `generator.provider_code` | string | **必须** | 提供者编码（占位 `{{PROVIDER_CODE}}`，备案后回填，见 §12） |
| `generation_trace.session_id` | string | **必须** | 会话 ID（对应 SW-D01） |
| `generation_trace.task_id` | string | **必须** | 任务 ID |
| `generation_trace.stage_chain` | string[] | **必须** | 阶段链路，枚举见下表 |
| `generation_trace.templates` | object[] | **必须** | 使用的提示模板 `{id, version}`（对应 SW-109 模板热更追溯） |
| `generation_trace.model` | object | **必须** | `{name, backend, revision}`（对应 SW-108 模型后端可替换追溯） |
| `compliance.safety_check` | object | **必须** | `{input, output, checked_at}`，取值 `passed` / `blocked` |
| `compliance.copyright_check` | object | **必须** | `{status, note}`，对应 SW-015 |
| `compliance.marking_check` | object | **必须** | `{explicit, implicit}`，取值 `present` / `missing` |
| `compliance.statement_id` | string | **必须** | 合规声明编号，与 `COMPLIANCE.md` 一致 |
| `aspect_ratio_default` | string | **应当** | 默认画幅，如 `16:9` / `9:16`；镜头可覆盖 |
| `total_duration_ms` | integer | **应当** | 全片总时长（各镜头 `duration_ms` 之和） |
| `notes` | string | 可 | 备注 |

**`stage_chain` 枚举**（与 SYS-Q11 确认的 5 段链路一致）：

`synopsis`（梗概）→ `script`（剧本）→ `storyboard`（分镜脚本）→ `shot_prompt`（分镜提示词）

> 交付提示词集时可只填 `["shot_prompt"]` 或含上游阶段；**必须**与实际生成链路一致，因为它是溯源凭据。

### 3.3 全局风格锚点 `style_bible`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `style_id` | string | **必须** | 风格唯一标识，如 `STYLE-ANIME-CN-A`；各镜头 `style_ref` 引用此值 |
| `style_prompt_zh` | string | **必须** | 风格串（中文），描述画风/质感/时代/色调 |
| `style_prompt_en` | string | **应当** | 风格串（英文）——多数下游模型对英文更敏感 |
| `color_palette` | string[] | 可 | 主色板（HEX），用于后续滤镜/调色对齐 |
| `lighting_default` | string | 应当 | 默认光照，取值见词表 |
| `film_grain` | string | 可 | 颗粒感：`none` / `light` / `medium` / `heavy` |
| `negative_global` | string[] | **必须** | 全局负向词，会被合并进每个镜头的 `negative_prompt` |

**填写规则（应当）**：`style_prompt_zh` / `style_prompt_en` 应控制在 **30–80 字**；过短无约束力，过长会被模型截断或稀释主体描述。风格串**全片唯一**，不得逐镜头改风格——需要风格差异时用 `lighting` 与 `shot_size` 表达。

### 3.4 角色锚点 `characters[]`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `character_id` | string | **必须** | 角色标识，如 `CHR-01`；镜头用 `character_refs` 引用 |
| `name` | string | **必须** | 角色名 |
| `appearance_lock_zh` | string | **必须** | 外观锁定串（中文）：发型/发色/瞳色/服装/体态/年龄感 |
| `appearance_lock_en` | string | 应当 | 同上英文 |
| `ref_image` | string | 可 | 参考图相对路径（如 `refs/CHR-01.png`）——有参考图机制的下游模型优先使用 |
| `forbidden` | string[] | 应当 | 该角色**禁止变化**的要素（如"服装颜色""发型"），生成后人工核对用 |

> **一致性关键**：角色外观**只在此处定义一次**，镜头内**不得**重复描述角色外观细节，只引用 `character_refs`。这是避免「同一角色在不同镜头长得不一样」的结构性手段。

### 3.5 镜头 `shots[]`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `shot_id` | string | **必须** | 镜头唯一编号，建议 `S<场景号>-SH<三位镜号>`，如 `S01-SH003` |
| `scene_no` | integer | **必须** | 场景号（≥1） |
| `shot_no` | integer | **必须** | 镜号（≥1） |
| `shot_size` | enum | **必须** | 景别，取值见 §3.6.1 |
| `camera.move` | enum | **必须** | 运镜方式，取值见 §3.6.2 |
| `camera.speed` | enum | 应当 | 运镜速度：`slow` / `normal` / `fast` |
| `camera.angle` | enum | 应当 | 机位角度：`eye_level` / `high_angle` / `low_angle` / `overhead` / `dutch` |
| `duration_ms` | integer | **必须** | 镜头时长（毫秒），受下游模型上限约束（见 §5.3） |
| `aspect_ratio` | string | 应当 | 缺省取 `meta.aspect_ratio_default` |
| `resolution` | string | 可 | 如 `720p` / `1080p`；仅作目标值提示 |
| `prompt_zh` | string | **必须** | 中文画面提示词 |
| `prompt_en` | string | **应当** | 英文画面提示词 |
| `negative_prompt` | string[] | 应当 | 镜头级负向词（与 `style_bible.negative_global` 合并使用） |
| `lighting` | string | 应当 | 光照，取值见词表；缺省取 `style_bible.lighting_default` |
| `style_ref` | string | **必须** | 引用 `style_bible.style_id` |
| `character_refs` | string[] | **必须** | 引用 `characters[].character_id`（无角色场景为空数组） |
| `ref_image` | string 或 null | 可 | 该镜头首帧参考图（图生视频用） |
| `dialogue` | string | 可 | 该镜头对白/旁白（供剪辑与配音使用） |
| `sfx` | string | 可 | 音效/环境音提示 |
| `transition_in` | enum | 可 | 入点转场：`cut` / `fade_in` / `dissolve` / `wipe` |
| `notes` | string | 可 | 备注（如"需人工核对角色一致性"） |

### 3.6 字段取值规则

#### 3.6.1 景别 `shot_size`

| 枚举值 | 中文 | 画面范围 |
| --- | --- | --- |
| `extreme_wide` | 大远景 | 环境为主，人物极小 |
| `wide` | 远景 | 人物全身 + 大量环境 |
| `full` | 全景 | 人物全身 |
| `medium` | 中景 | 人物半身（腰以上） |
| `close_up` | 近景 / 特写 | 面部或关键物件 |
| `extreme_close_up` | 大特写 | 局部细节（眼神、手部） |

`lighting`：`soft_key_light` / `hard_key_light` / `rim_light` / `backlight` / `side_light` / `top_light` / `under_light` / `practical_light` / `volumetric_light` / `golden_hour` / `blue_hour` / `overcast` / `neon_night` / `candlelight` / `moonlight`

#### 3.6.4 中英双写规则（应当）

| 规则 | 说明 |
| --- | --- |
| 语义对齐 | `prompt_en` 不是逐字翻译，而是**面向模型优化的英文表达**；两者语义必须一致 |
| 要素顺序 | 统一按「主体 → 动作 → 环境 → 光线 → 镜头语言 → 风格」顺序书写，降低模型理解成本 |
| 禁止项 | `prompt_zh` / `prompt_en` 内**不得**写模型参数指令（如 `--ar 16:9`），参数一律走结构化字段 |
| 长度 | 单镜头建议 40–120 字（中文）/ 30–90 词（英文）；超长拆镜 |

### 3.7 校验与常见错误

交付前**必须**通过 Schema 校验（`jsonschema` 校验 `shot_prompt_pack.json`）。常见错误与处置：

| 错误 | 处置 |
| --- | --- |
| `style_ref` 未命中 `style_bible.style_id` | **阻断**（一致性锚点断裂） |
| `character_refs` 引用不存在的 `character_id` | **阻断** |
| `total_duration_ms` ≠ 各镜头时长之和 | **阻断**（数据自相矛盾，审查易被质疑） |
| 单镜头时长超下游模型上限 | 提示并按 §5.5 拆分或截断 |
| `aigc_meta` 缺失或字段缺失 | **阻断**（违反 §5 隐式标识义务） |
| 出现重复的元数据块 | **阻断**（GB 45438 要求仅保留一份） |
| `prompt_zh` 含参数指令 | 提示并可自动剥离 |

## 4 AIGC 元数据块规范

> 对应需求：SW-013（隐式生成标识）、SW-014（元数据传递）；法规依据：《标识办法》§5、GB 45438—2025 §6.1 与附录 E

### 4.1 字段定义

元数据块**必须**为**单个 JSON 对象**，顶层键为 `AIGC`，取值规则见下表：

```json
{
  "AIGC": {
    "Label": "1",
    "ContentProducer": "{{PROVIDER_NAME}}/{{PROVIDER_CODE}}",
    "ProduceID": "FR-PK-20261012-7K2M9XQ4",
    "ReservedCode1": "",
    "ContentPropagator": "{{PROVIDER_NAME}}/{{PROVIDER_CODE}}",
    "PropagateID": "FR-PK-20261012-7K2M9XQ4",
    "ReservedCode2": ""
  }
}
```

| 字段 | 取值规则 | 本项目填写 |
| --- | --- | --- |
| `Label` | 生成合成标签 | 固定 `"1"`（表示人工智能生成合成内容） |
| `ContentProducer` | 内容制作方（生成合成服务提供者）标识：`<名称>/<提供者编码>` | `{{PROVIDER_NAME}}/{{PROVIDER_CODE}}` |
| `ProduceID` | 内容编号，**全局唯一**，编码规则见 §4.2 | 与 `meta.pack_id` 同值 |
| `ReservedCode1` | 预留字段 | 留空字符串 `""` |
| `ContentPropagator` | 内容传播方标识，格式同 `ContentProducer` | **首次写入时与 `ContentProducer` 完全同值**（本系统即传播起点；<br>后续被他人传播时，由传播方按标准自行追加/更新） |
| `PropagateID` | 传播编号 | **首次写入时与 `ProduceID` 同值** |
| `ReservedCode2` | 预留字段 | 留空字符串 `""` |

> ⚠️ **字段语义与取值以 GB 45438—2025 附录 E 正式文本为准**。本规范采用其规范格式；`ContentProducer` 的具体组成（是否需要附带统一社会信用代码、编码由谁分配）**须在备案前核对标准原文与主管部门口径后回填**（§12 待明确事项 T-02）。**回填前不得用于正式交付**，用占位符 `{{PROVIDER_CODE}}` 仅作结构演示。

### 4.2 内容编号（`ProduceID`）编码规则

编号**必须**满足：全局唯一、可反查生成记录、无歧义字符、长度可控。

```
<企业码>-<产物类型码>-<YYYYMMDD>-<8位任务短码>

示例：FR-PK-20261012-7K2M9XQ4
      │  │   │           └ 任务短码：任务 ID 经 Crockford Base32 编码后取前 8 位
      │  │   └ 生成日期（UTC+8）
      │  └ 产物类型码（见下表）
      └ 企业码（{{PROVIDER_NAME}}，FR）
```

| 产物类型码 | 含义 | 产物类型码 | 含义 |
| --- | --- | --- | --- |
| `GR` | 故事梗概 | `SB` | 分镜脚本 |
| `SC` | 剧本 | `PK` | 分镜提示词包 |
| `EX` | 导出包 | | |

**规则**：

| 规则 | 说明 |
| --- | --- |
| **必须** | 字符集限定为 `A-Z0-9-`；大小写按 Crockford Base32 规则（排除易混字母 `I` `L` `O` `U`） |
| **必须** | 同一 `pack_id` 在同一交付包内**只出现一次** |
| **必须** | 编号写入生成记录（`SW-D02` / `SW-D03`），支持「编号 → 生成记录」反查 |
| 应当 | 重新生成（改稿）不沿用旧编号，生成新编号并保留旧编号的历史记录 |
| 应当 | 编号长度固定为 24 字符（企业码 2 + 分隔 1 + 类型 2 + 分隔 1 + 日期 8 + 分隔 1 + 短码 8 ≈ 23–24），便于校验 |

### 4.3 写入位置与唯一性

| 载体 | 写入方式 | 唯一性要求 |
| --- | --- | --- |
| `shot_prompt_pack.json` | 顶层 `aigc_meta` 键 | **仅一份** |
| 导出 JSON | 顶层 `AIGC` 键（与 pack 内不重复：导出文件为独立文件时写一份） | **仅一份** |
| 导出 XLSX | 文档属性（自定义属性）+ 首行标识行的元数据列 | **仅一处**（以文档属性为准） |
| 导出 MD / TXT | 文件末尾「元数据块」段落（与首部显式标识区分） | **仅一份** |
| 导出 CSV | 表尾注释行（`#AIGC:` 前缀） | **仅一份** |
| 视频侧（由客户落地） | 提示客户写入成片容器元数据 | 由下游工具/客户负责 |

> **GB 45438 明确要求「文件中仅保留一份」隐式标识**。实现时须做**去重校验**：同一文件内出现 ≥2 个 `AIGC` 元数据块即**阻断交付**。

### 4.4 防删改与校验

| 措施 | 说明 | 对应需求 |
| --- | --- | --- |
| 解析校验 | 交付前校验元数据块可被 JSON 解析、字段齐全、`Label` 合法 | SW-013 |
| 一致性校验 | `ProduceID` 与 `meta.pack_id`、`statement_id` 三者互相关联且可对上 | SW-016 |
| 变更留痕 | 任何对元数据块的改写（如回填提供者编码）都记录变更时间与操作者 | SW-016 |
| 无去标识功能 | 系统**不得**提供移除/隐藏/伪造元数据的功能；管理控制台同样禁止 | 《标识办法》§10 |
| 交付声明告知 | 在 `COMPLIANCE.md` 中告知：删除、篡改、隐匿标识属法规禁止行为 | §7.2 |

## 5 多模型适配规范

> 对应需求：SW-007（提示词生成 + 按优先级适配）、SW-025（多模型适配）；决策依据：SYS-Q4（通用规范为基准）、SYS-Q17（优先级）

### 5.1 适配原则：基准 + 单向投影

```
        ┌──────────────────────────────┐
        │  通用规范提示词包（基准）      │  ← 唯一真值来源（shot_prompt_pack.json）
        │  schema 固定、字段完整、可校验  │
        └───────────────┬──────────────┘
                        │  单向投影（只读，不回写）
      ┌────────┬────────┼────────┬────────┐
      ▼        ▼        ▼        ▼        ▼
  MiniMax H3  Seedance  即梦    可灵    其余（P3）
   （P0）      （P0）   （P1）  （P2）   通用 + 说明
```

| 原则 | 说明 |
| --- | --- |
| **基准唯一** | 所有适配格式都从同一个通用规范包生成；**禁止**直接编辑适配输出（改了会被下次生成覆盖） |
| **单向投影** | 适配是「读基准 → 写适配格式」，不修改基准 |
| **降级可用** | 任何模型适配缺失时，**必须**仍能输出通用规范 + 使用说明（不得因适配缺失而无法交付） |
| **配置化** | 新增模型 = 新增/修改 `CFG-001_model_adapters.yaml` 配置，**不改代码**（SW-025 验收标准、SW-108 精神） |
| **不与下游耦合** | 适配只做**格式与写法转换**，不调用下游 API、不托管下游密钥（SYS-018） |

### 5.2 优先级与范围

| 优先级 | 模型 | 说明 | 本期要求 |
| --- | --- | --- | --- |
| **P0** | **MiniMax H3**（海螺） | 客户第一优先使用 | 适配可用，含导入格式与运镜写法 |
| **P0** | **Seedance** | 客户次优先 | 同上 |
| **P1** | 即梦（Dreamina / 系出同源） | 客户第三优先 | 完成适配 |
| **P2** | 可灵（Kling） | 客户第四优先 | 完成适配 |
| **P3** | Vidu / 通义万相 / Pika / Runway / 其他 | 长尾 | 通用规范 + 使用说明，按需增配 |

> **提示**：优先级由 SYS-Q17 确定，属于**配置数据**而非硬编码。若客户实际使用结构变化，改配置即可调整优先级，无需改代码。

### 5.3 适配维度（通用）

每个模型适配条目**应当**覆盖以下 10 个维度，形成完整映射：

| # | 维度 | 说明 |
| --- | --- | --- |
| 1 | 提示词语言倾向 | 中文优先 / 英文优先 / 双语皆可 → 决定 `prompt_zh` / `prompt_en` 取哪个为主 |
| 2 | 提示词组织顺序 | 按模型偏好排列「主体/动作/环境/光线/镜头/风格」 |
| 3 | 运镜表达方式 | 自然语言描述 / 专用指令语法（如方括号指令）/ 不支持 |
| 4 | 负向提示词 | 支持独立字段 / 不支持（需转写为正向约束） |
| 5 | 参考图机制 | 支持首帧 / 支持角色参考 / 支持风格参考 / 不支持 |
| 6 | 单镜头时长上限 | 决定 `duration_ms` 是否需要拆分（见 §5.5） |
| 7 | 画幅与分辨率 | 支持的比例与档位；不在支持列表时提示取最近档 |
| 8 | 单次输入长度上限 | 超出时需精简（§5.5） |
| 9 | 导入格式 | 纯文本 / JSON / CSV / 表格粘贴 / 逐条录入 |
| 10 | 特殊约束 | 如禁止出现真实人名、需避免的敏感词等平台规则 |

### 5.5 降级与拆分策略

| 场景 | 处置 |
| --- | --- |
| 未知模型或无适配配置 | 输出通用规范 + 使用说明（**必须**，不得阻断交付） |

| 提示词长度 > 模型输入上限 | 按优先级裁剪：删除修饰性形容词 → 精简环境描述 → 缩短风格串（**禁止**删除主体动作与镜头语言） |
| 适配配置未核对（`verify_status: pending`） | 输出时附「适配参数待核对」提示，**不得**标记为已验证 |
| 平台不支持负向提示词 | 转写为正向约束句；同时在交付说明中标注该转换 |

### 5.6 新增模型接入流程（配置级）

```
① 在 CFG-001_model_adapters.yaml 新增一条 model 条目（代号、显示名、优先级、limits、mapping）
② 填写 10 个适配维度；无法确认的项置 verify_status: pending
③ 用 examples/CFG-004_demo_pack.json 跑一次适配，人工核对输出可读性与完整性
④ 核对官方文档，回填参数上限与指令语法，置 verify_status: verified 并记录 verify_source
⑤ 登记到《适配覆盖表》（§12 T-03 附），交付测试
```

**必须**：新增模型**不得**引入代码改动（否则违反 SW-025 验收标准）；**不得**引入对下游 API 的调用（违反 SYS-018）。

### 5.7 适配输出格式规范

| 要求 | 说明 |
| --- | --- |
| 分隔 | 多镜头之间用 `━━━ 镜头 S01-SH001 ━━━` 之类**固定分隔行**，便于人工逐条复制 |
| 顺序 | 严格按 `scene_no` → `shot_no` 升序 |
| 完整性 | 每个镜头**必须**至少含：图片描述文本 + 时长 + 画幅（缺失时长/画幅时用 `meta` 默认值补齐并标注） |
| 不含元数据 | 模型适配文本**不含** AIGC 元数据块（元数据写在 pack 与导出文件中，避免污染提示词） |
| 文件头 | 每个适配文件头部含：`pack_id`、生成时间、模型代号、镜数、总时长 |
| 编码 | UTF-8 无 BOM |

## 6 标识素材规范

> 对应需求：SW-014（标识素材包）；法规依据：《标识办法》§4(四)、GB 45438—2025 §5.4

### 6.1 法规硬指标（GB 45438—2025 §5.4）

视频显式标识**必须**同时满足：

| # | 硬指标 | 要求 |
| --- | --- | --- |
| 1 | 文字内容 | 含「**人工智能**」或「**AI**」，且含「**生成**」和/或「**合成**」 |
| 2 | 位置（时间） | 位于**起始画面**；**可**在末尾或中间适当位置添加 |
| 3 | 位置（空间） | 位于画面**边或角** |
| 4 | 字号 | **文字高度 ≥ 画面最短边 5%** |
| 5 | 时长 | 正常播放速度下**持续 ≥ 2 秒** |

### 6.2 本项目规格（建议值，含余量）

| 参数 | 法规下限 | **本项目取值** | 取此值的原因 |
| --- | --- | --- | --- |
| 文字高度 | ≥ 最短边 5% | **≥ 最短边 6%** | 预留缩放/转码/裁切损耗余量 |
| 持续时长 | ≥ 2s | **3s** | 视频平台转码可能裁头尾，留 1s 余量 |
| 位置 | 边或角 | **横版：右下角；竖版：底部居中偏下** | 避开平台 UI 遮挡区（进度条、按钮） |
| 安全边距 | 无规定 | **≥ 最短边 4%** | 防裁切 |
| 对比度 | 无规定 | 文字与背景对比度 **≥ 4.5:1**，加深色半透明底衬 | 保证可辨识（低对比度是常见被驳回原因） |

**尺寸换算表**（字高按本项目 6% 计）

| 画面规格 | 最短边 | 法规下限 (5%) | **本项目字高 (6%)** |
| --- | --- | --- | --- |
| 1920×1080（横版 1080p） | 1080 | 54 px | **65 px** |
| 1080×1920（竖版 1080p） | 1080 | 54 px | **65 px** |
| 1280×720（横版 720p） | 720 | 36 px | **43 px** |
| 720×1280（竖版 720p） | 720 | 36 px | **43 px** |
| 3840×2160（横版 4K） | 2160 | 108 px | **130 px** |

### 6.3 素材清单

每次交付**必须**包含以下素材（横竖两版，共 4 个 PNG）：

| 文件 | 类型 | 用途 | 展示要求 |
| --- | --- | --- | --- |
| `overlay_intro_16x9.png` | 片头卡（横版） | 放在视频起始画面的全屏/大幅提示卡 | 起始展示 **3s** |
| `overlay_intro_9x16.png` | 片头卡（竖版） | 同上（竖版视频） | 起始展示 **3s** |
| `overlay_corner_16x9.png` | 角标（横版，含透明背景） | 直接叠加到画面右下角 | 起始 ≥3s，**建议**全片常驻 |
| `overlay_corner_9x16.png` | 角标（竖版，含透明背景） | 同上（竖版） | 同上 |

> **推荐做法**：片头卡 + 角标**同时使用**（片头卡满足"起始画面显著提示"，角标满足"边或角持续提示"），合规最稳。
> **素材提供多种样式**：本期提供 ≥2 套样式候选（字体/配色/底衬不同），供 SYS-Q15 最终定稿选择，见 `03-工程代码/delivery/assets/`。

### 6.4 文案规范

| 项 | 文案 |
| --- | --- |
| **本期定稿（SYS-Q15）** | `本文件由AI生成，已经过合规验证` |
| 建议替换（§7.1.1 风险提示） | `本文件由人工智能（AI）生成，请注意甄别` |

**合规要素核对**（定稿文案）：

| 硬指标 | 核对结果 |
| --- | --- |
| 含「AI」 | ✅ 是 |
| 含「生成」 | ✅ 是 |
| 长度可控 | ✅ 14 字，单行可容纳 |
| 可辨识 | ✅ 需配合底衬保证对比度 |

> ⚠️ **风险提示（重申）**：标识的立法目的是**提示公众甄别**，不是给内容做真实性背书。「已经过合规验证」后六字若日后内容被认定违规，可能被作为「已自认完成验证」的不利证据。因此：
> - 文案已做成**集中配置项**，替换不需改代码；
> - 若保留原文案，**应当**在用户服务协议与交付声明中写明：「本标识仅声明内容由 AI 生成，不构成对内容真实性、准确性或合法性的承诺」；
> - 素材会**同时提供两套文案版本**，便于随时切换。

### 6.5 字体与版权注意事项

| 注意点 | 说明 |
| --- | --- |
| **必须** | 正式交付素材使用的字体须具备**商用授权**。推荐免费商用中文字体：思源黑体（SIL OFL）、阿里巴巴普惠体、HarmonyOS Sans |
| **必须** | 若素材中含图形元素（图标/图案），须为自绘或已获授权，**不得**使用第三方有版权图库素材 |
| 禁止 | 不得使用微软雅黑、方正系列等**需授权**字体投入正式交付 |
| 说明 | `assets/` 中的候选样式**若使用系统字体，仅作视觉预览**，正式素材须替换为授权字体后重新生成 |

> 这一点在备案与商业使用中都会涉及——**字体侵权**是短视频/漫剧领域被索赔的高频风险点，务必在素材生成管线中固定为「授权字体白名单」。

### 6.6 使用指引（客户「照做即合规」）

交付声明中**必须**包含以下图文说明要点：

| 步骤 | 说明 |
| --- | --- |
| 1 | 把 `overlay_intro_*` 放在成片**起始画面**，展示**满 3 秒**再进入正片 |
| 2 | 把 `overlay_corner_*` 叠加到画面**边角**（推荐右下角），全片保留或至少在起始 3 秒出现 |
| 3 | **不要**缩小、裁切、模糊、遮挡标识文字；不要改变文字颜色至不可辨识 |
| 4 | 不要把标识放在会被平台 UI（进度条/按钮/标题条）遮挡的位置 |
| 5 | 成片容器元数据**建议**写入 §4 的 AIGC 元数据块（如工具支持） |
| 6 | 发布时**按平台要求**勾选/声明「AI 生成」相关选项 |
| 7 | **不得**删除、篡改、隐匿标识（法规禁止，见 §7.2） |

## 8 导出与文件格式规范

> 对应需求：SW-022（内容导出含导出文件显式标识）、SW-I04、SW-020（导出鉴权）；法规依据：《标识办法》§4 末段

### 8.1 支持格式与用途

| 格式 | 用途 | 对应文件 |
| --- | --- | --- |
| **JSON** | 机器可读的完整提示词包（四件套之一） | `shot_prompt_pack.json` |
| **CSV** | 分镜表，表格软件直接打开，便于批量复制 | `exports/shot_prompt_pack.csv` |
| **XLSX** | 分镜表（含标识行与文档属性），商务协作常用 | `exports/shot_prompt_pack.xlsx` |
| **Markdown** | 可读文本稿，便于阅读与二次编辑 | `exports/shot_prompt_pack.md` |
| **TXT** | 各模型适配格式（纯文本，便于逐条投喂） | `exports/<model>/*.txt` |
| **PDF**（可） | 归档与打印版 | `exports/shot_prompt_pack.pdf` |

### 8.2 各格式的标识注入方式（差异化，必须）

> 依据《标识办法》§4 末段：「提供下载、复制、导出等功能时，应当确保文件中含有满足要求的显式标识。」

| 格式 | 显式标识注入位置 | 隐式标识注入位置 |
| --- | --- | --- |
| **TXT** | **首行**（`【AI生成内容】…`）+ **末行**重复标注 | 文件末尾元数据块段落 |
| **MD** | **文首引用块**（`> 【AI生成内容】…`）+ **文末**标注 | 文末 `## 元数据` 小节 |
| **JSON** | 顶层 `explicit_mark` 字段（文案 + 位置说明） | 顶层 `AIGC` 键 |
| **CSV** | **首行注释行**（`#AI生成内容…`）+ **末行**重复 | 末行 `#AIGC:` 前缀的 JSON |
| **XLSX** | **首行合并单元格标识行**（醒目填充色）+ **工作簿自定义属性**（标题/备注） | 工作簿自定义属性（`AIGC_*`） |
| **PDF** | **页眉或页脚**固定标识（每页可见） | 文档属性（Key/Value） |

**必须**：任一格式的标识注入失败 → **阻断导出并告警**，不得出现「导出成功但无标识」。
**必须**：标识文案与实际配置一致（集中配置项，不得硬编码在多个位置）。
**应当**：导出文件**不**包含用户隐私信息与内部调试字段。

### 8.3 文件命名规范

```
<pack_id>_<内容类型>_v<版本>.<扩展名>

示例：
FR-PK-20261012-7K2M9XQ4_分镜提示词集_v1.0.json
FR-PK-20261012-7K2M9XQ4_分镜表_v1.0.xlsx
FR-PK-20261012-7K2M9XQ4_适配_MiniMaxH3_v1.0.txt
```

| 规则 | 说明 |
| --- | --- |
| **必须** | 文件名以 `pack_id` 开头，保证与元数据可互相检索 |
| **必须** | 不含空格与特殊字符（反斜杠、正斜杠、冒号、星号、问号、英文双引号、尖括号、竖线） |
| 应当 | 内容类型用中文（客户可读） |
| 应当 | 同一包多次导出时版本号递增，不覆盖旧文件 |

### 8.4 导出鉴权与留痕

| 项 | 要求 | 依据 |
| --- | --- | --- |
| 鉴权 | 导出前**必须**校验真实身份认证状态，未认证**拒绝**导出 | SYS-003、SW-020 |
| 留痕 | 每次导出记录：时间、操作者、`pack_id`、格式、文件校验和 | SW-016 |
| 留存 | 导出留痕 **≥ 6 个月** | 《标识办法》§9 |
