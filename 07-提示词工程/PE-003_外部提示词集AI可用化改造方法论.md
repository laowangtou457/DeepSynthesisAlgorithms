# 外部提示词集「AI 可用化」改造方法论

> **适用对象**：任何人拿到一份**非本产线生成**的提示词集（AI 生成的、编剧写的、外包交付的、从别处抄来的），需要把它改造成**能稳定喂进视频/图像生成模型、并拍出可用镜头**的规范提示词集。
> **覆盖模型**：MiniMax H3 · Seedance（字节即梦）· 可灵 Kling · 即梦 Dreamina · Seedream（图像）· 通用兜底写法。各模型规范**分章独立列出**，互不混写。
> **适用版本**：写作时点的各家公开规范快照（见附 4 版本表）。模型规范会迭代，**迁移前请按附 4 的"复核清单"重新核对官方文档**。
> **本文用途**：可复用、可交付、可审计的改造 SOP。

## 0. 一句话总纲与使用方式

**总纲：AI 可用性不是文笔问题，是可验证性问题。**

一份提示词集"不可用"，绝大多数时候不是因为写得不够美，而是因为：

1. 违反了目标模型**写作规范的某几条硬规则**；
2. 缺少让画面"有节奏"的**镜头语言信息**；
3. **用错了模型的语法格式**（把 A 模型的提示词直接喂给 B 模型——这是本次扩展要重点解决的问题）。

改造的正确姿势：

```
选模型 → 建尺子 → 改稿 → 用尺子证明改对了 → 固化成流程
(§2)    (§1)     (§3)      (§6 清单)           (§4 SOP)
```

**使用方式**：先看 §2 选定目标模型，再跳对应分论（§8–§12）取该模型的**规范三件套**（结构公式 / 硬约束 / 词表），然后按 §4 六步 SOP 执行。**不要先改文字。**

## 1. 核心判据：三把尺子

外部提示词集最常见的幻觉是：**它读起来很像分镜脚本，于是就以为它可以直接生成。**

事实是：**分镜脚本的详细度 ≠ 提示词的可用度。** 一份结构化、术语规范、看起来非常专业的分镜稿，在"镜头语言"上可能比可用稿差一个数量级，而且**很可能用的是另一个模型的语法**。

必须区分**三件事**：

| 层次 | 量什么 | 判定依据 | 不通过的后果 |
|---|---|---|---|
| **① 规范合规** | 结构、字段顺序、时间码、镜号、参考标签、对白语法、字数上限 | 目标模型的官方写作规范 | 模型**直接报错、截断、语法不生效或输出错乱**——不是"效果差"，是"跑不动" |
| **② 镜头语言** | 景别/运镜/角度/光学/构图/轴线/光线/画面结果 八维覆盖率 | 跨模型通用的镜头语言审计 | 模型**能跑，但拍出平铺直叙的画面**：不知道看哪里、谁压过谁、镜与镜什么关系 |
| **③ 语义合规** | 剧情功能是否被悄悄改写、已删改的敏感表述是否回退 | 人工对照（可半自动） | 过了前两关，但**内容出了合规问题**，返工代价最大 |

> **关键结论（本项目实测）**：一份提示词可以 **100% 通过规范合规，同时运镜/角度/光学/构图/轴线/光线全部为 0%**。
> 参考数据：本项目被改造的原始稿 **17/17 个单元全部通过规范校验**（"合规"），但 **0/17 个单元通过镜头语言质量门**。见附 1。

**②③两层与模型无关，可以直接跨模型复用；①层必须按目标模型重建。** 这就是本文档"通用部分 + 分模型章节"分体的原因。

## 2. 模型能力矩阵与选型

**先选模型，再写提示词。** 选错的代价是全套重写。

| 维度 | MiniMax H3 | Seedance 2.5 | 可灵 Kling | 即梦 Dreamina | Seedream 4.x |
|---|---|---|---|---|---|
| **类型** | 视频生成 | 视频生成 | 视频生成 | 视频生成 | **图像生成** |
| **官方结构** | 三字段 / **六段式** | 资产映射 + 一句话简报 + 时间轴 + 全局约束 | **五要素公式** | 基础结构 + 词典 | 自然语言 + 短词美学 |
| **多镜头** | ✅ 单提示词内 `[Shot N]` | ✅ 时间范围分段 | ▶ 独立多镜头模式 | ✅ `镜头1 + 动作1 + 镜头2 + 动作2` | — |
| **时间控制** | 绝对时间码 `At MM:SS.mmm,` | **整秒连续区间** `0–3s` | 无原生时间戳 | 时序标签 | — |
| **参考语法** | `<Subject N>` / `<Picture N>` / `<Video N>` / `<Audio N>` | **`@Image N` / `@Video N` / `@Audio N`** | 上传槽位 + 六轴参数 | 上传槽位 | 多图参考（图1/图2…） |
| **对白语法** | `<d>[Chinese] …</d>` | 花括号 `{…}` | 自然语言描述 | 自然语言 | — |
| **负面提示词** | ❌ 无字段（须正面措辞） | ✅ 约束块 | ✅ **独立字段** | ✅ **独立输入框** | 部分渠道支持 |
| **字数上限** | **7,000 字符 / 块** | 无明确公开上限（宜短） | **2,500 字符** | 无明确公开上限 | — |
| **单次时长** | **4–15 秒整数** | **4–30 秒** | 3–15 秒（可延长） | 4–12 秒量级 | — |
| **参考上限** | 图≤9 / 视频≤3 / 音频≤3 | 图≤30 / 视频≤10 / 音频≤10（合≤50） | 图≤7（O1 模型） | — | 多图 |
| **强项** | **可校验性最强**（字段与词表最严） | 参考素材编排、长时序 | 运镜执行、原生音频 | 中文原生、易上手 | 文字渲染、4K、图文组 |

**选型建议**：

- 需要**跨镜头严格一致性 + 可程序化校验** → MiniMax H3（规范最严，能上 CI）。
- 需要**多素材参考编排 + 单次长片** → Seedance。
- 需要**运镜精准执行** → 可灵（六轴参数可量化控制）。
- 需要**中文原生快速出片** → 即梦。
- 需要**画面里的文字准确** → Seedream（图像），再由视频模型做图生视频。

## 3. 七层改造框架（模型无关）

七层按**改造顺序** = 按**检查成本**排列。**不要跳层**——L0 没修完就改 L4，等于在错的地基上装修。

```
L0 目标模型确认与格式对齐  ← 新增层，最先做：选错模型 = 全部白工
L1 语言与角色规范          ← 正则可查，批量修
L2 结构合规（单元切分 + 骨架） ← 决定后面所有内容有没有地方放
L3 台词与音画              ← 物理可行性 + 音轨分层
L4 镜头语言八维            ← 内容层，工作量最大，收益也最大
L5 跨单元连续性            ← 轴线 / 光位 / 帧链
L6 语义与合规不回退        ← 防"改形式时把内容改回去"
L7 可验证性                ← 跑尺子 + 留证据
```

> **与单模型版的差异**：新增 **L0**。单模型项目里"目标模型"是已知常量；跨模型场景里，**第一件必须确认的事就是"这套提示词要喂给谁"**，以及"原稿用的是谁的语法"。这是本次扩展最重要的结构变化。

### L0 · 目标模型确认与格式对齐

必须回答两个问题：

1. **这套提示词最终喂给哪个模型？**（决定 §3 全部骨架与词表）
2. **原稿是用哪个模型的语法写的？**（决定是"改造"还是"翻译"）

**常见陷阱**：原稿写了 `[Shot 2] At 00:03.500,`（H3 语法），却要喂给不认时间码的模型；或原稿是"景别 + 主体 + 动作"的通用写法，却直接塞进 H3 的六段式——**都会静默失效**（模型不报错，只是不按你说的做）。

若是多模型投放（同一内容要出多版），**先确定主模型**，其余走 §7 迁移流程。

### L1 · 语言与角色规范（模型无关，可批量修）

| 检查项 | 共性约束 | 模型差异 |
|---|---|---|
| **中文出现位置** | 中文**只允许**出现在"对白/画面可见文字"的位置，框架描述必须用目标模型的工作语言 | H3：`<d>` 内与英文双引号内。Seedance/Kling/即梦：**中文是工作语言**，无此限制（见各分论） |
| **对白标注** | 台词必须被**明确标记为台词**，与描述分离 | H3：`<d>[Chinese] …</d>`。Seedance：花括号 `{…}`。Kling/即梦：自然语言引述 |
| **角色身份** | 说话人/主体必须有**稳定、可复用的指称** | H3：`(S1)` + `<Subject N>`。Seedance：`@Image N` 角色绑定。Kling：主体 + Element 库。即梦：主体描述串逐字复用 |
| **画面可见文字** | 画面里要出现的文字必须**加引号原样写出**，不许翻译 | **四家一致**（H3 用英文双引号；Seedream 明确要求 `"…"`） |
| **台词保真** | 原文**逐字**保留，不改写、不翻译、不增删标点 | **四家一致** |

**自动化改法（H3 场景）**：① 扫 `<d>` 未以 `[语言]` 开头的块 → 补标签；② 扫删除 `<d>` 与英文双引号内容后的残留 CJK → 列出所有位置；③ 扫中文引号 → 替换为英文双引号。

### L2 · 结构合规：生成单元切分与骨架

**这是最容易被"看起来很专业"掩盖的一层。**

#### L2.1 生成单元切分

**一条提示词 = 一个生成单元**，不是"一章"、不是"一场戏"。

判据（**模型无关的推算方法**）：

```
单元镜数上限 = min( 目标模型单次时长 / 单镜最小可用时长 , 字数上限 / 单镜平均字数 )
单元镜数下限 = 由「镜头语言审计」的运镜类型数门槛反推（见下）
```

**"镜数下限"这条逻辑跨模型通用**：本项目审计器的门槛是 `min(5, max(2, ceil(镜数 / 4)))`——**分母是镜数**。1 镜单元要求 ≥2 种运镜，而一个镜头写不出两种运镜，**结构上必挂**。
→ **每个生成单元至少 2 镜**，拆单元时**不允许拆到只剩 1 镜**。4 镜拆成 2+2 可以；拆成 3+1 不行。

#### L2.2 骨架必须按模型套

**同一个故事，四家的骨架完全不同：**

| 模型 | 骨架 |
|---|---|
| MiniMax H3 | 三字段（`integrated_multimodal_description` → `overall_soundscape` → `non_diegetic_music`）**或**六段式（`subject_definitions` → `summary` → `retention_analysis` → `detailed_description` → `overall_soundscape` → `non_diegetic_music`） |
| Seedance | 资产映射清单 → 一句话简报 → 时间轴/镜头序 → 全局约束 |
| 可灵 | `主体 + 主体动作 + 场景 + 镜头语言 + 灯光氛围`（+ 独立负面词字段） |
| 即梦 | `主体 + 运动 + 背景 + 镜头语言`（+ 风格/画质/时长） |

> **改造时的顺序**：**先切单元，再套骨架。** 骨架套错了，后面所有内容都"无处安放"。

### L3 · 台词与音画

#### L3.1 台词语速可行性（物理约束，模型无关）

中文台词按 **≈6.5 字/秒** 折算（保守可用 6 字/秒倒推窗口）。**超速的台词，模型会念得含混或吞字，靠调镜头无法解决。**

| 语速 | 判定 | 修法 |
|---|---|---|
| ≤ 5 字/秒 | 宽裕 | 不动 |
| 5–7 字/秒 | 可接受（冷硬风格念白可压到 7–8） | 不动或微调 |
| 7–9 字/秒 | **偏快** | 优先扩窗口 |
| > 9 字/秒 | **不成立** | **必须扩窗口**，无替代方案 |

**唯一可靠的修法：给台词加时——画面一句不改，只改时间点。**

#### L3.2 声音分层

| 层 | 内容 | 注意 |
|---|---|---|
| **环境声 / 物理声** | 风、雨、脚步、布料、撞击、呼吸 | 不含对白 |
| **对白 / 歌唱 / 画内音乐** | 角色能听到的语音与音乐 | **必须与描述分离**标记 |
| **画外配乐（观众专属）** | 角色听不到、只有观众听得到的配乐 | **禁止抽象情绪词**（sad/tense/紧张…），只写乐器、速度、节奏、力度变化 |

**画内 vs 画外判定**：角色能听到的音乐（收音机、电视、乐器、歌女）→ **画内**；只有观众能听到的配乐 → **画外**。

**画外音写法（H3）**：`says in an off-screen voiceover` + 紧跟"嘴唇紧闭"说明。
> **方法论要点**：小说里的心理描写**优先转成画外音**，不要丢掉也不要硬塞成动作。**结构性红利**：画外音不与画面动作抢时间轴，几乎不会超速；**对白做不到**，这就是对白密集段最容易超速的根因。

#### L3.3 负面约束

| 模型 | 处理方式 |
|---|---|
| MiniMax H3 | **无负面字段** → 所有限制必须**正面措辞**（"画面里只有他一个人"，不写"不要出现别人"） |
| Seedance | 有全局约束块 → 正向写"保持…不变 / 不引入…" |
| 可灵 | **有独立负面词字段** → 不与正向混写 |
| 即梦 | **有独立负面输入框** → 不与正向混写 |

### L4 · 镜头语言八维（模型无关，跨模型可直接复用）

八维必须写在**画面描述部分内部**，不新增字段。

| # | 维度 | 必须出现 | 合格示例 |
|---|---|---|---|
| 1 | **景别** | 标准术语之一：`extreme long shot` / `long shot` / `medium shot` / `medium close-up` / `close-up` / `extreme close-up` / `insert shot`。**不要自造词** | `A medium close-up of …` |
| 2 | **运镜** | **类型 + 幅度 + 速度** | `The camera pushes in with small amplitude at slow speed.` |
| 3 | **角度** | 机位高度/俯仰角，写出**谁高谁低** | `shooting from a low angle so the table edge cuts across his chest` |
| 4 | **光学** | 焦段/景深/焦点，写出**观众该看哪里** | `with a shallow depth of field, the lantern in the background out of focus` |
| 5 | **构图** | 前/中/后景层次 + 主体在画框中的位置 | `he sits in the left third of the frame with the empty bench filling the foreground` |
| 6 | **轴线** | 对手戏必须写**屏幕方位**，保证不跳轴 | `she stays on the right of the frame and he on the left, their eyelines meeting across the table` |
| 7 | **光线** | **逐镜**光位，不是只在风格句里写一次 | `the lamp light falls on one side of his face only` |
| 8 | **画面结果** | 动作/环境在画面上留下的**可见改变** | `the wine spreads across the wet floor and the nearest men flinch back` |

**运镜三要素**：**运镜 = 运动类型 + 幅度 + 速度**。中等幅度与正常速度通常省略。
`Static Shot` 与 `POV` 不填幅度/速度。

**运镜句的独立成句要求**：运镜要写成**独立句或镜头内的自然英语动作**，不要藏在从句里，也不要在同一句里写两次运镜。
（H3 的校验器只认 `The camera` 起句；其他模型虽不强制，但**这仍是提高可控性的最佳实践**。）

#### L4.1 切镜/转场措辞

| 模型 | 措辞要求 |
|---|---|
| MiniMax H3 | **只有 5 句**（见分论 A） |
| Seedance | 转场可点名（`whip-pan left` + `wipe` + `dissolve`） |
| 可灵 / 即梦 | 自然语言（"镜头切换"） |

**通用原则**：切镜应带来**新信息**（新主体/空间/状态/视角/时间）；如果只是距离或轻微角度变化，**优先用运镜而不是切镜**。

#### L4.2 单人戏（无对手单元）的八维替代律

**这是最容易做错的一点，且跨模型通用。**

双人戏的八维本质是一套**关系学**：轴线是 A→B 的连线，视线是 A 看 B，景别对切靠两人轮流占画面。单人戏把"另一个人"抽走后，**照双人模板硬填的结果是"一个不动的人在一个不动的房间里"——八个格子全填了，但全是空的。**

所以单人戏的八维不是"填满"，是**换发动机**：

| 双人戏的参数 | 单人戏的替代物 | 怎么写 |
|---|---|---|
| **视线轴**（A→B） | **空间轴**（场景自身的两个方向，如 `窗 ↔ 门`） | 用场景的方向做轴；摄像机永不越线。方位词照旧用 `toward the left/right of the frame` |
| **对手**（第二个人） | **光** | 光是唯一在场的另一个角色。每镜都要说出"这一镜的光在干什么"，且必须是**变化** |
| **正反打**（切另一边） | **焦点对切**（`the focus pulls off A and settles on B`） | 换一次焦点＝换一次注意力，等于剪了一刀但没切镜头 |
| **台词**（两人对话） | **身体** | 画外音必须嘴唇闭合，所以"他在说什么"不能靠嘴。**先由身体说一遍**（喉头吞咽/手指收紧/肩线沉下/呼吸停半拍） |

**两条禁律**：
1. **禁"无光的镜头"**——光若没有任务，这一镜就是空的。
2. **禁"无结果的静止"**——静止镜里必须有一样东西在动，**而且必须被写出来**。**静止镜 ≠ 空镜。**

**两处放开**：
- **角度**——单人戏没有轴要保，角度就是最直接的内心外化工具：`slightly high` = 被压着；`eye level` = 中性；`slightly low` = 顶着。**一条完整的"高→平→低"角度弧，就是一个单元的情绪曲线。**
- **景别**——不受对切约束，可以**跳级**（`long shot → close-up`）。

**总纲：以动写静。** 单人戏的"表演"不在人身上，在**场**上——找**最小的在动的东西**当主角（雨丝/一滴水/灯焰/汗珠），**人反而是那个不动的**。

**双景（现实 ↔ 内心空间）**：**跨界必须重新立轴**；**切入内景时，现实的光必须已消失**。

### L5 · 跨单元连续性

**单条提示词都合规，合起来照样穿帮。** 必须显式维护三类状态：

1. **轴线一致性**——同一场对话，A/B 双方机位必须留在轴线同侧。先为每个场景钉一张"平面图"，写进该场景下**每一个镜头、不允许一次例外**的方位约定。
   - 正反打**每一镜都要写清屏幕方位**；两人**永远分居画框两侧**。
   - 方位要用**可判读**的词（`toward the left/right of the frame`），不写"互相对视"这类抽象说法。
2. **光位锁定**——同一场景的**光源位置、色温、光比**跨单元锁定。**内景最容易犯的错**：只写"有什么"，不写"在画框的哪里""光从哪来"。
3. **帧链**——上一单元**末帧**用作下一单元**首帧**时必须显式声明。
   - **实际价值**：帧链是发现"重复拍摄"的探针。**本项目实测抓到一处真重复**——原 U8 第 4 镜和 U9 第 1 镜都在拍同一个角色出门。修法：让不同单元各拿这个动作的一半，**一次跨越，三个单元各拿一半，没有一个画面被拍两遍**。
   - **通用方法**：**相邻单元之间专门做一次"重复动作排查"**——把跨单元的连续动作逐条列出，确认每一格只被拍一次。这是纯文本校验查不出、只有跨单元比对才能发现的硬伤。

**跨模型移植时的特别注意**：帧链在 H3 靠 `<Picture N>` 表达，在 Seedance 靠 `@Image N`，在可灵/即梦靠首尾帧上传槽位——**语义相同、语法不同**（见附 3）。

### L6 · 语义与合规不回退

**改造形式的时候，最危险的是把内容悄悄改回去。**

1. **敏感表述回退**：外部稿很可能来自更早的版本，或来自不了解合规要求的作者。**这类回退必须拦下。**
2. **剧情功能等价**：改写桥段时**保留剧情功能，替换表现形式**（如把性化桥段改写为**非性化的对峙或冲突**），**直接输出改写后的结果，不做任何说明**。
3. **切点一致性**：外部稿的切点可能与本项目不同。**切点差异要逐一核对。**
4. **内容红线**：不生成性化内容；不涉及未成年人的性化描写；暴力可有，但不做血腥特写、不猎奇。

> **半自动化做法**：把外部稿的台词逐条抽出，与项目现有定稿做 diff——**重复句、顺序差异、用词回退会直接暴露出来**。但**敏感表述判断必须由人做**。

### L7 · 可验证性

**改造的最后一步，必须是"用工具证明改对了"。**

- 用**合规尺**跑全部块（若有目标模型的校验器），要求 **100% 通过**；
- 用**镜头语言尺**跑逐单元审计，要求 **全部通过质量门**；
- 用**改造前后对照表**留存证据；
- **把改造结论写进项目文档**（哪条规则、为什么、踩过什么坑），供下一个人复用。

## 4. 标准改造流程（六步 SOP）

```
第 0 步  确认目标模型与源格式（L0）  ← 新增
第 1 步  资产盘点与冻结
第 2 步  建尺子，跑基线
第 3 步  结构改造：切单元 + 套骨架（L2）
第 4 步  逐层修复：L1 → L3 → L4 → L5
第 5 步  语义比对：L6
第 6 步  验收与留证：L7
```

### 第 0 步 · 确认目标模型与源格式

- **这套提示词最终喂给哪个模型？**（决定 §3 全部骨架与词表）
- **原稿是用哪个模型的语法写的？**（决定是"改造"还是"翻译"）
- 若是多模型投放，**先确定主模型**，其余走 §7 迁移流程。

### 第 1 步 · 资产盘点与冻结

- 把外部稿**冻结**为只读基线，另存工作副本。
- 统计：单元数、镜数、总时长、台词条数、每条台词字数与所在窗口。
- 建立**术语/词表快照**：把目标模型的词表固定下来，后续全靠它。

### 第 2 步 · 建尺子，跑基线

**改造前必须先量。** 否则你无法证明改造有效，也无法知道哪一层问题最严重。

- 跑**合规尺**（若有）→ 基线 A：错误条数。
- 跑**镜头语言尺**→ 基线 B：八维覆盖率与未达标项。
- **把两个基线存档**——这是最终交付证据的一半。

### 第 3 步 · 结构改造（L2）

- **切单元**：按目标模型的时长/镜数/字数边界切；**禁止切到 1 镜**。
- **套骨架**：按目标模型套对应骨架；检查顺序、首镜时间处理、风格句位置。
- **重排时间轴**：镜号连续、时间码递增（若模型支持）。

### 第 4 步 · 逐层修复

严格按 L1 → L3 → L4 → L5 顺序：

1. **L1**：批量补对白标记、清违规字符、绑 ID、统一引号。
2. **L3**：核台词语速（超速的扩窗口）；核音轨分层；核对画外音写法；负面约束按模型归位。
3. **L4**：逐镜补八维。**这是主要工作量**——先定轴线、再排景别、再定角度光学、再补构图三层、最后补画面结果。
4. **L5**：跨单元对轴线/光位/帧链；**做一次"重复动作排查"**。

### 第 5 步 · 语义比对（L6）

台词逐条 diff；敏感表述回退检查；剧情功能等价性确认。

### 第 6 步 · 验收与留证（L7）

跑尺子 → 填 §6 清单 → 生成改造前后对照表归档。

## 5. 跨模型共性硬约束（不随模型改变的部分）

以下 12 条在**任何**视频/图像生成模型上都成立，可直接写入通用规范：

| # | 约束 | 理由 |
|---|---|---|
| 1 | **一条提示词只服务一个生成单元**，不写"一整章" | 单次生成有时长与注意力上限 |
| 2 | **每个生成单元 ≥ 2 镜**（若模型支持多镜） | 运镜类型数的分母是镜数，1 镜结构上必挂 |
| 3 | **运镜 = 类型 + 幅度 + 速度** | 只写"环绕""推进"无法控制节奏 |
| 4 | **运镜要独立成句**，不要藏在从句里、不要一句两次运镜 | 藏在从句里会静默失效；两次运镜会被平均掉 |
| 5 | **切镜要带来新信息**；只是距离变化就用运镜 | 无信息的切镜会让成片碎 |
| 6 | **景别不许连续三镜同级**；推荐递进或跳级 | 同级连切＝视觉停滞 |
| 7 | **静止镜必须有东西在动，且要写出来** | 静止镜 ≠ 空镜 |
| 8 | **对手戏每一镜都写屏幕方位**，两人恒分居画框两侧 | 不写就跳轴 |
| 9 | **单人戏每镜点名一个光源 + 它这一镜做的事** | 无光的镜头是空镜 |
| 10 | **台词必须与描述分离标记，且逐字保真** | 混写会污染语义；改写会破坏合规 |
| 11 | **画面可见文字必须加引号原样写出，不翻译** | 四家一致要求 |
| 12 | **抽象情绪词不用于配乐/氛围描述**，写具体的声音与光影 | 情绪词无法执行 |

## 6. 验收清单

### A. 目标对齐（L0）

- [ ] 对白被明确标记为对白，且标记语法符合目标模型

- [ ] 景别无连续三镜同级
- [ ] 单人戏：每镜有点名光源；静止镜里有"在动的东西"且被写出

### F. 跨单元层

- [ ] 同场景各单元屏幕方位一致（不越轴）
- [ ] 同场景光位/色温锁定
- [ ] 帧链/首末帧声明正确（按目标模型语法）
- [ ] **"重复动作排查"已完成**

### G. 语义层

- [ ] 敏感表述无回退
- [ ] 台词无重复 / 顺序与定稿一致 / 切点已核对
- [ ] 内容红线全部通过

### H. 验证层

- [ ] 合规尺（若有）：100% 通过
- [ ] 镜头语言尺 `-u --gate`：全部单元通过
- [ ] 改造前后对照表已生成并归档
- [ ] 改造结论（含踩坑）已写入项目文档

## 7. 迁移到新模型的标准动作

**当你已有某个模型的合格提示词集，要投放到另一个模型时**，按这五步做：

```
1. 拆件   —— 把成品拆成「模型无关内核」与「模型专属外壳」
2. 换壳   —— 用目标模型的骨架重装
3. 换词   —— 用目标模型的词表替换运镜/转场/参考语法
4. 校边界 —— 重新核对时长/镜数/字数/参考上限
5. 重验   —— 用目标模型的尺子（或至少 §6 清单）重新验收
```

### 可分拆的「模型无关内核」（可直接复用）

- 故事与切点、镜头序列、每镜的景别/角度/光学/构图/轴线/光线/画面结果
- 台词文本、语速核算
- 角色/场景/光线锚点串的内容
- 八维写法、单人戏替代律、L5 连续性逻辑

### 必须重建的「模型专属外壳」

| 外壳 | H3 | Seedance | 可灵 | 即梦 |
|---|---|---|---|---|
| 字段结构 | 三字段/六段式 | 映射+简报+时间轴+约束 | 五要素 | 四要素 |
| 参考语法 | `<Subject N>` | `@Image N` | 上传槽位 | 上传槽位 |
| 时间表达 | `At MM:SS.mmm,` | `0–3s` | 无 | 时序标签 |
| 对白标记 | `<d>[Chinese]` | `{…}` | 自然语言 | 自然语言 |
| 负面词 | 无（正面化） | 约束块 | 独立字段 | 独立输入框 |

> **注意**：**"迁移"不是"改几个词"**。骨架不同意味着段落顺序、信息优先级、甚至镜头切分粒度都可能要变。**跨模型迁移的工作量通常不低于 50% 重写。**

## 8. 分论 A · MiniMax H3

> **规范强度：★★★★★**（四家中最严，字段与词表均可程序化校验）
> **适用场景**：需要跨镜头严格一致性、需要可自动化验收的生产线。

### 8.1 两套模式，先选一套

| 模式 | 用于 | 骨架 |
|---|---|---|
| **基础模式** | T2VA / I2VA / FL2VA / L2VA | 三字段 |
| **全参考模式** | Ref2VA（有参考素材） | 六段式 |

### 8.2 骨架

**基础模式（三字段，空行分隔）**

```
integrated_multimodal_description: [Shot 1] ...

overall_soundscape: ...

non_diegetic_music: ...
```

**全参考模式（六段式，顺序固定）**

```
subject_definitions → summary → retention_analysis →
detailed_description → overall_soundscape → non_diegetic_music
```

**关键位置规则**：

| 规则 | 说明 |
|---|---|
| `[Shot 1]` | **不带时间码**；风格句写在 `[Shot 1]` **之内** |
| `[Shot 2]` 起 | `[Shot N] At MM:SS.mmm,`，**严格递增**且小于单元时长 |
| 六段式的风格句 | **必须在 `[Shot 1]` 之前**（与三字段版不同，最易搞混） |
| 图生视频模式 | I2VA/FL2VA/L2VA **首行必须是对齐指令**，与官方模板逐字一致，随后一个空行 |
| 三字段版正文 | **不出现 `<Subject N>` 标签**（标签只属于 Ref2VA） |

### 8.3 硬约束清单

| # | 项 | 约束 |
|---|---|---|
| 1 | **切镜措辞** | **只有 5 条**：`the camera cuts to` / `the shot cuts to` / `the shot transitions to` / `the shot changes to` / `the shot switches to`。`the shot cuts back to` 这类变体**不合规** |
| 2 | **运镜句** | 必须以 `The camera` 起句、独立成句。藏在从句里（`…, and as he goes the camera pulls out…`）会被判"缺运镜" |
| 3 | **运镜类型** | 只能取官方 20 种（见 §8.5） |
| 4 | **幅度/速度** | `small` / `large` / `null`；`slow` / `fast` / `null`。`Static Shot` 与 `POV` 不填 |
| 5 | **时间码** | `[Shot 1]` 不带；后续 `At MM:SS.mmm,`；严格递增、无重复、小于单元时长；个数 = 镜数 − 1 |
| 6 | **镜号** | 从 1 连续 |
| 7 | **说话人 ID** | 稳定 ID `(S1)`/`(S2)`；`<d>[Chinese] …</d>` 只放台词本身，**识别与语气写在 `<d>` 外面** |
| 8 | **画外音** | `says in an off-screen voiceover` + 每个画外音 `<d>` 后**紧跟**"嘴唇紧闭"说明 |
| 9 | **中文位置** | **只允许**在 `<d>` 内与英文双引号内；引号必须是英文双引号（中文引号违规） |
| 10 | **`<d>` 配对** | `<d>` 与 `</d>` 数量相等 |
| 11 | **声音字段** | `overall_soundscape` **1–4 句**；`non_diegetic_music` **1–3 句**；soundscape 不复述对白；music 无抽象情绪词 |
| 12 | **参考标签** | 四种：`<Subject N>` / `<Picture N>` / `<Video N>` / `<Audio N>`；编号唯一；**正文所有标签必须已定义** |
| 13 | **参考上限** | 图 ≤ **9**、视频 ≤ **3**、音频 ≤ **3** |
| 14 | **`retention_analysis`** | 行格式固定；标记取自固定集合；可见内容必须带**括号定位说明**；**绝对不许出现 `(S1)`**；每个已定义标签都要有对应行 |
| 15 | **`summary` 前缀** | 方括号任务类型开头；6 个固定值；多类型 ` + ` 连接不重复；**不许引入新标签** |
| 16 | **任务类型判定** | 只是拿视频当运镜/节奏参考 → `reference generation`，**不是** `video editing` |
| 17 | **`detailed_description`** | 必须含 `[Shot 1]`；`[Shot 1]` 前有风格开头句；建议 **350–500 英文词** |
| 18 | **三字段块** | 不出现 `<Subject N>` |
| 19 | **负面约束** | **无 Negative 字段** → 全部**正面措辞** |
| 20 | **字数上限** | 单块 ≤ **7,000 字符** |
| 21 | **单元边界** | 时长 **4–15 秒整数**；镜数 **2–4**（八维版建议 ≤3） |

### 8.4 字数预算（本项目实测，硬约束）

- **八维全开比纯画面描述费字约 +47%**（实测 4,724 → 6,933 字符 / 14 秒 4 镜）。
- 因此 **7,000 字符是真正的约束**：**八维版单单元应压到 3 镜以内，4 镜已到极限。**
- **`subject_definitions` 的条数才是字数的主要变量，不是镜头数。** 3 镜单元实测 5,377–6,926 字符；6,926 那条有 9 条声明（最坏情况）。2 镜单元实测 4,122–4,329 字符，安全。
- 结论：**先数 `subject_definitions` 有几条。超过 7 条的单元，3 镜就是上限。**

**压缩优先级（按有效性排序）**：
1. **`subject_definitions` 里写过的外形/场景，镜头里只用 `<Subject N>` 指代，不再抄一遍**（最有效，单单元可省百余字符）；
2. `retention_analysis` 不复述 `subject_definitions`，只写"保留了什么 + 本单元新增的变化"；
3. 删冗余定语（`about a dozen square wooden tables` → `square tables`）；
4. 对白密集段**优先保台词**，八维只保留轴线 + 景别 + 运镜，其余五维分配到别的镜头——**单元级达标，不是每镜都要八维全开**。

### 8.5 词表速查

**运镜 20 类**：`Zoom In/Out`、`Push In`、`Pull Out`、`Pan Left/Right`、`Truck Left/Right`、`Tilt Up/Down`、`Pedestal Up/Down`、`Arc Shot`、`Tracking Shot`、`Static Shot`、`Shake Slightly/Strongly`、`POV`、`Roll Clockwise/Counterclockwise`

## 9. 分论 B · Seedance（字节即梦）

> **规范强度：★★★★**（结构清晰、参考语法强，但字段不如 H3 硬）
> **适用场景**：多参考素材编排、单次长片（4–30 秒）、需要给每个素材分配明确角色。

### 9.1 骨架：四部分结构

```
① 资产映射（Asset mapping）      —— 每个上传文件干什么
② 一句话简报（One-sentence brief）—— 主体 + 地点 + 事件 + 类型/风格 + 特殊镜头处理
③ 时间轴 / 镜头序（Timeline）    —— 视觉、动作、运镜、对白、声音按时序
④ 全局约束（Global constraints） —— 机位、光线、色彩、氛围、画幅、无字幕、无BGM
```

**官方示例骨架**：

```
[生成目标] 描述要做的东西
[素材] @Image 1 defines ... / @Video 1 defines ... / @Audio 1 defines ...
[场景或阶段计划] 主体 + 可见动作/事件 + 环境 + 风格 + 运镜 + 音频
[保持一致] Keep ... unchanged. Do not introduce ...
```

### 9.2 硬约束清单

| # | 项 | 约束 |
|---|---|---|
| 1 | **资产映射必须逐条绑定** | 声明每个 `@Image N` / `@Video N` / `@Audio N` **属于谁、参考什么**。**不要让模型猜"images 1–4"是不是四个人。** |
| 2 | **每个素材要能补完这句话** | "Use this asset for ___，and ignore ___"。补不完就不要加。 |
| 3 | **部分使用要声明不继承什么** | 只借运镜就写"仅参考运镜，不得复制其主体或场景" |
| 4 | **时间范围必须连续** | `0–3秒`、`3–7秒`、`7–15秒`，**不留未解释的空档** |
| 5 | **每段一个主要状态变化 + 一个可见结束态** | 结束态是下一段的起点 |
| 6 | **精确秒数只用于真正需要提示的事件** | 其余用相对时间（"按下快门后，定格一秒"） |
| 7 | **内容密度要匹配时长** | 太稀模型会自行发挥；太密会互相争抢 |
| 8 | **每条提示词只含一项可见变化** | 优于充斥相互竞争指令的冗长段落 |
| 9 | **不要重复描述参考图里能看到的东西** | 图生视频模式下，**提示词是导演指令，不是美术描述** |
| 10 | **避免** | 模糊赞美（"使其更具电影感"）、相互冲突的运镜、过多同时发生的动作、不被支持的精确指令（"一秒内恰好眨眼三次"） |

### 9.3 时间戳语法

| 类型 | 写法 | 示例 |
|---|---|---|
| **时间范围** | `x–y秒 动作描述`（整秒，支持小数） | `0–3秒 低角度中远景…` |
| **精确时间** | `At second 5, …` | `At second 5, whip-pan left and complete the transition with a wipe followed by a natural dissolve.` |
| **相对时间** | 事件触发 | `After the lead presses the shutter, freeze the frame for one second, then enter the next shot.` |

**官方建议**：段数**不超过 5 段**，过多会稀释时序注意力。

| 镜头时长 | 建议拆段数 |
|---|---|
| 3 秒 | 3 段 |
| 10 秒 | 3–4 段 |
| 30 秒 | 4–5 段 |

**错误写法**：`一开始低头，后来抬头`（无明确时间节点）
**正确写法**：`0-1s 保持低头站姿; 1-2.5s 匀速缓慢抬头; 2.5-3s 定格仰望姿态`

### 9.4 参考素材语法与上限

**标签**：`@Image N` / `@Video N` / `@Audio N`

| 素材 | 上限 | 建议起始量 |
|---|---|---|
| 图像 | ≤ **30**（每张 ≤4K） | 1–8 个不同主体 |
| 视频 | ≤ **10**（合计 ≤30 秒） | 1–5 个，每个 5–10 秒 |
| 音频 | ≤ **10**（合计 ≤30 秒） | 只保留场景真正用到的 |
| 合计 | ≤ **50** | — |

> **"上限不是目标。"** 十张松散相关的角色图比三张标注清楚的多视图更容易造成歧义。**只在你能补完"Use this asset for ___，and ignore ___"时才加素材。**

**同一主体多视图要显式声明**：

```
@Image 1 defines the front of the same travel speaker.
@Image 2 defines its left-side controls.
@Image 3 defines its rear ports.
All three images describe one speaker. Keep exactly one speaker in the video.
```

最后一句是**基数约束**——防止参考包变成演员表。

### 9.5 对白与声音的特殊标记

当区分变得重要时：

| 内容 | 标记 |
|---|---|
| 音乐 | 圆括号 `( … )` |
| 音效 | 尖括号 `< … >` |
| 对白 | 花括号 `{ … }` |
| 字幕 | 全角方括号 `【 … 】` |

### 9.6 运镜词表

Seedance 对镜头指令理解良好，**要点名景别、运动、速度**：

| 运动 | 可用写法 | 适用 |
|---|---|---|
| 推向主体 | `slow push-in` / `dolly-in` / `zoom toward` | 人像、产品细节、揭示 |
| 拉离主体 | `pull back` / `dolly-out` / `slow pull away` | 风景、大全景建立镜头 |
| 环绕主体 | `orbit left/right` / `arc around` | 产品、物体、建筑 |
| 水平摇 | `pan left` / `pan right` / `track left` | 横向场景 |
| 垂直摇 | `tilt up` / `crane up` / `tilt down` | 高主体、天空揭示 |
| 固定 | `static locked-off` / `no camera movement` | 桌面、讲话人、产品特写 |
| 轻微手持 | `slight handheld movement` / `subtle camera drift` | 纪录感、自然背景 |

**速度修饰**：`very slow` / `gradually` / `quick pan` / `sweeping`。**Seedance 对节奏语言有响应，会体现在成片上。**

### 9.7 时长与边界

| 项 | 值 |
|---|---|
| 单次生成时长 | **4–30 秒** |
| 精确拆段建议 | ≤ 5 段 |

### 9.8 改造 Seedance 提示词的重点

1. **补资产映射**：这是 Seedance 最容易缺、也最影响一致性的一块。外部稿通常只写"参考图 1"，不写"参考它的什么"。
2. **时间范围补连续**：外部稿常出现跳跃的时段，要补成连续区间。
3. **每段补可见结束态**：外部稿常只写"开始做什么"，不写"停在哪一格"。
4. **删掉重复描述参考图的内容**：图生视频模式下重复描述会浪费注意力。
5. **全局约束收尾**：补"保持一致"块（身份、数量、服装、道具归属、空间方向、音频、排除项）。

> **可灵独有的优势**：运镜可以用**数值**表达，这是四家里唯一能精确量化机位运动的。改造时若原稿是"环绕一点"，可改写为明确的六轴参数。

| 2 | **简洁精确优于华丽堆叠** | 4.x 对文本理解更强，**堆砌复杂词汇反而变差** |
| 3 | **文字必须放进引号** | ✅ `生成一张海报，标题为 "Seedream V4.0"`<br>⚠️ `生成一张标题为 Seedream V4.0 的海报` |
| 4 | **写明应用场景** | 明确图像用途与类型（logo / 海报 / 插画 / 图表） |
| 5 | **编辑公式** | `变化动作 + 变化对象 + 变化特征`（如"将骑士的头盔变为金色"） |
| 6 | **多图参考要分工** | "将图 1 中的角色放入图 2 的背景中，参考图 3 的风格" |
| 7 | **避免模糊代词** | ✅ `保持其姿态不变` + 明确指称<br>⚠️ `把那个换成粉色` |
| 8 | **专业词汇用词源语言** | 术语用原文更准确 |
| 9 | **组图** | 用"一系列""组图""帮我生成几张图"触发，最多 10 张 |

### 11.5 改造即梦/Seedream 提示词的重点

1. **重排优先级**：把最重要的主体信息放到最前面（识别权重最高）。
2. **抽象形容词替换为具体描述**：这是即梦稿最常见的毛病。
3. **拆分"姿态锚点"与"镜头语言"**：不要用 `[低桩]` 这种自造标签代替机位描述。
4. **补程度副词**：动作缺"大幅度/缓缓"这类修饰，节奏就丢了。
5. **文字移入引号**；视频场景则**直接避免生成文字**。
6. **负面词移入独立输入框**。

## 12. 分论 E · 通用兜底模型

> **适用**：不公开写作规范的模型（Runway、Sora、Pika、以及各类自部署/第三方模型）。

### 12.1 兜底原则

**没有官方规范，不等于没有规范。** 用 §5 的 12 条共性硬约束 + §3 的 L4 八维，已经可以覆盖 80% 的可用性问题。

### 12.2 通用输出格式（可直接粘贴）

```text
【主体】具体外形串（年龄/服装/发型/标志物，逐字复用）
【动作】一个核心动作，含起-承-结与可见结果
【场景】可锚定的载体（不止"在桥上"，而是"桥中央第三块桥板"）
【镜头】景别 + 机位角度 + 运镜（类型+幅度+速度）+ 构图层次
【光线】光源位置 + 光质 + 光比
【氛围】环境声 + 次级动态
【风格】风格锚点（固定 3–5 个，不增不减）
【约束】需要保持不变的部分（正向措辞）

负面词：（若平台支持，单独列出）
```

### 12.3 三条生成路线（应对单次时长不足）

单次生成无法覆盖多拍长片时，**必须显式给出路线**：

| 路线 | 做法 | 适用 |
|---|---|---|
| **A 逐拍** | 每拍生成一段素材，剪辑取爆发段 | 最忠实原节奏 |
| **B 合并** | 相近拍合并为 4–6s 长镜，段内剪辑切拍 | 预算受限 |
| **C 压缩** | 削减重复动作单元，用 10s+5s 覆盖 | 必须一次出片 |

### 12.4 首尾帧工作法

利用每拍已写好的"起始状态 / 结束状态"各出一张关键帧图，用图生视频锁定起止姿态——**这是让 0.5–1.2 秒微动作听话的最稳办法**（关键帧图可由 Seedream 等图像模型产出）。

### 12.5 兜底禁则

- **【禁】虚构平台专属参数**（不存在的分辨率、专属字段、伪 API 名词）。
- **【建议】只引用已被告知的具体平台能力**（时长选项、首尾帧支持）。

## 附 1. 改造前后实测证据（MiniMax H3 全量数据）

> 以下数据全部来自工具实测，不是估算。这张表本身就是**"改造必须有两把尺子"**的最佳证据。

### 1.1 规范合规

| 对象 | 结果 |
|---|---|
| 外部稿（3 章 AI 生成稿） | **4/4 条全部不通过，共 33 处报错** |
| 本项目 · 未升级原始稿 | 17/17 条通过（**形式上是合规的**） |
| 本项目 · 八维升级后合集 | **30/30 条通过**（15 单元 × 双版本） |

### 1.2 镜头语言 —— 这才是真正的差距

| 维度 | 本项目原始稿 | 外部稿 | 八维升级后 | 质量门 |
|---|---|---|---|---|
| 景别 | 89% | 100% | **100%** | 100% |
| 运镜 | 100% | 0% | **100%** | 100% |
| 角度 | 4% | 0% | **100%** | ≥40% |
| 光学 | 0% | 0% | **100%** | ≥30% |
| 构图 | 2% | 0% | **100%** | ≥50% |
| 轴线 | 0% | 0% | **97%** | ≥30% |
| 光线 | 20% | 0% | **95%** | ≥40% |
| 画面结果 | 40% | 75% | **100%** | ≥60% |

**通过质量门的单元数**：

| 对象 | 通过 / 总 |
|---|---|
| 本项目原始稿 | **0 / 17** |
| 八维升级后合集 | **30 / 30** |

**其他指标**：镜数 55 → 78；静止镜 26/55（47%，超限）→ 24/78（31%，合格）；未达标项 8 → 0。

### 1.3 能读出三件事

1. **原始稿是"合规但平铺"的典型**：17/17 通过规范，却 0/17 通过镜头语言门——**运镜 100% 却在角度/光学/构图上几乎为零**。"每镜都有运镜"远不等于"镜头语言丰富"。
2. **外部稿连合规都没过**：运镜/角度/光学/构图/轴线/光线**六维全部 0%**。它连"每镜有运镜"这条最基本的都没做到。
3. **"画面结果 75%"是外部稿唯一亮点**，说明作者会写"动作留下什么痕迹"，但不会写"怎么拍"——**这正是"分镜思维"与"镜头语言思维"的差别**。

### 1.4 一个反直觉的实测发现

工具抓到的最严重问题**不是风格问题，而是会被模型直接拍错的硬错**：

| 问题 | 性质 |
|---|---|
| 用了非官方切镜措辞 `the shot cuts back to` | 措辞不合规 |
| 某镜漏写角度——**"高→平→低"角度弧的中间那一点漏了，弧就只剩两头** | 结构性缺失 |
| 某镜运镜句没独立成句（藏在 `…, and as he goes the camera pulls out…` 里） | 会被判"缺运镜" |
| 某单元 `non_diegetic_music` 残留抽象情绪词 `tense` | 内容违规 |
| **跨单元真·重复拍摄**（同一动作被两个单元各拍一遍） | 纯文本校验查不出 |

> **结论**：改造的价值不在于"把句子写漂亮"，而在于**把模型会拍错的地方全部堵掉**。

## 附 2. 常见失败模式总表

按**从死到轻**排序。前 4 条是"直接不可用"，其余是"能用但拍不好"。

| # | 失败模式 | 涉及模型 | 后果 | 修法 |
|---|---|---|---|---|
| ① | **台词无语言/对白标记**（21 条全写成 `<d>已经三天三夜了。</d>`，缺 `[Chinese]`） | H3 | 模型无法判定语言 | 正则批量补；**这是"每条都错"型错误，必须全量扫** |

| ③ | **整章当一个生成单元**（第 2 章 8 镜 + 8 句台词塞一条） | 全模型 | 超时长、超字数、指令被稀释 | 按 2–4 镜 / 时长边界切；**切完必须数——不许出现 1 镜单元** |
| ④ | **运镜无幅度速度 / 一句两次运镜**（14 句全缺；`The camera then shifts to …`） | H3 / Seedance / 可灵 | 模型把两个动作"平均掉"，节奏全丢 | 补三要素；**拆句——一句只允许一个运镜动作** |

| ⑥ | **时间范围不连续 / 无结束态** | Seedance | 段间无可靠起点，模型自行发挥 | 补连续区间 + 每段可见结束态 |

| ⑪ | **用了未核实的官方语法**（如 `<scenetrans>`） | H3 | 静默失效或报错 | **没核实的东西不写进交付稿**（见附 5 第 3 条） |

## 附 5. 本方法论的自我限定

1. **质量门阈值是本项目自定，不是任何厂商的官方硬性要求。** 官方只规定"怎么做"（格式、词表、语法），不规定"做多少"（覆盖率的百分比）。阈值可随项目调整，但**"两把尺子分开量"的原则不变**。
2. **只有一个模型有可执行校验器（MiniMax H3）。** 其余三家目前只能靠 §6 清单人工验收。**这是本文档目前的局限，也是后续可补强的方向。**
3. **未核实的官方语法一律不写进交付稿。** 这是本方法论里**最贵的一条经验**，它来自两次真实的决策拦截（`<scenetrans>` 语法至今未逐字核实，因此从未进入任何交付稿）。
4. **L6 语义不回退无法完全自动化。** 可以做半自动 diff（台词逐条比对），但**敏感表述判断必须由人做**。不要把合规判断交给脚本。
5. **跨模型迁移不是"改几个词"。** 骨架不同意味着段落顺序、信息优先级、甚至镜头切分粒度都可能要变。**跨模型迁移的工作量通常不低于 50% 重写。**
6. **本文只解决"提示词可用性"，不解决"内容创作质量"。** 剧本好不好、分镜合不合理，是另一个问题。本文的边界是：**给定一份内容，让它能被模型正确、稳定、有节奏地拍出来。**
7. **模型规范是移动靶。** 本文所有具体数值（字数上限、时长、参考上限）都是**特定时点的快照**，使用前必须复核（见附 4）。
