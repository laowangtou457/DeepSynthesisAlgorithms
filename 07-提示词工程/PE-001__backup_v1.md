# 外部提示词集「AI 可用化」改造方法论

> **适用对象**：任何人拿到一份**非本产线生成**的提示词集（AI 生成的、编剧写的、外包交付的、从别处抄来的），需要把它改造成**能稳定喂进视频生成模型、并拍出可用镜头**的规范提示词集。  
> **方法论载体**：MiniMax H3 提示词体系（本文所有示例、词表、阈值、脚本均来自该体系）。**方法本身可迁移到其他「有官方写作规范 + 有可校验字段」的视频生成模型**，迁移方式见 §9。  
> **本文用途**：可复用、可交付、可审计的改造 SOP。读完应能独立完成一次完整改造，并用工具证明改造成了。

## 0. 一句话总纲与使用方式

**总纲：AI 可用性不是文笔问题，是可验证性问题。**

一份提示词集"不可用"，绝大多数时候不是因为写得不够美，而是因为它违反了模型官方规范的某几条硬规则，或缺少让画面"有节奏"的镜头语言信息。**前者可以被脚本逐条查出，后者可以被脚本按维统计。** 因此改造的正确姿势是：

```
先建尺子  →  再改稿  →  用尺子证明改对了  →  把尺子固化成流程
（§6 工具）  （§2 七层）  （§4 质量门）        （§5 SOP / §8 清单）
```

**使用方式**：把本文当作改造作业手册。拿到外部提示词集后，**不要先改文字**，直接跳到 §5 执行六步 SOP；每一步需要的详细规则再回查 §2 对应层。

## 1. 核心判据：为什么「看着对」不等于「能用」

外部提示词集最常见的幻觉是：**它读起来很像分镜脚本，于是就以为它可以直接生成。**

事实是：**分镜脚本的详细度 ≠ 提示词的可用度。** 一份结构化、术语规范、看起来非常专业的分镜稿，在"镜头语言"上可能比可用稿差一个数量级。

必须区分**三件事**，它们是三个独立的质量层次，互不替代：

| 层次       | 量什么                             | 谁来量                     | 不通过的后果                                  |
| -------- | ------------------------------- | ----------------------- | --------------------------------------- |
| **规范合规** | 字段顺序、时间码、镜号、参考标签、台词语法、字数上限      | 合规校验器（本文 §6 的"合规尺"）     | 模型**直接报错、截断或输出错乱**——不是"效果差"，是"跑不动"      |
| **镜头语言** | 景别/运镜/角度/光学/构图/轴线/光线/画面结果 八维覆盖率 | 镜头语言审计器（本文 §6 的"镜头语言尺"） | 模型**能跑，但拍出平铺直叙的画面**：不知道看哪里、谁压过谁、镜与镜什么关系 |
| **语义合规** | 剧情功能是否被悄悄改写、已删改的敏感表述是否回退        | 人工对照（可半自动化）             | 过了前两关，但**内容出了合规问题**，返工代价最大              |

> **关键结论（本项目实测）**：一份提示词可以 **100% 通过规范合规，同时运镜/角度/光学/构图/轴线/光线全部为 0%**。  
> 参考数据：本项目被改造的原始稿 **17/17 个单元全部通过规范校验**（"合规"），但 **0/17 个单元通过镜头语言质量门**。见 §6。

所以改造的**验收必须是两个尺子同时通过**，缺一不可。

## 2. 七层改造清单（L0–L6）

七层按**改造顺序**排列，也按**检查成本**排列：越靠前越机械、越容易批量修，越靠后越需要判断。**不要跳层**——L0 没修完就改 L3，等于在错的地基上装修。

```
L0 语言与角色规范   ← 正则可查，批量修
L1 结构合规        ← 切单元、套骨架，决定后面所有内容有没有地方放
L2 台词与音画      ← 物理可行性（念不念得完）+ 音轨分层
L3 镜头语言八维    ← 内容层，工作量最大，收益也最大
L4 跨单元连续性    ← 轴线 / 光位 / 帧链，必须显式维护状态
L5 语义与合规不回退 ← 防"改形式时把内容改回去"
L6 可验证性        ← 跑尺子 + 留证据
```

---

### L0 · 语言与角色规范（机械可查，最先做）

这一层完全不需要懂镜头，纯机械匹配，但**错了就是整条提示词被判无效**。

| 检查项             | 约束                                                     | 说明                                 |
| --------------- | ------------------------------------------------------ | ---------------------------------- |
| **中文（CJK）出现位置** | 只允许出现在**两处**：`<d>…</d>` 标签内、以及**英文双引号**内（画面可见文字）       | 框架描述里出现任何中文都算违规。这是外部稿最密集的错误来源      |
| **台词语言标签**      | `<d>[Chinese] 台词原文</d>`，方括号语言标签**必须有**                 | 漏标签是最常见错误，且**每条台词都错**，不是个别         |
| **引号类型**        | 画面可见文字必须用**英文双引号** `"…"`，不用中文引号 `""''` `「」`            | 中文引号会被判违规                          |
| **角色身份**        | 说话人用**稳定 ID** `(S1)` `(S2)`…；视频参考模式另用 `<Subject N>` 标签 | 不发声的角色**不给 ID**                    |
| **角色命名**        | 人名/称谓必须转写为**英文**，并绑定稳定 ID                              | 不允许在英文句子里直接写中文人名                   |
| **台词位置**        | 说话人识别语、动作、语气**写在 `<d>` 外面**；`<d>` 内**只放**语言标签 + 逐字原文   | 混写会导致 `<d>` 语义污染                   |
| **台词保真**        | 原文**逐字**保留，不许改写、翻译、增删标点                                | 语气通过 `<d>` 外的 delivery 描述表达，不改台词本身 |

**自动化改法**：对全文做三遍正则——

1. 扫 `<d>` 未以 `[语言]` 开头的块 → 补标签；
2. 扫删除 `<d>` 与英文双引号内容后的残留 CJK 字符 → 列出所有位置逐一改写为英文；
3. 扫中文引号 → 替换为英文双引号。

> **注意**：第 2 步**必须排除英文双引号内的内容**，否则画面里的中文招牌（合法）会被误报。实现上先 `re.sub(r"<d>.*?</d>", "", text, flags=S)`，再 `re.sub(r'"[^"]*"', "", ...)`，然后才统计 CJK。

### L1 · 结构合规：生成单元切分与字段骨架

这是**最容易被"看起来很专业"掩盖**的一层。外部稿在这里通常犯**结构性**错误。

#### L1.1 生成单元切分（最重要的一条）

**一条提示词 = 一个生成单元**，不是"一章"、也不是"一场戏"。

| 约束     | 值                                  | 依据          |
| ------ | ---------------------------------- | ----------- |
| 单元时长   | **4–15 秒（整数）**                     | 模型单次生成的时间上限 |
| 单元镜数   | **2–4 镜**（八维版本建议 ≤3 镜；**硬下限 2 镜**） | 见下          |
| 单块字符上限 | **7,000 字符**                       | 模型输入上限      |

**外部稿的典型错误：整章当一个生成单元。** 例如第 2 章 8 镜 + 8 句台词塞进一条提示词——既超时长、又超字数、还会让模型在长上下文里丢失后半段的指令。

**拆单元的下限（必须记住）**：**每个生成单元至少 2 镜。**  
原因：镜头语言审计的"运镜类型数"门槛是 `min(5, max(2, ceil(镜数 / 4)))`——**分母是镜数**。1 镜单元要求 ≥2 种运镜，而一个镜头写不出两种运镜，**结构上必挂**。  
→ 所以拆单元时**不允许拆到只剩 1 镜**。把 4 镜拆成 2+2 可以；拆成 3+1 不行。

#### L1.2 字段骨架

模型有两套官方输出格式，**骨架不同、不能混用**：

**基础模式（T2VA / I2VA / FL2VA / L2VA）—— 三字段**

```
integrated_multimodal_description: [Shot 1] ...

overall_soundscape: ...

non_diegetic_music: ...
```

**全参考模式（Ref2VA）—— 六段式，顺序固定**

```
subject_definitions → summary → retention_analysis →
detailed_description → overall_soundscape → non_diegetic_music
```

骨架层的硬规则：

| 规则                                                  | 说明                                     |
| --------------------------------------------------- | -------------------------------------- |
| 三字段/六段**顺序不可换、不可缺**                                 | 校验器按固定顺序比对，顺序错=报错                      |
| 字段名后**必须跟冒号**                                       | `integrated_multimodal_description:` 等 |
| **`[Shot 1]` 不带时间码**                                | 从 `[Shot 2]` 起才写 `At MM:SS.mmm,`       |
| **风格句在三字段版写在 `[Shot 1]` 之内；在六段式版必须在 `[Shot 1]` 之前** | 这是两种模式最容易被搞混的一处                        |
| 图生视频模式（I2VA/FL2VA/L2VA）**首行必须是对齐指令**，且与官方模板逐字一致     | 见 §3 硬约束                               |
| **三字段版正文不出现 `<Subject N>` 标签**                      | 参考标签只属于 Ref2VA                         |

> **改造时的顺序**：**先切单元，再套骨架。** 骨架套错了，后面所有内容都"无处安放"，改 L2–L3 全是白工。

### L2 · 台词与音画规范

#### L2.1 台词语速可行性（物理约束，改镜头救不回来）

中文台词按 **≈6.5 字/秒** 折算（保守可用 6 字/秒倒推窗口）。**超速的台词，模型会念得含混或吞字，靠调镜头无法解决。**

判定与修法：

| 语速      | 判定                 | 修法              |
| ------- | ------------------ | --------------- |
| ≤ 5 字/秒 | 宽裕                 | 不动              |
| 5–7 字/秒 | 可接受（冷硬风格念白可压到 7–8） | 不动或微调           |
| 7–9 字/秒 | **偏快**             | 优先扩窗口           |
| > 9 字/秒 | **不成立**            | **必须扩窗口**，无替代方案 |

**唯一可靠的修法：给台词加时——画面一句不改，只改时间点（扩后镜的时间码 / 加总时长）。**  
极端情况下可考虑台词跨切点（官方 `<scenetrans>` 语法），**但该语法未逐字核实前不得写入交付稿**（见 §7 第 4 条，这是个真实的踩坑案例）。

#### L2.2 画外音

固定写法：`says in an off-screen voiceover`，且**每个画外音 `<d>` 块之后必须紧跟"嘴唇紧闭"的说明**：

```
The man (S1) says in an off-screen voiceover: <d>[Chinese] …</d> while his lips remain completely closed.
```

> **方法论要点**：小说里的心理描写**优先转成画外音**，不要丢掉，也不要硬塞成动作。  
> **结构性红利**：画外音不与画面动作抢时间轴——画面在演、声音在旁边说，可各用各的节奏，所以画外音几乎不会超速。**对白做不到这一点**（必须与嘴型、与对方反应绑在同一段时间里），这就是对白密集段最容易超速的根因。

#### L2.3 音轨分层（两个独立字段）

| 字段                   | 写什么                                              | 禁止                                                                        |
| -------------------- | ------------------------------------------------ | ------------------------------------------------------------------------- |
| `overall_soundscape` | 环境声、物理动作声、非语言人声（风/雨/脚步/布料/撞击/呼吸…）。**1–4 句**，连成一段 | **绝对不许出现对白、歌唱、画内音乐**——那些属于主字段。也不许**复述**主字段里的台词                            |
| `non_diegetic_music` | **角色听不到、只有观众听得到**的配乐：配器、速度、节奏、力度变化。**1–3 句**     | **禁止抽象情绪词**（`sad`/`tense`/`emotional`/`epic`/`紧张`/`悲`…）。只写"是什么乐器、多快、怎么变化" |

**画内 vs 画外的判定**：角色能听到的音乐（收音机、电视、乐器、酒肆歌女）→ **画内**，写进主字段；只有观众能听到的配乐 → `non_diegetic_music`。

**全静音 / 无配乐**时写 `N/A`（仅在明确要求全静音时）。

#### L2.4 负面约束必须正面写

基础模式**没有 Negative 字段**。所有限制必须**正面措辞**：

- ✗ 不要出现别人 → ✓ 画面里只有他一个人
- ✗ 镜头不要抖 → ✓ 镜头保持绝对稳定

### L3 · 镜头语言八维

**这是"能生成"与"能看"之间的分水岭，也是工作量最大的一层。**

八维必须写在**画面描述字段内部**（三字段版写在 `integrated_multimodal_description` 的镜头文本里；六段式版写在 `detailed_description` 里），**不新增字段**。

| # | 维度       | 必须出现                                                                                                                                                                  | 合格示例                                                                                              |
| - | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 1 | **景别**   | 标准术语之一：`extreme long shot` / `long shot` / `medium shot` / `medium close-up` / `close-up` / `extreme close-up` / `insert shot`。**不要自造词**（`tight close`、`wide-ish` 不算） | `A medium close-up of …`                                                                          |
| 2 | **运镜**   | `The camera …` 句，含**类型 + 幅度 + 速度**                                                                                                                                    | `The camera pushes in with small amplitude at slow speed.`                                        |
| 3 | **角度**   | 机位高度/俯仰角，写出**谁高谁低**                                                                                                                                                   | `shooting from a low angle so the table edge cuts across his chest`                               |
| 4 | **光学**   | 焦段/景深/焦点，写出**观众该看哪里**                                                                                                                                                 | `with a shallow depth of field, the lantern in the background out of focus`                       |
| 5 | **构图**   | 前/中/后景层次 + 主体在画框中的位置                                                                                                                                                  | `he sits in the left third of the frame with the empty bench filling the foreground`              |
| 6 | **轴线**   | 对手戏必须写**屏幕方位**，保证不跳轴                                                                                                                                                  | `she stays on the right of the frame and he on the left, their eyelines meeting across the table` |
| 7 | **光线**   | **逐镜**光位，不是只在风格句里写一次                                                                                                                                                  | `the lamp light falls on one side of his face only`                                               |
| 8 | **画面结果** | 动作/环境在画面上留下的**可见改变**                                                                                                                                                  | `the wine spreads across the wet floor and the nearest men flinch back`                           |

#### L3.1 运镜三要素（官方规范）

**完整运镜 = 运动类型 + 幅度 + 速度。** 中等幅度与正常速度通常省略。

- **运动类型**（官方词表，共 20 种）：`Zoom In/Out`、`Push In`、`Pull Out`、`Pan Left/Right`、`Truck Left/Right`、`Tilt Up/Down`、`Pedestal Up/Down`、`Arc Shot`、`Tracking Shot`、`Static Shot`、`Shake Slightly/Strongly`、`POV`、`Roll Clockwise/Counterclockwise`
- **幅度**：`with small amplitude` / `with large amplitude`（medium 省略）
- **速度**：`at slow speed` / `at fast speed`（normal 省略）
- **`Static Shot` 与 `POV` 不填幅度/速度**

**写法要求**：运镜要写成**镜头内的自然英语动作句**，而不是在句尾堆标签：

```
✓ The camera pushes in with small amplitude at slow speed toward the folded letter in her hands.
✗ The camera then shifts to a slow push in.        ← 一句话里两次运镜，模型会把两个动作平均掉
✗ …, and as he goes the camera pulls out …         ← 运镜句藏在从句里，会被判"缺运镜"
```

> **硬要求**：运镜句必须**以 `The camera` 起句且独立成句**。校验器只认这个开头。

#### L3.2 切镜措辞只有 5 条

```
the camera cuts to
the shot cuts to
the shot transitions to
the shot changes to
the shot switches to
```

**变体（如 `the shot cuts back to`）不合规。** 官方另说明：切镜应带来**新信息**（新主体/空间/状态/视角/时间）；如果只是距离或轻微角度变化，应优先用**运镜**而不是切镜。

#### L3.3 单人戏（无对手单元）的八维替代律

**这是最容易做错的一点。** 双人戏的八维本质是一套**关系学**：轴线是 A→B 的连线，视线是 A 看 B，景别对切靠两人轮流占画面。单人戏把"另一个人"抽走后，**照双人模板硬填的结果是"一个不动的人在一个不动的房间里"——八个格子全填了，但全是空的。**

所以单人戏的八维不是"填满"，是**换发动机**：

| 双人戏的参数        | 单人戏的替代物                                            | 怎么写                                                                         |
| ------------- | -------------------------------------------------- | --------------------------------------------------------------------------- |
| **视线轴**（A→B）  | **空间轴**（场景自身的两个方向，如 `窗 ↔ 门`）                       | 用场景的方向做轴；摄像机永不越线。方位词照旧用 `toward the left/right of the frame`                |
| **对手**（第二个人）  | **光**                                              | 光是唯一在场的另一个角色。每镜都要说出"这一镜的光在干什么"，且必须是**变化**（被切断/被气流带歪/从某处亮起来）                 |
| **正反打**（切另一边） | **焦点对切**（`the focus pulls off A and settles on B`） | 换一次焦点＝换一次注意力，等于剪了一刀但没切镜头。单人戏最省钱、最不崩的"切"                                     |
| **台词**（两人对话）  | **身体**                                             | 画外音必须嘴唇闭合，所以"他在说什么"不能靠嘴。**先由身体说一遍**（喉头吞咽/手指收紧/肩线沉下/呼吸停半拍），**观众先看到身体，再听到声音** |

**两条禁律（单人戏特有）**：

1. **禁"无光的镜头"**——光若没有任务，这一镜就是空的。每镜必须点名一个光源 + 它这一镜做的一件事。
2. **禁"无结果的静止"**——静止镜里必须有一样东西在动，**而且必须被写出来**（雨线/一滴水/灯焰/汗珠/指尖余晖）。**静止镜 ≠ 空镜。**

**两处放开**（双人戏必须收着、单人戏可以撒开）：

- **角度**——双人戏放宽就跳轴，只能稳；单人戏没有轴要保，角度就是**最直接的内心外化工具**：`slightly high` = 被压着（无力/被困）；`eye level` = 中性；`slightly low` = 顶着（压迫/笃定/反守为攻）。**一条完整的"高→平→低"角度弧，就是一个单元的情绪曲线。**
- **景别**——不受对切约束，可以**跳级**：`long shot → close shot → extreme close-up` 一口气推到底。

**总纲：以动写静。** 单人戏的"表演"不在人身上，在**场**上——找**最小的在动的东西**当主角（雨丝/一滴水/灯焰/汗珠），**人反而是那个不动的**。

**双景（现实 ↔ 内心空间）额外一条**：**跨界必须重新立轴。** 现实轴与内景轴没有换算关系；切回现实的那一刻，轴必须立刻回到现实那一条。另：**切入内景时，现实的光必须已消失**（内景通常只有自发光），否则内景会变成"有窗户的山洞"。

### L4 · 跨单元连续性

**单条提示词都合规，合起来照样穿帮。** 必须显式维护三类状态：

#### L4.1 轴线一致性

同一场对话，A/B 双方机位必须留在轴线同侧。做法：**先为每个场景钉一张"平面图"**，写进该场景下**每一个镜头、不允许一次例外**的方位约定；单元级的写法都服从它。

- 对手戏的**正反打，每一镜都要写清屏幕方位**（他的视线朝哪边、她的视线朝哪边），不能只在某一镜写。
- 同一轴线上的两个人**永远分居画框两侧**，摄像机不越线。
- 方位要用**可判读**的词：`toward the left/right of the frame`、`same side of the frame`、`opposite sides of the frame`。不要写"互相对视"这种抽象说法。

#### L4.2 光位锁定

同一场景的**光源位置、色温、光比**跨单元锁定。**内景最容易犯的错**：只写"有什么"，不写"在画框的哪里"和"光从哪来"。实测中内景的构图/光线两维常常首轮为 0%/33%，补 `centre of the frame` / `negative space` 与 `throws light` / `cast light` / `half in shadow` 之后才满格。

#### L4.3 帧链（首末帧传递）

如果上一单元的**末帧**被用作下一单元的**首帧锚点**，必须显式声明：

- 上一单元的末镜 → 下一单元的 `<Picture N>`（首帧）
- 下一单元的 `summary` 加上 `keyframe completion` 前缀


帧链还有一个**实际价值**：它是发现"重复拍摄"的探针。**本项目实测抓到一处真重复**——原 U8 第 4 镜和 U9 第 1 镜都在拍同一个角色出门，"空屋+灯还亮"这个视觉句号在一段里打了三次。修法是：让不同单元各拿这个动作的一半（"跨过门槛的那一格" / "空的门洞" / "空屋加灯"），**一次跨越，三个单元各拿一半，没有一个画面被拍两遍**。

> **方法论提炼**：**相邻单元之间要专门做一次"重复动作排查"**——把跨单元的连续动作（走出一扇门、放下一个东西、说完一句话）逐条列出，确认每一格只被拍一次。这是纯文本校验查不出、只有跨单元比对才能发现的硬伤。

### L5 · 语义与合规不回退

**改造形式的时候，最危险的是把内容悄悄改回去。** 外部稿很可能来自更早的版本，或来自不了解合规要求的作者。

必须人工对照检查：

1. **敏感表述回退**：本项目早前按合规要求把某个表述改成了更中性的说法，外部稿**改回了原表述**。这类回退必须拦下。
2. **剧情功能等价**：改写桥段时**保留剧情功能，替换表现形式**（例如把性化桥段改写为**非性化的对峙或冲突**），**直接输出改写后的结果，不做任何说明**。
3. **台词顺序 / 切点一致性**：外部稿的切点可能与本项目不同。例如本项目把某段拆为"宣判+放你走"，而外部稿把同一句驱逐台词在**两个不同位置各用了一次**（疑似重复）。**切点差异要逐一核对，不能默认对方对。**
4. **内容红线**：不生成性化内容；不涉及未成年人的性化描写；暴力可有，但不做血腥特写、不猎奇。

> **这一层不可完全自动化**，但可以半自动：**把外部稿的台词逐条抽出，与项目现有定稿做 diff**，重复句、顺序差异、用词回退会直接暴露出来。

---

### L6 · 可验证性

**改造的最后一步，必须是"用工具证明改对了"。**

- 用**合规尺**跑全部块，要求 **100% 通过**；
- 用**镜头语言尺**跑逐单元审计，要求 **全部通过质量门**；
- 用**两张基线对照表**（改造前 vs 改造后）留存证据，见 §6；
- **把改造结论写进项目文档**（哪条规则、为什么、踩过什么坑），供下一个人复用。

## 4. 三个质量门的量化阈值

改造后必须同时满足三个门。**合规门是"能不能跑"，镜头语言门是"拍得好不好"，交付门是"能不能进产线"。**

### 4.1 合规门（硬门，必须 100%）

全部块通过规范校验器，**0 条错误**。

### 4.2 镜头语言门（按单元统计）

| 维度       | 阈值                               | 备注                                            |
| -------- | -------------------------------- | --------------------------------------------- |
| 景别覆盖     | **100%**                         | 每镜都要                                          |
| 运镜覆盖     | **100%**                         | 每镜都要                                          |
| 角度覆盖     | ≥ 40%                            |                                               |
| 光学覆盖     | ≥ 30%                            |                                               |
| 构图覆盖     | ≥ 50%                            |                                               |
| 轴线覆盖     | ≥ 30%                            | **有两人以上对手戏时强制**；单人戏可用空间轴替代                    |
| 光线覆盖     | ≥ 40%                            |                                               |
| 画面结果覆盖   | ≥ 60%                            |                                               |
| 静止镜占比    | **≤ 40%**                        | **按镜数缩放为绝对个数**：允许 `max(1, ceil(0.40 × 镜数))` 个 |
| 单一运镜占比   | ≤ 35%                            | 同样按镜数缩放。连续两镜不许同类型；`Push In` 一单元最多 2 次         |
| 运镜类型数    | ≥ `min(5, max(2, ceil(镜数 / 4)))` | **分母是镜数** → 1 镜单元结构上必挂                        |
| 运镜三要素完整率 | 100%                             | 运镜句必须含幅度+速度（`Static Shot`/`POV` 除外）           |

**附加剪辑规则**（不体现在覆盖率里，但直接影响观感）：

- 景别不许**连续三镜**同级；推荐 `远 → 中 → 近` 递进，或**故意跳级**（`远 → 特写`）制造冲击。
- 连续两镜不许用同一运镜类型。

### 4.3 交付门（文本层）

| 项                        | 阈值                                                |
| ------------------------ | ------------------------------------------------- |
| 单块字数                     | ≤ 7,000 字符（**实测：八维全开比纯画面描述费字约 +47%**，所以字数会真正成为约束） |
| `subject_definitions` 条数 | 条数越多字数越紧。**超过 7 条的单元，3 镜即上限**                     |
| 台词速速                     | 全部 ≤ 7 字/秒（>9 字/秒必须扩窗口）                           |
| `summary` 任务类型           | 与实际素材角色一致，无冗余类型                                   |

**字数不够时的压缩优先级（按有效性排序）**：

1. **`subject_definitions` 里写过的外形/场景，镜头里只用标签指代，不重复抄写**（最有效，单单元可省百余字符）；
2. `retention_analysis` 不复述 `subject_definitions` 的内容，只写"保留了什么 + 本单元新增的变化"；
3. 删冗余定语（`about a dozen square wooden tables` → `square tables`）；
4. 对白密集段**优先保台词**（台词必须逐字完整，字数不能省），八维只保留轴线 + 景别 + 运镜，其余五维分配到别的镜头——**单元级达标，不是每镜都要八维全开**。

## 5. 标准改造流程（六步 SOP）

```
第 1 步  资产盘点与冻结
第 2 步  建尺子，跑基线（改造前必须先量一遍）
第 3 步  结构改造：切单元 + 套骨架（L1）
第 4 步  逐层修复：L0 → L2 → L3 → L4（按成本从低到高）
第 5 步  语义比对：L5（与项目现有定稿 diff）
第 6 步  验收与留证：L6（两把尺子 + 证据表）
```

### 第 1 步 · 资产盘点与冻结

- 把外部稿**冻结**为只读基线（不要边改边丢原件），另存工作副本。
- 统计：单元数、镜数、总时长、台词条数、每条台词字数与所在窗口。
- 确认模型与模式：**基础三字段**还是**全参考六段式**？（决定骨架）
- 建立**术语/词表快照**：把官方运镜词表、切镜 5 句、标记值集合固定下来，后续全靠它。

### 第 2 步 · 建尺子，跑基线

**改造前必须先量。** 否则你无法证明改造有效，也无法知道哪一层问题最严重。

- 跑**合规尺**（记为基线 A）：得到错误条数。
- 跑**镜头语言尺**（记为基线 B）：得到八维覆盖率与未达标项。
- **把两个基线存档**——这是最终交付证据的一半。

### 第 3 步 · 结构改造（L1）

- **切单元**：按 2–4 镜 / 4–15 秒 / ≤7,000 字符切；**禁止切到 1 镜**。
- **套骨架**：按模式套三字段或六段式；检查顺序、`[Shot 1]` 时间码、风格句位置。
- **重排时间码**：镜号连续、时间码严格递增、个数 = 镜数 − 1。

### 第 4 步 · 逐层修复

严格按 L0 → L2 → L3 → L4 顺序：

1. **L0**：正则批量补 `<d>[Chinese]`、清 CJK、清中文引号、绑 ID。
2. **L2**：核台词语速（超速的扩窗口）；核音轨分层；核对画外音写法；负面约束正面化。
3. **L3**：逐镜补八维。**这是主要工作量**——按 §L3 逐维写，先定轴线、再排景别、再定角度光学、再补构图三层、最后补画面结果。
4. **L4**：跨单元对轴线/光位/帧链；**做一次"重复动作排查"**。

### 第 5 步 · 语义比对（L5）

- 台词逐条 diff（重复句、顺序差异、用词回退）。
- 敏感表述回退检查。
- 剧情功能等价性确认。

### 第 6 步 · 验收与留证

- 跑**合规尺**：要求 100% 通过（对照基线 A）。
- 跑**镜头语言尺 -u --gate**：要求全部单元通过（对照基线 B）。
- 填写 §8 验收清单。
- 生成**改造前后对照表**（§6 格式），归档。

### 6.1 规范合规（合规尺）

| 对象                  | 结果                                      |

| 对象      | 通过单元 / 总单元           |
| ------- | -------------------- |
| 本项目原始稿  | **0 / 17**           |
| 八维升级后合集 | **30 / 30**（双版本各自计数） |

**其他关键指标：**

| 指标    | 原始稿                  | 升级后                 |
| ----- | -------------------- | ------------------- |
| 镜数    | 55                   | 78                  |
| 静止镜占比 | 26/55 = **47%（超上限）** | 24/78 = **31%（合格）** |
| 未达标项  | **8 项**              | **0 项**             |

### 6.3 从这张表能读出三件事

1. **原始稿是"合规但平铺"的典型**：17/17 通过规范，却 0/17 通过镜头语言门——**运镜 100% 却在角度/光学/构图上几乎为零**。这说明"每镜都有运镜"远不等于"镜头语言丰富"。
2. **外部稿连合规都没过**：运镜、角度、光学、构图、轴线、光线**六维全部 0%**。它连"每镜有运镜"这条最基本的都没做到（运镜 0%）。
3. **"画面结果 75%"是外部稿唯一的亮点**，说明作者会写"动作留下什么痕迹"，但不会写"怎么拍"——**这正是"分镜思维"与"镜头语言思维"的差别**。

### 6.4 一个反直觉的实测发现

本项目改造过程中，工具抓到的**最严重问题不是风格问题，而是会被模型直接拍错的硬错**：

| 问题                                                         | 性质       |
| ---------------------------------------------------------- | -------- |
| 用了非官方切镜措辞 `the shot cuts back to`                          | 措辞不合规    |
| 某镜漏写角度——**"高→平→低"角度弧的中间那一点漏了，弧就只剩两头**                      | 结构性缺失    |
| 某镜运镜句没独立成句（藏在 `…, and as he goes the camera pulls out…` 里） | 会被判"缺运镜" |
| 某单元 `non_diegetic_music` 残留抽象情绪词 `tense`                   | 内容违规     |
| **跨单元真·重复拍摄**（同一动作被两个单元各拍一遍）                               | 纯文本校验查不出 |

> **结论**：改造的价值不在于"把句子写漂亮"，而在于**把模型会拍错的地方全部堵掉**。

## 7. 常见失败模式与修法（含外部集实测病灶）

按**从死到轻**排序。前 4 条是"直接不可用"，后 2 条是"能用但拍不好"。

### ① 台词无语言标签（**每条都错**）

- **病灶**：21 条台词全部写成 `<d>已经三天三夜了。</d>`，缺 `[Chinese]`。
- **后果**：模型无法判定语言，多语种场景下会张冠李戴。
- **修法**：正则批量补 `<d>[Chinese] …</d>`。**注意这是"每条都错"型错误，一定要全量扫，不要抽查。**

### ② 框架描述里混中文

- **病灶**：`low-angle仰拍` / `俯拍` / `谄笑` / `媚态` / `艳丽` 等直接写进英文句；角色名写成中文。
- **后果**：模型对中文方位/情绪词的解析不可靠，且**中文出现在框架层本身就是违规**。
- **修法**：删除 `<d>` 与英文双引号后的残留 CJK 全量替换为英文；人名转写并绑定 ID；中文方位词换成官方运镜/角度术语。

### ③ 整章当一个生成单元

- **病灶**：第 1 章 7 镜 + 台词 5 句、第 2 章 8 镜 + 台词 8 句，各塞进一条提示词。
- **后果**：超时长、超字数、指令在长上下文中被稀释，后半段基本失控。
- **修法**：按 2–4 镜 / 4–15 秒切单元。**切完必须节数——不允许出现 1 镜单元。**

### ④ 运镜无幅度速度 / 一句话两次运镜

- **病灶**：14 句 `The camera …` 全部缺 `with small/large amplitude at slow speed`；另有 `The camera then shifts to …` 这类双动作句。
- **后果**：模型会把两个动作"平均掉"，得到一个不想要的中间态；缺幅度速度则节奏全丢。
- **修法**：按 §L3.1 补三要素；**拆句**——一句话只允许一个运镜动作。

### ⑤ 内景只写"有什么"，不写"在哪里、光从哪来"

- **病灶**：内景单元的构图/光线两维常常首轮 0%/33%。
- **后果**：画面平，没有视觉重点，没有光位关系。
- **修法**：补 `centre of the frame` / `negative space`（构图）+ `throws light` / `cast light` / `half in shadow`（光线）。

### ⑥ 单镜单元 / 拆到 1 镜

- **病灶**：字数超限时想把单元拆小，拆成 3+1 或 2+1，出现 1 镜单元。
- **后果**：**结构上必挂**——运镜类型数门槛 `min(5, max(2, ceil(镜数/4)))` 的分母是镜数，1 镜要求 ≥2 种运镜。
- **修法**：拆成 **2+2**；实在超限就**压字数而不是拆单元**（§4.3 给了压缩优先级）。

### ⑦ 用了未核实的官方语法（**最容易踩的隐性坑**）

- **病灶**：为解台词超速问题，想用 `<scenetrans>` 让台词跨切点。
- **风险**：**该语法未在官方文档中逐字核实**。
- **铁律**：**没核实的东西不写进交付稿。** 宁可扩时长（画面一句不改），也不用未核实的语法。这条已两次拦住错误决策。
- **通用化**：**任何"我印象里官方支持"的语法，未在官方文档逐字确认前，一律按不支持处理。**

## 附：本方法论的自我限定

1. **质量门阈值是本项目自定，不是官方硬性要求。** 官方只规定"怎么做"（格式、词表、语法），不规定"做多少"（覆盖率的百分比）。阈值可随项目调整，&#x4F46;**"两把尺子分开量"的原则不变**。
2. **L5 语义不回退无法完全自动化**。可以做半自动 diff（台词逐条比对），但敏感表述判断需要人。**不要把合规判断交给脚本。**
3. **未核实的官方语法一律不写进交付稿**（§7 第 7 条）。这是本方法论里**最贵的一条经验**，它来自两次真实的决策拦截。
4. **本文只解决"提示词可用性"，不解决"内容创作质量"。** 剧本好不好、分镜合不合理，是另一个问题。本文的边界是：**给定一份内容，让它能被模型正确、稳定、有节奏地拍出来。**
