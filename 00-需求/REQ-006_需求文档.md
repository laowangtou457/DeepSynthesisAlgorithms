## 1 项目背景

### 1.1 项目起因

拟面向互联网信息服务场景，提供**生成合成类（文本合成）算法**服务，并按监管要求完成**算法备案**。

### 1.2 核心目标

| 目标 | 说明 |
| --- | --- |
| 主目标 | 完成生成合成类算法备案 |
| 技术目标 | 建成可运行、可审计、可追溯的文本合成服务 |
| 合规定位 | 采用「B 级」方案：自部署开源模型 + 二次开发 + 安全护栏 + 内容标识 |

### 1.3 关键前提结论（已澄清）

| 编号 | 结论 | 说明 |
| --- | --- | --- |
| C-001 | B 级可完成算法备案 | 备案审查的是「是否对公众提供生成合成类算法服务」+ 安全能力 + 材料完整性，非模型是否自训 |
| C-002 | 模型采用开源自部署 | 不购买第三方模型服务；选用 Qwen2.5-7B-Instruct（Apache 2.0，商用无限制） |
| C-003 | 现有 1×24G GPU 满足文本备案 | 7B BF16 舒适；14B 需量化；QLoRA 微调 7B 可行 |
| C-004 | 硬盘建议 300–500GB SSD | 模型权重 + 环境 + 数据集 + 检查点 + 余量 |
| C-005 | 周期 4–8 周至可提交 | 瓶颈在数据准备与审核等待，技术开发最快 |
| C-006 | 文生视频为潜在扩展方向 | 硬件门槛约为文本的 3–5 倍，见 §7 |

## 2 范围定义

### 2.1 本期范围（In Scope）

- 文本合成算法服务（生成 / 摘要 / 改写 / 抽取 四类任务）
- 算法备案材料的编制
- 安全护栏与生成内容标识的技术实现
- 提示词资产体系
- 部署与运维方案

### 2.2 暂不纳入（Out of Scope）

- 文生图、文生视频、语音合成（列为后续扩展，见 §7）
- 从零训练基座模型
- 面向 C 端的大规模商业化运营
