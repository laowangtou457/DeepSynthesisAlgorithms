# SYS-Q4 决策支持 · 下游 AI 视频工具的对接方式与标识协作

| 项目 | 内容 |
| --- | --- |
| 文档编号 | SYS-Q4-DS-001 |
| 版本 | V1.1 |
| 日期 | 2026-10-12 |
| 关联需求 | SYS-Q4（✅ 已确认）、SYS-009、SYS-016、SYS-017、**SYS-018、SYS-019**、SW-014、SW-025、SW-026 |
| 文档定位 | SYS-Q4 的候选方案对比与决策支持材料，供选型评审使用 |

> **本文档目的**：SYS-Q4 决定 SW-014（视频标识提示）的实现方式。本系统只输出**文本**（分镜提示词集），最终对外传播的却是**视频**，标识义务因此跨主体。本文给出 **5 个对接方案 + 1 个载体变体**，并给出三层标识协作机制与推荐组合，供决策。

---

## 决策结论（2026-10-12 已确认）

| 决策项 | 结论 |
| --- | --- |
| SYS-Q4-1 下游工具范围 | 客户可能使用**全部主流视频生成模型**（即梦 / 可灵 / Seedance / MiniMax H3 等）→ 采用「**通用规范 + 多模型适配层**」，不针对单一工具定制；新增模型以配置接入，不改代码 |
| SYS-Q4-2 对接方式 | **不 API 直连**。系统定位为**上游内容生产方**，只交付产物，**与下游平台脱钩**——不代调、不接触成片、不托管下游密钥 → **排除方案 D** |
| SYS-Q4-3 标识协作 | **不要求客户回传成片**。由本系统完成**自身合规自检**，并在交付时出具**合规声明**（含标识方法/样式说明、用户标识义务与使用责任提示、禁止删改告知） |
| 选定组合 | **方案 B（标准化提示词包，基线）+ 方案 A（文件级导出，兜底）+ 方案 C 的标识素材与交互增强**；方案 E 列为远期，不做 |
| 新增系统级需求 | **SYS-018 上游脱钩与产物交付原则**、**SYS-019 交付合规声明与自检**；SYS-016 描述细化 |
| 对应软件级需求 | SW-007（增加多模型适配）、**SW-014 改写为「产物标识传递与合规声明」**、新增 **SW-025 多模型提示词适配**、**SW-026 交付合规声明与自检**、SW-I04 改为「产物交付包接口（不直连下游）」 |
| 模型适配优先级 | 后续由 **SYS-Q17** 确定为：**MiniMax H3（P0）> Seedance（P0）> 即梦（P1）> 可灵（P2）> 其余（P3）** |
| 导出文件标识 | 后续由 **SYS-Q16** 补充：导出文件本身须含显式标识（标识办法 §4 末段）→ 落于 SW-022 |

### 由此确定的交付形态：**交付四件套**

1. **分镜提示词集** —— 通用规范 + 所选目标模型的适配格式
2. **AIGC 元数据块** —— GB 45438—2025 附录 E 规范格式（`Label` / `ContentProducer` / `ProduceID` / `ContentPropagator` / `PropagateID`）
3. **标识素材包** —— 片头卡 / 角标素材，满足 §5.4：位于画面边或角、文字高度 ≥ 画面最短边 5%、正常播放速度下持续 ≥2s
4. **交付合规声明** —— 标识方法/样式说明 + 标识落地义务与使用责任提示 + 禁止删改隐匿标识告知 + 适用人群场合用途

> **脱钩原则的注意点**：因为不与下游平台对接，本系统**无法验证**最终视频是否按标识素材落地。该风险通过三层机制缓释——① 交付合规声明与用户服务协议明确客户标识义务（《标识办法》§8、§9 与 §10 为依据）；② 交付物自带元数据块与标识素材，客户"照做即合规"；③ 最终传播平台按 §6 核验并加提示标识兜底。**同时，系统内不得存在任何去标识功能**（§10 禁止为他人去除标识提供工具或服务）。

## 3 标识的法律依据与责任链

### 3.1 法规要点映射

| 依据 | 要求 | 对本项目的含义 |
| --- | --- | --- |
| 《标识办法》§4(四) | 视频：起始画面与播放周边加显著提示标识，可在末尾与中间适当位置加 | 视频侧标识的**具体形态**（交付下游客服用） |
| 《标识办法》§4 末段 | 提供下载/复制/导出功能时，应确保**文件中含有满足要求的显式标识** | 本系统导出文本时，导出文件须带显式标识（对应 SYS-017） |
| 《标识办法》§5 | 文件元数据中添加隐式标识：属性信息 + 服务提供者名称/编码 + 内容编号 | 文本侧隐式标识（SW-013）；也是视频元数据的字段来源 |
| 《标识办法》§6 | 传播平台核验元数据→在内容周边加显著提示标识；未核验到但用户声明/检测到痕迹也要加 | **最终传播环节有平台兜底**，降低本系统兜底压力 |
| 《标识办法》§8 | 服务提供者应在**用户服务协议**中明确标识方法、样式等规范，并提示用户理解 | 协议条款是法定交付物，必须有 |
| 《标识办法》§9 | 用户申请无显式标识内容时，可在协议**明确用户标识义务与使用责任**后提供，须留存日志 ≥6 个月 | **协议式责任转移的法律依据**——本方案 L3 层的核心 |
| 《标识办法》§10 | 任何组织个人不得恶意删除、篡改、伪造、隐匿标识；**不得为他人实施上述行为提供工具或服务** | 本系统**禁止**提供任何「去除/关闭 AI 标识」功能 |
| 《标识办法》§12 | 履行算法备案、安全评估时须提供标识相关材料 | 备案材料需含标识方案说明 |
| GB 45438—2025 §5.4 | 视频显式标识：文字须含「人工智能」或「AI」+「生成」和/或「合成」；位于起始画面（可加末尾/中间）；位于画面**边或角**；文字高度**≥画面最短边 5%**；正常播放速度下**持续 ≥2s** | 交付客户的「标识素材」必须满足的硬指标 |
| GB 45438—2025 §5.5/§5.6 | 虚拟场景、交互场景界面标识要求 | 小程序/网页界面的显著提示（SW-012） |
| GB 45438—2025 §6.1 + 附录 E（规范性） | 文件元数据隐式标识字段名含「AIGC」，值为 JSON 字符串，含 Label / ContentProducer / ProduceID / ReservedCode1 / ContentPropagator / PropagateID / ReservedCode2；**仅保留一份** | **元数据块的具体格式**，方案 B 直接采用 |

### 3.2 标识责任链

```
① 本系统（生成合成服务提供者 · 文本）
   │  交付：分镜提示词集（带文本显式 + 隐式标识）
   ↓
② 客户（内容使用者 / 制作方）
   │  用提示词喂下游工具 → 得到视频
   ↓
③ 下游 AI 视频工具（生成合成服务提供者 · 视频）
   │  本身对视频负有标识义务（依其自有合规义务）
   ↓
④ 内容传播平台（抖音/视频号/小程序等 · 内容传播服务提供者）
   └  §6：核验元数据 → 在内容周边添加显著提示标识
```

**两条关键结论：**

1. **视频侧标识义务首先落在下游视频工具**——它才是视频的「生成合成服务提供者」。本系统的法定义务是**文本侧标识 + 协议告知 + 提示传递**，不是替下游打标。这个定位要写进备案材料，避免自我加码。
2. **但本系统不能完全不作为**——§8 要求协议写明标识规范，§9 的责任转移以「协议明确 + 日志留存」为前提，§10 禁止提供去标识工具。所以本系统必须提供**可落地的标识素材与指引**。

### 3.3 三层标识协作机制（所有方案共用）

| 层 | 内容 | 属性 |
| --- | --- | --- |
| **L1 文本侧自主落地** | 梗概/剧本/分镜脚本/提示词的显式标识（起始或末尾）+ 隐式元数据标识 + 交互界面显著提示 | **法定，必须**（SW-012/013） |
| **L2 传递与素材** | 提示词包携带 AIGC 元数据块；随包交付**标识素材**（片头卡/角标 PNG，满足 §5.4 的 5% 字高与 ≥2s 时长）+ 标识建议文案 | 推荐（SW-014 主体） |
| **L3 协议与留痕** | 用户服务协议写明标识方法/样式规范与用户标识义务；导出留痕日志 ≥6 个月；提供《标识落地指引》图文说明 | **法定**（§8/§9） |

## 4 候选方案

### 方案 A｜文件级交付（零对接）

| 项 | 内容 |
| --- | --- |
| 对接形态 | 导出结构化提示词包（TXT / JSON / CSV / Markdown 分镜表 / Excel），客户人工投入下游工具 |
| 标识协作 | L1 全量 + L2 素材与文案随包 + L3 协议 |
| 外部依赖 | **无** |
| 实现量 | 小（复用 SW-017 / SW-022 导出链路） |
| 合规覆盖 | 文本侧 100%；视频侧靠客户自觉，**无证据链** |
| 主要风险 | 客户不落地 → 依赖传播平台 §6 兜底 |
| 适用 | 起步阶段、客户工具不固定、快速上线 |

### 方案 B｜标准化提示词包 + 元数据传递（Schema 化）★ 推荐基线

| 项 | 内容 |
| --- | --- |
| 对接形态 | 定义《分镜提示词交付规范 v1》：镜头级结构化字段 + 携带 AIGC 元数据块；提供多格式适配器（通用 JSON / 分镜表 / 各主流工具批量导入格式） |
| 关键交付物 | ① 提示词包 schema；② GB 45438 附录 E 格式元数据块；③ 多格式导出适配器 |
| 标识协作 | L1 + **L2（元数据块随包下发，下游若支持则自动落地，不支持则人工粘贴）** + L3 |
| 外部依赖 | 无（schema 与导出器均本系统自控） |
| 实现量 | 中（schema + 校验 + 多格式导出 + 适配器） |
| 合规覆盖 | 文本侧 100%；视频侧**有载体、可传递、可核验** |
| 主要风险 | 低 |
| 适用 | **所有场景的公共底座**，与 A/C/D 均可叠加 |

**镜头级字段（草案）**

| 字段 | 说明 |
| --- | --- |
| `shot_id` | 镜头唯一编号（与内容编号体系一致） |
| `scene_no` / `shot_no` | 场景号 / 镜号 |
| `shot_size` | 景别（远景/全景/中景/近景/特写） |
| `camera` | 机位与运镜（推/拉/摇/移/跟/升降） |
| `duration_ms` | 时长 |
| `prompt_zh` | 中文画面提示词 |
| `prompt_en` | 英文画面提示词（多数下游工具对英文更敏感） |
| `negative_prompt` | 负向提示词 |
| `style_ref` | 风格锚点（统一风格串，保证跨镜头一致性） |
| `character_ref` | 角色锚点（角色外观一致性） |
| `ref_image` | 参考图（可选） |
| `aigc_meta` | AIGC 元数据块（见下） |

**AIGC 元数据块（依 GB 45438—2025 附录 E，规范性）**

```json
{"AIGC": {"Label": "1", "ContentProducer": "{{PROVIDER_NAME}}/{{PROVIDER_CODE}}", "ProduceID": "FR-PK-YYYYMMDD-XXXXXXXX", "ReservedCode1": "", "ContentPropagator": "{{PROVIDER_NAME}}/{{PROVIDER_CODE}}", "PropagateID": "FR-PK-YYYYMMDD-XXXXXXXX", "ReservedCode2": ""}}
```

> 说明：首次写入时按标准要求 `ContentPropagator` = `ContentProducer`、`PropagateID` = `ProduceID`；文件中**仅保留一份**元数据隐式标识。
> **字段取值规则与内容编号编码规则已细化定义**，见 `01-架构设计/分镜提示词交付规范-v1.2.md` §5.2（含 `<企业码>-<类型码>-<YYYYMMDD>-<8位短码>` 编码规则；`{{PROVIDER_CODE}}` 为待回填占位，见该规范 §13 **NT-02**）。

### 方案 C｜半自动交付（深链 / 批量剪贴板 / 标识贴片）

| 项 | 内容 |
| --- | --- |
| 对接形态 | ① 单镜头一键复制、② 批量剪贴板序列、③ Deep link 预填（下游工具支持时）、④ 导出「图文分镜脚本」（提示词 + 参考图 + 标识说明）供剪辑软件使用 |
| 标识协作 | L1 + L2 + **本系统生成「标识贴片素材包」**（片头卡 / 角标 PNG，符合边角位置、字高 ≥5%、展示 ≥2s） |
| 外部依赖 | 下游是否支持深链（多数不支持 → 自动降级为剪贴板，不影响可用性） |
| 实现量 | 小—中（以前端交互为主） |
| 合规覆盖 | 同 B，且**显著提升客户实际落地率** |
| 适用 | B 的体验增强层，非独立方案 |

### 方案 D｜API 直连下游生成（闭环加标）

| 项 | 内容 |
| --- | --- |
| 对接形态 | 本系统作为编排方调用下游视频工具开放 API（提交任务 → 轮询/回调 → 回收成片），成片回本系统后统一加标识再交付 |
| 标识协作 | L1 + L2 + **闭环加标**：用 ffmpeg 加显式标识（满足 GB 45438 §5.4）+ 写入元数据块；证据链完整 |
| 外部依赖 | 下游须有开放 API 且商务可谈；生成按次计费（成本转嫁客户） |
| 实现量 | 大（任务编排 + 对象存储 + 转码 + 回调 + 失败重试） |
| 合规覆盖 | 最优（本系统实际控制成片） |
| **关键风险** | 一旦本系统代客户调用视频 API 并交付成片，事实上构成**向公众提供文生视频服务** → **可能触发文生视频算法备案义务，与当前「只做文生文备案」范围冲突** |
| 规避口径 | a) 仅下发「编排指令/跳转」，由客户**自有账号与密钥**执行，本系统不接触成片（推荐）；b) 将视频生成定性为客户自行使用第三方服务，本系统仅交付提示词；**不建议**本系统托管成片并对外交付（除非同步扩设备案范围） |
| 适用 | 客户强需求一站式体验，且法务确认口径 |

### 方案 E｜本地自部署视频模型（远期）

| 项 | 内容 |
| --- | --- |
| 对接形态 | 本地部署 Wan2.1 / CogVideoX 等，端到端自主 |
| 标识协作 | 全链路自控 |
| 前置条件 | 需 **48G+ 显存**（现有 1×24G 不足）；**必然触发文生视频备案** |
| 结论 | 本期**不做**，列为 P3 远期方向 |

### 方案 F｜MCP / 工具化对接（B 的载体变体）

把「分镜提示词生成」封装为 MCP Server / 编辑器插件，被下游 Agent 平台或剪辑软件**主动调用**；标识以结构化字段随返回值下发，由调用方落地。属方案 B 的另一种交付载体，不单独成方案。

## 6 推荐组合

```
本期基线：方案 B（标准化提示词包 + 元数据传递）
         + 方案 A 作为导出格式兜底（B 的导出即含 A）
         + 方案 C 作为体验增强（P1）
可选升级：方案 D —— 仅当客户强需求一站式，且法务确认「客户自有账号执行」口径
远期：   方案 E / F
```

**理由**：B 的方案不依赖任何特定下游工具，是本系统完全自控的一层；它同时为 A/C/D 提供公共载体（元数据块与 schema），后续无论走哪条路都不用返工。D 的风险不在技术，在**备案范围的重新界定**，必须先过法务。
