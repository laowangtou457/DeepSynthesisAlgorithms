## 2 功能需求

> **字段说明（`RQ5-01`）**：本节六张表统一为 **12 列**——「编号 / 需求名称 / 描述 / 输入 / 处理 / 输出 / 异常 / 验收标准 / 状态」为原有九列，「**来源 / 优先级 / 关联**」三列为本次补齐。补齐后每条需求均满足 `00-需求/README.md` §四 的**八项必备字段**（编号 / 需求名称 / 描述 / 来源 / 优先级 / 验收标准 / 状态 / 关联）。
> **来源**列填**上位依据**——优先填承接的**系统级条目**（`SYS-xxx`，见 `REQ-004`）；确无上位条目的技术性需求填**架构约束**（`REQ-006` §5 技术选型）或 `REQ-006` 的项目级条目（`F-xxx` / `N-xxx`），**并在该处注明**——「无对应 SYS 条目」本身即为待议 A（主登记与层级条目的映射）的实证，如实暴露、不强行挂靠。
> **状态**取值见 `00-需求/README.md` §四。本层条目现为「**内部确认**」（需求已内部确认、尚未开工）或「**开发中**」（`SW-004`~`SW-008`：其**提示词模板资产已建/在建**，但**服务化实现未开始**）。⚠️ **「模板建成」不等于「需求完成」**——需求验收须以**服务化跑测**为准（`RQ5-03`）。
> **分组与编号（`RQ5-11`）**：本节按**主题分组**组织，编号按建立顺序分配，故**组内编号不连续**。各组含编号如下——2.1 `SW-001`~`SW-003`；2.2 `SW-004`~`SW-008`、`SW-023`、`SW-025`；2.3 `SW-009`~`SW-011`、`SW-017`；2.4 `SW-012`~`SW-014`、`SW-026`；2.5 `SW-015`、`SW-016`、`SW-019`；2.6 `SW-018`、`SW-020`~`SW-022`、`SW-024`、`SW-027`、`SW-028`。
