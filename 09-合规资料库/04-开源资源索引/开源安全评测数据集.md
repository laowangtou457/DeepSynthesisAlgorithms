# 开源安全评测数据集索引

> **用途**：为 `02-生成内容测试题库` 与 `03-拒答题库` 的扩充提供可改造的外部来源。
> **原则**：开源数据集**不能直接用**——它们的安全分类体系与 GB/T 45654 附录 A 的 31 类并不一致，必须**重新归类到国标 31 类**，并按本项目场景改写。
> 编制 2026-10-12。**规模、许可证以各仓库当前页为准，使用前须重新核实。**
>
> ℹ️ **⚠️ 重要说明（2026-10-12 规模扩充后补记）**：**本次把生成内容题库做到 2,020 题、拒答题库做到 585 / 509 题，并未使用本文件列出的任何开源数据集**，
> 而是由 `../06-构建工具/expand_banks.py` 与 `expand_refusal.py` 按「细分主题 × 提问风格」矩阵自建。
> 原因：这些数据集需逐个核实许可证，且其**原始 response 本身可能含不安全内容**，改造成本与合规风险都高于自建。
> **本文件继续作为「若未来采用开源数据集时的唯一判定依据」保留**——尤其 §四 使用红线，仍然有效且必须遵守。

## 一、中文安全评测数据集清单

### 1.1 Safety-Prompts ★ 主推荐（规模最大）

| 项 | 内容 |
| --- | --- |
| 来源 | 清华大学 COAI 课题组 |
| 仓库 | `github.com/thu-coai/Safety-Prompts` ／ HuggingFace `thu-coai/Safety-Prompts` |
| 许可证 | **Apache-2.0** |
| 规模 | 约 **100,000** 条 prompt–response 对（文件总大小约 68.5 MB） |
| 论文 | arXiv:2304.10436《Safety Assessment of Chinese Large Language Models》 |

**七个典型安全场景**（各 10,000 条，共 70,000）：

| 英文类目 | 中文 | 可映射到国标 |
| --- | --- | --- |
| Insult | 脏话侮辱 | A2-01 ~ A2-09 |
| Unfairness and Discrimination | 偏见歧视 | A2-01 ~ A2-09 |
| Crimes and Illegal Activities | 违法犯罪 | A1-08 |
| Physical Harm | 身体伤害 | A1-06 / A4-01 |
| Mental Health | 心理健康 | A4-01 |
| Privacy and Property | 财产隐私 | A4-05 / A4-06 |
| Ethics and Morality | 道德伦理 | A1 系列 |

**六个指令攻击场景**（各 5,000 条，共 30,000）：

| 英文类目 | 中文 | 说明 |
| --- | --- | --- |
| Goal Hijacking | 目标劫持 | 用无关指令诱导模型偏离安全约束 |
| Prompt Leaking | Prompt 泄漏 | 探测系统提示词 |
| Role Play Instruction | 赋予角色后发指令 | 强制模型扮演恶意角色 |
| Unsafe Instruction Topic | 不安全的指令主题 | 直接索取危险内容 |
| Inquiry with Unsafe Opinion | 带有不安全观点的询问 | 把有害观点包装成中性提问 |
| Reverse Exposure | 反面诱导 | 利用安全机制本身暴露漏洞 |

> **本项目用法**：六类**指令攻击**对本项目价值极高——本产品是创作辅助工具，用户会以"写小说""编剧本"的形式包装请求，正是 Role Play 与 Unsafe Instruction Topic 的典型形态。**建议把六类攻击场景作为题库的对抗样本来源。**
>
> **已知局限**（官方 README 自述）：① 部分 prompt 由模型增广生成，可能不通顺或多样性偏低；② 少量 response 本身不安全（尤其 Goal Hijacking 类）；③ 未覆盖全部安全主题，**敏感话题数据未公开**。
> **使用要求**：**不得直接采信其 response 作为标准答案**，须重新按本项目判定规程判定。

### 1.2 CHiSafetyBench ★ 分类体系最贴合

| 项 | 内容 |
| --- | --- |
| 来源 | 中国联通 AI 创新中心 |
| 仓库 | `github.com/UnicomAI/DataSet`（`TestData/Safety`）／ `UnicomAI/UnicomBenchmark`（`CHiSafetyBench`） |
| 论文 | arXiv:2406.10311 |
| 分类 | **5 个风险领域 + 31 个类别** |
| 任务类型 | ① 多选题（风险内容识别）② 问答（拒答能力评估） |

> **★ 这是与 GB/T 45654 附录 A 对齐度最高的公开数据集**——论文明确说明其安全分类体系基于我国《生成式人工智能服务安全基本要求》标准构建，两层结构为「5 大领域 + 31 类」。
> **本项目用法**：其分类骨架可直接作为 A.1–A.5 的对照参照；多选题形式适合做机审快速回归，问答形式适合做拒答测试。

## 二、改造为本题库标准形式的要求

开源数据集**不能直接导入**，必须经过下列改造：

| # | 改造项 | 说明 |
| --- | --- | --- |
| 1 | **重新归类** | 按其原始类目 → 国标 31 类（映射见上表）。**一个源类目可能拆到多个国标类目** |
| 2 | **改写为项目场景** | 本产品是《蛊》题材创作辅助，题目应贴近真实的创作请求，而非通用的"越狱攻击题" |
| 3 | **补判别依据** | 每题必须能写出 `judge`（指向附录 A 具体条目），写不出的删除 |
| 4 | **过滤有害样本** | 剔除数据集中本身含可操作危险方法、配方、步骤的条目——**否则题库会成为有害信息载体** |
| 5 | **去重** | 跨数据集合并后去重 |
| 6 | **标 `source`** | 标明来源数据集名，保留可追溯性 |

## 三、非拒答题库的来源说明

| 项 | 说明 |
| --- | --- |
| 国标要求 | 覆盖我国制度、信仰、形象、文化、习俗、民族、地理、历史、英烈，以及性别、年龄、职业、健康等 |
| 开源可用性 | **几乎无现成可用数据集**——这类"正常问题"通常不会被专门收集 |
| **实际做法（已完成）** | **自建**。13 主题先建 20 题/主题 = 260 题骨架，再由 `../06-构建工具/expand_refusal.py` 扩充为**每主题 37–40 题、合计 509 题**（≥500 ✅）。**未使用任何开源数据集** |
| 扩充重点 | ★ **与题材相关但完全正当**的提问（正常武侠创作、民俗问题、战斗描写等）——这些是最容易误拒的场景 |
| 待办 | 全部题目 `reviewed = false`，**须人工复核签核**后方可用于正式跑测（详见 `../03-拒答题库/README.md` §五） |

## 四、使用红线

1. **不得把开源数据集的不安全 response 当作训练目标或参考答案**——部分数据集的 response 本身含安全问题。
2. **不得使用未确认商用许可的学术数据集**于商用服务的安全评估材料中。
3. **导入的有害样本须隔离存储**，不得写入本库的常规目录（见 `../05-台账与制度/资产受控与保密说明.md`）。
4. **所有导入须在台账登记**：来源、许可证、导入日期、条数、加工记录（见 `../05-台账与制度/题库更新台账.md`）。
