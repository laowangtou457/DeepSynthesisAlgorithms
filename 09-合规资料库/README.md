# 09-合规资料库

> **定位**：本项目通过 **算法备案安全评估** 所需的**内容安全数据实体库**。
> **与需求文档的区别**：`00-需求/系统级需求/SYS-内容安全尺度与红线口径-最终版.md` 回答「**红线在哪、怎么判**」；
> 本库提供「**实际有多少条**」——国标要求的是**可计数的资产**，评估时查的是题库与台账实体。
>
> 建立 2026-10-12 ｜ 主要依据：**GB/T 45654—2025《网络安全技术 生成式人工智能服务安全基本要求》**

---

## 一、为什么必须有这个库

GB/T 45654—2025 第 8 章把「安全评估」的准备工作写成三条**可量化的硬指标**：

| 资产 | 国标条款 | 规模要求 | 覆盖要求 | 更新频率 |
| --- | --- | --- | --- | --- |
| **关键词库** | §8.1 | ≥ **10,000** 个 | A.1+A.2 共 17 类；A.1 ≥200/类，A.2 ≥100/类 | 每周至少一次 |
| **生成内容测试题库** | §8.2 | ≥ **2,000** 题 | 完整覆盖 31 类；A.1/A.2 ≥50/类，其他 ≥20/类 | 每月至少一次 |
| **拒答测试题库** | §8.3 | 应拒答 ≥**500** ／ 非拒答 ≥**500** | 应拒答覆盖 17 类 ≥20/类；非拒答覆盖 13 主题 ≥20/主题 | 每月至少一次 |

**这三样是可计数的资产，不是文档。** 口径文档写得再全，评估时专家要看的是：
- 词库文件在哪、有多少条、逐类配额是否达标
- 题库文件在哪、抽了多少题、合格率多少
- 更新台账是否真实、抽检记录是否完整

> **备案被打回的常见原因就是这个**：某应用报送时安全评估报告显示"全部合格"，审查方抽测发现拒答题库仅 200 余条（远低于 500 基线）、生成内容题库不足 2000 条、且人工抽检记录缺失——材料被打回，不得不临时补建，周期拉长两个月。

## 五、三条核心设计原则

### 5.1 分类骨架不与国标分离

31 类风险分类**严格照抄 GB/T 45654 附录 A**，不自创、不合并、不重排。
原因：评估方是按**逐类配额**核对的（A.1 每类 ≥200、A.2 每类 ≥100）。**自创分类等于自断核对路径。**

### 5.2 规模 ≠ 质量，误拒也是不合格

国标同时设了两组门槛：

| 门槛 | 要求 | 含义 |
| --- | --- | --- |
| 生成内容合格率 | ≥ 90% | 该拦的拦住 |
| 正确拒答率 | ≥ 95% | 该拒的拒掉 |
| **误拒率** | **≤ 5%** | **不该拒的不能拒** |
| 违法内容输出率 | = 0% | 绝对红线 |

**过度拒答同样不合格。** 本产品是《蛊》武侠题材创作工具，用户会问刀剑、江湖、蛊术——这些**完全正当的创作话题被拒答，就是误拒**。所以 `03-拒答题库/非拒答/` 不是陪衬，是必须认真做的部分。

### 5.3 受控资产：内容受控，过程可核查

涉政、涉民族类词条与题目**不在工程文档明文留痕**（避免二次传播），存入受控区。
但这**不影响可核查性**——通过**受控资产台账**证明规模，必要时在监管方要求的受控环境下抽样展示。

| 文件 | 作用 |
| --- | --- |
| `05-台账与制度/资产受控与保密说明.md` | 受控范围、存储、访问、双人原则、销毁要求、**§三之二 版本控制方案** |
| `05-台账与制度/受控资产台账.md` | **受控类规模台账**（只记条数/时间/人员，不含内容） |
| `05-台账与制度/受控类编写指引.md` | **内容从哪来、怎么写**：法条与官方口径来源清单、三步推导法、配额拆解、编写红线 |
| `05-台账与制度/controlled_assets.json` | 机读计数，`check_quota.py` 据此自动判定受控类达标 |
| `06-构建工具/init_controlled.py` | 生成受控区骨架；`--sync` 回填计数 |

**受控区版本控制（高频问题）**：**不需要为受控区建 SVN 仓库**。
国标要求的是「资产真实存在且可核查」，**未要求**受控内容进版本库。
实测本工程根目录**既无 Git 也无 SVN**——这意味着最大的风险不是"该不该用 SVN"，
而是**将来 `git init` 时把受控区一并入库**。因此已在工程根建立 `.gitignore` 排除 `_受控区/`。
若组织制度强制版本化，则用 **SVN 独立仓库**（路径级 ACL + 稀疏检出 + `needs-lock`），
理由是 Git 的 `clone` 等于全量导出。完整对比与三种方案见 `资产受控与保密说明.md` §三之二。

> **核心口径不变**：**内容是受控的，过程是可核查的。**
> 受控类未回填时，`check_quota.py` 会明确标注「受控类待回填」，不会把 0 误报为达标。
