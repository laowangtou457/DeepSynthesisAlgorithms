### 2.1 核心结论（归档备查）

| 项 | 结论 |
| --- | --- |
| GPU | **现状 1×24 GiB 满足文本方案**（型号与计算能力待登记）；门槛为「计算能力 ≥8.0（Ampere 及以上）」，否则不支持 BF16 与 FlashAttention-2 |
| **磁盘口径变更** | C-004 的「300–500 GB」为**最小可用**估算，未含 6 个月日志留存、RAG 向量库、对象存储与快照冗余 → 按完整口径测算 **≈610 GB**，故上调为**最低 500 GB / 推荐 1 TB**（C-004 不撤销，作覆盖性上调） |
| 8K 上下文并发 | BF16 权重下 24 GiB 卡理论 ≈15 路，与 SYS-015「单卡 10 并发」暂定值相容，10 并发为**保守可达成值** |
| 带宽 | **不是瓶颈**——300 并发下出口需求不足 1 Mbps。选企业专线是为**固定 IP + 上行稳定 + ICP 备案资格** |
| **上线阻断项** | 家宽/普通办公宽带**不满足 ICP 备案接入要求**，且无固定 IP → 微信小程序服务器域名白名单无法配置。须**最先启动**（有外部审核周期） |
| 内存优先级 | 升内存与磁盘**优先于**升 GPU（成本低、收益直接）；GPU 升降级**放在并发实测之后** |
| 2×24 GiB ≠ 1×48 GiB | 消费级卡无 NVLink，vLLM 张量并行跨卡通信走 PCIe，效率明显低于单卡 48 GiB → 目标等效 48 GiB 应优先单卡 |

### 2.2 容量测算模型（可复算）

| 模型 | 公式 / 口径 |
| --- | --- |
| 显存 | `KV Cache = 2 × n_layers × n_kv_heads × d_head × dtype_bytes × tokens`；Qwen2.5-7B 取值 28 / 4 / 128 / 2 字节 → **单 token 56 KiB** |
| 存储 | 12 个分项逐项估算（模型权重 60 GB / 语料 100 GB / 对象存储 100 GB / 日志 36 GB …）→ 小计 ≈472 GB，含 30% 冗余 ≈**610 GB** |
| 带宽 | `输出速率 × 每 token 字节数`；中文 1 token ≈ 3 字节 → 300 并发 ≈144 kbps |
