## 3 门禁运行期化（`T-086` ①）

### 3.1 三层闸的职责边界（本批把「质量层」补上）

| 层 | 落点 | 判什么 | 后果 |
| --- | --- | --- | --- |
| **结构层** | `services/artifact_contract.py`（`ISSUE-042` 根治批） | 能不能解析、形态相符否、必需键齐否 | **可阻断**（`APP_SHAPE_GATE_ENFORCE`） |
| **质量层** | **`services/quality_gate.py`（本批）** | 判据 `R1`~`R40` ＋ 交付侧 `BLOCK`/`WARN` | **可阻断**（`APP_QUALITY_GATE_ENFORCE`，当前关） |
| **内容层** | `services/content_adequacy.py`（`ISSUE-045` 批） | 算术自洽、单场时长、单元规模、场覆盖度 | **只判不拦** |

⚠️ 三层的**结论字段分组留痕**、**不得合并** —— 合并会把「结构过了」读成「质量也过了」。

### 3.2 判据唯一来源与并发安全

- `prompts/validate_output.py` 与 `delivery/validate_pack.py` **都不是包**（`prompts/`、`delivery/` 下无 `__init__.py`）⇒ 以 `importlib.util.spec_from_file_location` **按路径加载**，加载结果缓存 ＋ 线程锁。
- ⚠️ **`validate_output.py` 的并发不安全**（本批读源码确认）：`RESULT`／`UPSTREAM`／`QUIET` 是**模块级全局**，而 `vllm_max_concurrency=10` ⇒ 必须用 `asyncio.Lock`（`_engine_serial`）**串行化**每次调用，否则并发请求会**互相污染判定结果**（典型的「并发下结果不可复现」）。
- 每次调用前**重置** `QUIET`／`RESULT`／`UPSTREAM`，并用 `TemporaryDirectory` 写上游文件后传 `fname=`。

### 3.3 ⭐ 三态判定 —— 本批**实测踩到**的真实缺陷

`ok` 必须是**三态**：`True` / `False` / **`None`（无法判定）**，且「判过且通过」与「根本没判」**必须可分**（`checked` 与 `ok` 分列）—— 这正是 `ISSUE-042` 同形缺陷的普适形态。

**自踩现场（探针实测）**：探针一度选错文件（`step4_storyboard.json` 是 **API 信封**而非裸产物）⇒ `detect_shape()` 返回 `None` ⇒ `engine_checks=0, errors=0` ⇒ 按「无失败即通过」得 **`ok=true`** —— **「什么都没判」被报成「通过」**。

**修复后**：
```
failures 非空        → ok = False
有 reason            → ok = None
shape is None        → ok = None, reason = "shape_undetected"
checks == 0 且无告警 → ok = None, reason = "nothing_checked"
否则                 → ok = True
```

## 4 重试回路（`T-086` ②③）

### 4.1 逐次尝试的主回路顺序（顺序即契约）

```
生成 → 截断判定（只看本批 seg_trace）→ 合并 → 输出闸（覆盖前）→ 真值覆盖 → 形态闸 → 门禁
```

⚠️ **真值覆盖必须在门禁之前**：门禁要判的是「**最终入库、最终交付的那一份**」。若先判后覆盖，判的是**模型自拟的元数据**（含假合规值），结论本身无意义 —— 而假值恰好会**通过**门禁，**比缺失更危险**（见 §5）。

### 4.2 按段定位与回退（`_retry_segments`）

| 判据 | 定位结果 |
| --- | --- |
| 报错含 `Uxx` | `unit:Uxx` |
| 含 `meta.`／`total_duration_ms`／`package` | `package_head` |
| 该段解析失败或**零贡献** | 重跑该段 |
| **都定位不到** | **回退全部段** ＋ 留痕 `scope_fallback` |

⚠️ **「宁可多跑，不得漏跑」** —— 定位不到就全跑，**不得**因为定位失败而少跑。

### 4.3 ⚠️ 「重试不得使结果变差」（本批自踩后加固）

**现场**：脚本化后端只预置一轮响应，第 2 次调用返回 `{}` ⇒ 形态闸判「无法识别」⇒ 直接抛出 —— 等于**用一个结构非法的产物替换掉一个结构合法的产物**，**净效果是变差**，且把「质量未过关」这一真问题**掩盖**成「产物不可解析」。

**修复**：加 `last_ok_state` 快照 —— 次轮结构非法时**回退**到首轮合法产物，留痕 `retry_degraded_fallback`，并 `logger.warning("quality_gate_retry_degraded")`。⚠️ **首轮**不合法则照旧抛出（与改造前行为一致：不写槽、不推进状态机）。

### 4.4 「不值得重试」与「没有额度了」**必须分列**

- `retryable` ＝ **模型这次怎么写的**，重采样有机会改（如 `R11` 运镜重复、`R14` 时长不守恒、`unit.shot_missing` 引用断链）。
- `non_retryable` ＝ **服务层域／合规资产侧**，重试改了也白改（如 `compliance.marking` 标识未接入、`pack_id` 占位、`artifact.*`／`meta.aigc`）。
- 停止理由分别记 `no_retryable_failure`（不值得重试）与「额度用尽」—— 混成一句「重试用尽」会**误导成「模型不行」**。

### 4.5 用尽重试的处置（硬约束落地）

`PM-001` `T-086` 硬约束原文「**用尽重试仍不过则必须如实拒绝／如实登记，不得以放行或『后处理修补』兜底**」的落地：
- `enforce=true` ⇒ 抛 `AppError(GENERATION_FAILED)`，`details.reason="quality_gate_not_passed"`（**不写产物槽、不推进状态机**）；
- `enforce=false` ⇒ 只 `logger.warning("quality_gate_bypassed")` 并**照常留痕**。
- ⚠️ **刻意不做**：不往 `meta.notes` 里写「本产物未过门禁」之类**修补** —— 那会把「未通过门禁」从产物里**抹掉**，而备案举证要的正是「产物可追溯到判定」。

## 6 连带修复：占位符渲染抹空（`{{X}}` → `{}`）

**根因**：`loader.py` 的 `_TOKEN = re.compile(r"\{([A-Za-z_][A-Za-z0-9_]*)(?:\?([^}\n]*))?\}")` 会命中 `{{PROVIDER_CODE}}` 的**内层** `{PROVIDER_CODE}`，而它不是变量 ⇒ **替换成空串** ⇒ 退化为 `{}`。**实测产物 `generator.provider_code == "{}"` 逐字吻合。**

**修复**（`_interpolate` 三步，**顺序不可换**）：① `{{…}}` 摘成哨兵 `\x01<序号>\x02` → ② 跑 `_TOKEN` → ③ 哨兵**原样还原**。

⚠️ **关键设计订正（本批自踩）**：初版按 Python `str.format` 语义转成**单**花括号（`{{X}}` → `{X}`），实测发现**判据失配** —— `validate_pack.py` 的判据写的是 `if "{{" in str(provider_code)`，故**必须保留双花括号**。已改为「**整段原样保留、不改变括号层数**」。

⭐ **修复的意义**：交付门禁的 `WARN provider.code`（「`provider_code` 仍为占位 → 不得用于正式交付，须回填（NT-02）」）**恢复可触发** —— 此前该告警**永不触发**、占位项**静默通过**。**实测已验证触发**（见 §8）。

**实测**：`'"provider_code": "{{PROVIDER_CODE}}"'` → **不变**；`'{"a": {"b": 1}}'` → 不变；`'v={foo}'` ＋ `{'foo':'OK'}` → `'v=OK'`（既有行为不变）；`'v={{foo}}'` → `'v={{foo}}'`（**行为变更，已记入注释**）。

## 11 🆕 新登记 `ISSUE-047`：交付 schema 与服务层「诚实占位」**互斥**（**须项目方裁决**）

**发现方式**：本批 `T-086` 配套（服务层真值覆盖）落地后，对**真实产物**跑交付门禁取证。

**现象（逐条可读，实测原文）** —— 覆盖后新增 **6 条 `schema.pack` BLOCK**：

```
[X] BLOCK schema.pack  meta/compliance/copyright_check/status: '占位（版权校验未接入，见任务 T-008）'
                       is not one of ['passed', 'warning', 'risk', 'skipped']
[X] BLOCK schema.pack  meta/compliance/marking_check/explicit: '占位' is not one of ['present', 'missing']
[X] BLOCK schema.pack  meta/compliance/marking_check/implicit: '占位' is not one of ['present', 'missing']
[X] BLOCK schema.pack  meta/compliance/safety_check/input:  '占位（内容安全双闸结果未取得）'
                       is not one of ['passed', 'blocked']
[X] BLOCK schema.pack  meta/compliance/safety_check/output: '占位（内容安全双闸结果未取得）'
                       is not one of ['passed', 'blocked']
[X] BLOCK schema.pack  meta/pack_id: '{{PROVIDER_CODE}}-PK-20261016-000E4A12'
                       does not match '^[A-Z0-9]{2}-[A-Z]{2}-[0-9]{8}-[A-Z0-9]{8}$'
```

**两个根因（各自独立、须一并裁决）**：

- **根因 A —— `compliance.*` 只有「真值枚举」，没有「未知／未接入」这一档。**
  `CFG-006_shot_prompt_pack.v1.schema.json` 的 `compliance.*` 枚举只有 `passed`/`blocked`/`present`/`missing`/`skipped`/`warning`/`risk`
  ⇒ **服务层纪律性的占位（「未取得」「未接入」）必然 `schema.pack` BLOCK**（5 条）。
  ⇒ 结构上**逼着**要么填假值、要么不合 schema —— **而填假值恰好能通过 schema**（见 §5.1）。
- **根因 B —— `pack_id` 的 `pattern` 不纳占位。**
  `^[A-Z0-9]{2}-[A-Z]{2}-[0-9]{8}-[A-Z0-9]{8}$` 要求真实企业码（2 位）⇒ `{{PROVIDER_CODE}}`（含花括号、16 字符）**必然不匹配**（1 条）。
  而占位是**服务层刻意**的：`NT-02` 已定「未取得编号时**不得自拟**」。
- **附带（归因错向，值得单列）**：同批还新增一条
  `[X] BLOCK compliance.safety  输入/输出内容安全检测未通过 → 阻断交付（SW-009/010）`
  —— 而真实状态是「**结果未取得**」。⇒ 交付门禁把「**未取得**」读成了「**未通过**」，**归因方向错误**（真实含义被替换成了更严重但错误的结论）。

**为什么必须裁决而不能自行处置**：两条路**互斥**且各有代价 ——
① **扩 `compliance.*` 枚举**（增「未知／未接入」档）⇒ 契约变更（须规范升版、判据同步、`CASE-*` 重跑）；
② **拆出「预演包」schema** ⇒ 需要确定「预演包**不得用于正式交付**」的机器判据与留痕字段；
③ 或者 **让服务层在「未接入」时写 `skipped`**（语义最接近的既有档）—— **但这是「用合法取值掩盖未做」**，与本工程第一纪律相悖，**不建议**。

⚠️ **`TPL-009` 第 743 行的既有措辞已为路径 ② 背书**：`metadata_missing` 情形下「照常产出产物（结构完整、**可交付预演**），但①该字段写占位符 ②在 `meta.notes` 写明『本包为占位预演，未取得编号，**不得用于正式交付**』」⇒ 规范**已经在概念上区分了「正式包」与「预演包」**，缺的是**机器可判的承载**。

**⚠️ 与本批门禁口径的关系（重要）**：只要 `ISSUE-047` 未解，`quality_gate_enforce=true` 就会让 **`shot_prompt` 段在正路上必然被拒**（不是模型的问题，是**契约与服务层纪律打架**）。⇒ **`enforce` 翻 `true` 的前置条件不只是 `T-087`（资产提质），还包括 `ISSUE-047` 的裁决与落地。** 本批 `enforce=false`（分阶段上线）**恰好把这条风险挡住了**。

**同批待确认的产品口径**：`APP_UNSUPPORTED_TASK_TYPES` 默认空（＝服务层不声明），而 `CFG-006` 要求**非空**。**具体内容属产品口径**，须项目方确认后由部署侧显式配置（服务层**不替项目方声明**）。
