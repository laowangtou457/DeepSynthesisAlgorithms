## 1 动作摘要

次日续跑 `T-004` 时起服务失败。**结论：与 venv 是否完好无关 —— 是脚本默认解释器选错，并连带把最该做的前置检查整段跳过。**

| 项 | 结果 |
| --- | --- |
| 现场报错 | 第 0 步 `[WARN] nvcc: 未探测到` ＋ `[WARN] 未取到 CUDART_VERSION（预期路径 /include/cuda_runtime_api.h）`；第 3 步 `[ERROR] 无法导入 vllm` |
| 真实根因 | `PY_BIN="${PY_BIN:-python3}"` —— 默认值写死**系统解释器**，而 venv 方案要求人工**每次**带 `PY_BIN=~/vllm-venv/bin/python` 前缀；漏写即**静默降级** |
| 连带后果 | 「运行环境归位」整段跳过（无 `<venv>/bin`、无 `CUDA_HOME`）⇒「CUDA 编译器／头文件版本一致性自检」**被无声绕过** |
| 处置 | 脚本**从默认值根治**：未显式指定 `PY_BIN` 时**自动探测 `~/vllm-venv`**，探到即用；探不到才回落 `python3` 并**响亮提示**；显式传参**永远优先** |
| 验证 | `bash -n` 通过；行尾族（纯 LF）与无 BOM 均保持；615 → **639 行**；`OPS-002` 新增 **§4.1.3** ＋ 变更行 **V1.12** |

## 2 定位过程（判据可复用）

### 2.1 一眼认出的判据：`预期路径` 而不是版本号

现场那行 `[WARN] 未取到 CUDART_VERSION（预期路径 /include/cuda_runtime_api.h）` 是关键 ——
`CUDA_HOME` 为空时该变量才展开成 `/include/...`；而 `CUDA_HOME` **只在脚本判定「解释器位于 venv 内」**（认 `pyvenv.cfg`）时才被兜底设置（脚本第 303~325 行）。
⇒ **这一行本身就是「正在用系统解释器」的铁证。**

⚠️ **不能拿版本号判断**：第 0 步打印 `Python: 3.12.3`，而 venv 的解释器**同样是 3.12.3**（`pyvenv.cfg` 实测 `version = 3.12.3`）⇒ **光看版本号区分不出来**。
真正的区分物是：① 是否有 `[OK] venv 归位：…` 那一行；② `预期路径` 是否为空。

### 2.2 venv 健康性核验（排除「环境坏了」这一支）

沙箱禁用 `wsl.exe`，故改由 **Windows 侧经 `\\wsl$\Ubuntu\…` 取证**（本项目既定手段）：

| 核验项 | 实测 |
| --- | --- |
| `~/vllm-venv` | 目录存在，`bin/` · `external/` · `include/` · `lib/` · `lib64/` · `share/` · `pyvenv.cfg` 齐备 |
| `bin/` 关键项 | `python` · `python3` · `python3.12` · `pip` · `pip3` · **`vllm`** · **`ninja`** 全部在位 |
| `site-packages/` | `vllm` · `torch` · `flashinfer` · `xgrammar` · `ninja` · `nvidia` 全套在位 |
| `pyvenv.cfg` | `version = 3.12.3`；`include-system-site-packages = false`；`command = /usr/bin/python3 -m venv /root/vllm-venv` |
| 残留进程 | **无**（`vllm-serve.log` 最后一行停在 10-15 18:39 ⇒ WSL 已重启过，8001 端口空闲，可直接起服务） |

⇒ **venv 无任何异常**，本次失败纯属解释器选错。

## 3 处置

### 3.1 `provision-vllm.sh`（默认值根治，非仅加提示）

`PY_BIN` 未显式给出时按序探测 `$HOME/vllm-venv` → `/root/vllm-venv`，命中即用并打印
`[OK] 解释器：未显式指定 PY_BIN，自动探测到 venv ⇒ …`；两处都未命中才回落 `python3`，
并**响亮提示**「系统侧未装 vllm 会导致第 3 步失败」及其覆盖写法。**显式传参永远优先**
（`PY_BIN=/usr/bin/python3 bash $0` 可强制用系统解释器 —— 走 OPS-002「方案 ①」时必须这样写）。

脚本头部 `--help` 注释里 `PY_BIN` 一行的「（venv 方案必带）」**已订正**为「**可省略**」。

> ⚠️ 为什么选「自动探测」而不是「报错要求显式传参」：本次事故的**危害不在报错本身**，
> 而在**它把 `CUDA 版本一致性自检` 一起绕过了**（该段取不到 `CUDART_VERSION` 时只 `warn` 不 `die`）。
> 但「自动探测」会改变「方案 ①（系统 pip）」的默认行为 ⇒ 已在 `OPS-002` §4.1 与 §4.1.3
> **显式写明**「走方案 ① 须显式写 `PY_BIN=/usr/bin/python3`」，避免把一类坑换成另一类。
