### 5.2 ⚠️ 本批自身事故与修正：`Edit` 工具改写整份 README 的换行符

| 项 | 事实 |
| --- | --- |
| 现象 | 用 `Edit` 给 `11-过程文档/开发历史/README.md` 的索引行加粗（`144` → `**144**`）后，`git diff` 报 **583 行变更**（文件仅 305 物理行） |
| 根因 | 该文件是**混合 EOL**（CRLF 291 ／孤立 CR 283 ／LF）；`Edit` 工具回写时按 LF 统一化 ⇒ **291 个 CRLF ＋ 283 个孤立 CR 被抹平**，字节数 84,126 → 83,954 |
| 修正 | **从 `HEAD~1` 取原始字节重建**：字节级唯一锚点定位 `-007` 行 → 仅在其后插入 `-008` 行（沿用该行终止符 `\n`）→ `wb` 二进制写回；断言 `CRLF 计数不变`／`长度增量 = 新行 + 终止符` |
| 结果 | `git diff --numstat HEAD~2 HEAD` = **`1 0`**（净新增 1 行、零删除）⇒ 已恢复原始 EOL |
| 教训 | **对混合 EOL 的台账类文件，禁止用 `Edit` 改单行**（看似只改一行，实际整文件被重排）。正确做法＝**二进制读 → 插入 → 二进制写**，并用「CRLF/CR 计数守恒」断言自证。此前记忆只记了「用临时脚本写」，未点明「`Edit` 工具同样会归一化」——**这是本批新增的硬纪律** |
