## 一、背景

r6 复验（夹具 v2 单键改 `S01-SH003.camera.move` `push_in`→`zoom_in`）于 11:20 起跑。16:00 前完成 6 个有效轮，此后为提速而起的并行路与断点续跑**连续 8 轮硬失败**（`run8`~`run15`，每轮 3~9 分钟），错误形态与内容质量无关：

| 轮 | 错误 |
| --- | --- |
| `run8`／`run9`／`run11`／`run13`／`run14` | `AppError: 分段产物不是合法 JSON，无法解析` |
| `run12` | `AppError: 分段产物为空，无法解析为 JSON 对象` |
| `run15` | `AppError: 分段产物中找不到 JSON 对象` |
| `run10` | `AppError: 「shot_prompt」段输出被长度上限切断（段：unit:U02）` |

## 二、根因

`app/core/config.py` 的 pydantic 设置以 `env_file=".env"` **按进程 cwd 相对解析**加载配置。`.env`（不入库）内含一条关键项：

```
APP_VLLM_GUIDED_DECODING_MODE=response_format   # 注释载明：服务器 vLLM 0.10.2 会静默忽略 structured_outputs 形态
```

链条如下：

1. 主序列 1~7 轮：以 `cd 03-工程代码` 启动 ⇒ 读到 `.env` ⇒ guided 模式 `response_format` ⇒ **受约束解码正常**；
2. `on_p1`~`p4` 与断点续跑：以 `cd .wb-e2e` 启动 ⇒ **`.env` 未读到** ⇒ guided 模式回落默认 `structured_outputs`；
3. 服务端 vLLM **0.10.2**（`GET /version` 实测）**静默忽略** `structured_outputs` 形态 ⇒ **完全无约束解码**；
4. 模型在 ~16k~26k token 的长 prompt 上自由发挥 ⇒ 产物不是合法 JSON ／为空 ／找不到对象。

## 三、三条铁证

1. **现场抓取**：`_r6_probe_round.py` 包装 `parse_json_object` 落盘原始输出，`_parse_dump.txt` 内容为字面 **8 个字符 `lyricist`** —— 与分镜任务完全无关。
2. **同 schema 不同结构**：`_probe_app_shape.py` 以应用同形态（真实 schema ＋ 19.6k prompt ＋ 8192 输出）连发两次，返回**不同顶层结构**（`shot_prompts` vs `unit/shots`）⇒ schema 未生效。
3. **换正确 cwd 后形态突变**：`on_p5`／`p6`／`p7` 以 `03-工程代码` 启动，垃圾产物**消失**，错误改判为 `推理后端响应超时（600.0 s）` —— 说明生成已回到受约束轨道，只是被并发拖过超时。

## 四、`ISSUE-085` 更正（原判「并发污染」系误诊）

| 项 | 原文 | 更正后 |

| 现象观测 | 4 路并发 5 次尝试 0 干净（`on_p2` run2 出现基线外码 `R26`／`R32`／`R33`、字段集偏薄、`style_ref=None`） | **观测成立、原样保留** |

## 六、恢复动作与口径登记

- 停掉 3 路（`on_p5`~`p7`，全部 600 s 超时）；
- 以 **2 路并发**（`on_s1`／`on_s2`，各 3 轮）＋ 采集期 `APP_VLLM_TIMEOUT_SECONDS=1200` 重启，18:20 起跑；实测 `kv_cache_usage_perc` ≈40%、`num_requests_waiting=0`；
- **口径差异必须登记**：采集进程超时 600→1200 s，生产 `.env` 的 600 s **未动**。该参数只影响「长调用是否被判伪失败」，**不影响**判据码（`R27`／`R28`／`R29`／`R34`）、15 镜/5 场守恒与 `R11`；
- 样本账：有效 **6/12**（主序列 1/2/4/5/6/7）＋ `on_s1`／`on_s2` 各 3 轮 = 12。

## 七、影响评估

- `app/` **零改动** ⇒ pytest 用例数与判据水位（`R1`~`R43`）不变；
- `ISSUE-084`（8192 截断）**维持成立**：`run3`／`run8` 的原始截断发生在受约束解码正常的 1~7 轮内，与本根因无关；
- 本次误诊的代价：约 3.6 h GPU 时间（8 轮无效）＋ 一次台账更正。

## 八、教训固化

1. **跑测类进程一律从 `03-工程代码` 启动**，或显式传 `APP_VLLM_GUIDED_DECODING_MODE`；`cd` 到子目录启动会静默丢配置。
2. **「生效配置」启动头必须含 guided 模式**：本次它不打印该字段，导致「看起来配置已生效」的误判持续了 8 轮。
3. **判定性探针必须复刻生产请求形态**：16:50 与 17:44 两次探针用小 prompt ＋ `structured_outputs`，未能复现问题；只有「真实 schema ＋ 长 prompt ＋ 正确 cwd 对比」才能定位。
4. **配置静默退化属「同一动作内的不完整落地」家族**：可退化而无断言，等价于没有约束。
