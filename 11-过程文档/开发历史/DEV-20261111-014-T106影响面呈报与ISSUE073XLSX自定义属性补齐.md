## §1 T-106 呈报：占位 `R27` 的影响面与改法选项（待项目方裁决）

### 1.1 问题一句话

程序构造的占位镜（`prompt_en` 留空）必然触发 `R27 PACK_REQUIRED` 每镜必备字段失败，
该失败当前被分拣为 **retryable** ⇒ 触发一次整段重采样；而 `ab_t101_r4` 实测重试自愈率
**0/11**（a1→a2 同码，模型恒缺 `S01-SH003`）⇒ 重试纯属白烧（on 2.9 vs off 2.3，轮均成本）。

### 1.2 代码位置（四处，呈报对象）

| # | 位置 | 职责 |
| --- | --- | --- |
| ① | `03-工程代码/app/services/dialogue_service.py` `_fill_missing_shots`（约 L2190–2290） | 占位镜构造：`prompt_en=""`、`notes` 明写「服务层构造占位（2026-11-07 裁决甲）」、告警码 `merge.shot_conservation_fill`（`pack_conservation_fill=true` 时生效） |
| ② | `03-工程代码/prompts/validate_output.py` `rule_pack_required`（约 L1653–1692） | `R27` 判据：每镜 14 必备字段，`prompt_en` 空 → `bad.append(f"{sid}.{k} 缺失／为空")`，聚合成**一条**报错 `{where} · R27 PACK_REQUIRED：N 处不合规 → …` |
| ③ | `03-工程代码/app/services/quality_gate.py` `_classify` ＋ `_NON_RETRYABLE_ENGINE_MARKERS = ("R30", "AIGC_META")`（L93–110、L476） | 分拣：报错文本**含任一 marker** → `non_retryable`；`R27` 不在 marker 集 ⇒ 进 `retryable` |
| ④ | `03-工程代码/app/services/dialogue_service.py` 重试回路（约 L1570–1790） | `should_retry`（retryable 非空即重试）→ `_retry_segments`（按报错文本中的 `shot_id` 做段包含定位）→ `quality_gate_max_attempts=2`（默认一次重试） |

### 1.3 关键技术事实：分拣层无法直接区分「占位 R27」与「模型原生 R27」

- `R27` 报错文本只含 `{sid}.{k}`，**不含 `notes` 字段内容** ⇒ marker 机制（对报错文本
  做子串匹配）没有现成锚点区分两种来源；
- 模型原生 `prompt_en` 缺失**应当保持 retryable**（重采样有机会改变，实测原生 R27 可自愈，
  `ISSUE-069` ③：on#09 无补镜告警、a1→a2 救回）——**不能**把整个 `R27` 加进
  `_NON_RETRYABLE_ENGINE_MARKERS`，否则误伤真可重试失败。

### 1.4 改法选项（呈项目方三选）

| 选项 | 做法 | 改动面 | 代价／风险 |
| --- | --- | --- | --- |
| **A（推荐）** | 判据侧细分码：`rule_pack_required` 对 `notes` 以「服务层构造占位」开头的镜单列报错 `{where} · R27P PLACEHOLDER：…`（与原生 R27 分两条 err）；`quality_gate.py` `_NON_RETRYABLE_ENGINE_MARKERS` 增 `"R27P"` | ② ③ 两文件 ＋ 测试；`_retry_segments` 包含定位天然兼容（R27P 文本同样含 `sid`） | 判据脚本升版（`validate_output.py` 版本号 ＋ 引用面核对，参照 `T-107` 体例）；「R27P」为新码，对外材料若引用 R 编号清单须同步 |
| B | 对话服务侧预检：重试判定前解析本层产物，若 retryable 失败**全部**可归属占位镜（`notes` 标记）则按「无 retryable」处理 | ④ 一处 | 逻辑重复判据职责（判据已判过一次归属）；重试是**段级**不是镜级——同段其余原生失败会被占位失败「连坐」跳过重试，**有掩盖真失败风险**，不推荐 |

## §2 ISSUE-073 实施：XLSX 自定义属性补齐（本批已完成）

### 2.1 方案变更：zip 手术 → 官方 API

呈报时的预估补做方式为「写盘后按 zip 追加 custom part」；实施时实测
**openpyxl 3.1.5 已原生支持**自定义文档属性（`wb.custom_doc_props.props.append(StringProperty(...))`），
写盘自动完成 `docProps/custom.xml` 落盘、`[Content_Types].xml` Override 注册、
`_rels/.rels` 关系挂接——**零 zip 手术、零新依赖**，探针全链路验证通过（写入＋读回＋注册三断言）。

### 2.2 改动明细（`app/services/export_service.py` 三处 ＋ 测试一处）

1. **`_render_xlsx`**：`AIGC_*` 逐键 `StringProperty` 写入 `docProps/custom.xml`（规范 §9.2 载体）；`keywords`／`description` 承载**保留**为冗余兼容（旧客户端只认核心属性，双载体同源）；docstring 由「已知偏差」改写为「双载体」说明；
2. **`_evidence` xlsx 分支**：取证双路化——custom.xml 属性名集合（`AIGC_ProduceID` ∈ names）∨ keywords 判 implicit；note 如实披露 `AIGC_* × N` 计数；
3. **调用处 `_record` note**：「隐式标识落于 keywords（openpyxl 不支持…）」→「自定义属性 docProps/custom.xml（规范 §9.2 载体）＋ 核心属性 keywords（冗余兼容）」；
4. **模块 docstring 已知偏差段**：改写为「已补齐」记述（保留删除线原文，如实留痕）。

### 2.3 回归锁

新增 `app/tests/test_export_service.py::test_xlsx_custom_doc_props`（三重断言）：
① zip 内 `docProps/custom.xml` 存在；② `[Content_Types].xml` 与 `_rels/.rels` 注册；
③ openpyxl 读回属性逐键比对（全 `AIGC_` 前缀、`AIGC_ProduceID` 非空）＋ keywords 冗余载体仍在 ＋ `_evidence` 双路取证认得规范载体。
