## 1 动作摘要

本动作由**一次终端用户侧的显示投诉**触发，最终收敛为**两条独立产出 + 一次口径订正**：既解决用户当下看不到「状态」列的问题（阅读版导出），又把投诉背后暴露的**一类系统性 Markdown 表格结构缺陷**整批清账。六步：

1. **只读取证与定位**：先排除三类常见误因（文件 BOM、代码围栏未闭合、同目录存在过期 `.docx` 干扰），确认根因是 **WPS 对 Markdown 宽表的渲染限制**——`REQ-005` §2 为 **12 列**宽表，超页宽即被**横向裁切**，最右四列（状态／来源／优先级／关联）不可见。
2. **全工程 Markdown 表格结构普查**：对 **165 个 `.md`** 逐个做「连续 `|` 行分块 → 校验第 2 行是否分隔行 → 逐行核对单元格数」机器审计，发现并登记 **`ISSUE-020`**——**18 处 / 12 文件**，分三型（§2.2）。
3. **分型处置**：**我方现行资产 9 文件 / 14 处 全部修**；**他人评审记录 2 文件 / 3 处**与**历史留痕 1 文件 / 1 处**（合计 **3 文件 / 4 处**）**只登记、不擅改**——沿用「他人产物不擅改」「时点快照不重写」两条既有口径。
4. **阅读版导出**：因本机 `pandoc` 不可用，改为**自研生成器**（纯 `python-docx`）＋产物 `.docx`；登记为 `CM-002` §3 豁免清单第 **7** 类「阅读版导出件」。
