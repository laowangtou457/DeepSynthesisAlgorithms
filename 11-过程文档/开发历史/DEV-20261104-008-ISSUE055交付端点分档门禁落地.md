## 二、实现

### 1. 单一口径的门禁加载（不做第二份）

`services/quality_gate.py` 新增公开入口 `load_pack_validator()`，交付端点与生成段**共用**
同一加载器（模块缓存／失败告警／相对路径解析全部复用）。
⚠️ 若各写一份，就会重演「同一文件两处加载」的分叉风险（本工程已收口过同类问题）。

### 2. 分档判定（`services/delivery_service.py`）

```
落盘四件套 → is_preview 判定（unfilled 非空 或 pack_id 含占位）
          → evaluate_gate(pack.json)  ← 只跑包侧判据，判据零改动
          → gate_report.json 落包目录（含 is_preview／evaluated_at／blocks／warns／scope）
          → 预演包：不拒付，结论进响应
          → 正式包 + blocked：抛 DELIVERY_PACK_INVALID（422），
            details = {gate_blocks:[code...], blocks:[{code,message}], gate_report, pack_id, pack_dir}
```

**拒付不删目录**：`SW-026` 要求自检记录留档 ≥6 个月、可随时调取 ⇒ 目录与报告一律保留。

### 3. 清单侧「如实不校验」

`CFG-005` 契约与现有 `build_manifest()` 形态**结构性不符**（详见 `ISSUE-057`）：
直接纳入会产出十几条与内容无关的 `schema` BLOCK，且 `self_check` 18 项、`human_review`、
质量门报告**须真实来源**（编造 `pass` 即假合规）。
⇒ 本批**只接包侧判据**，并在门禁结论中显式写 `manifest_checked=false` ＋ 原因
（**不是**静默跳过），`ISSUE-057` 裁决后由 `T-099` 翻为 `true`。

### 4. 契约变更（**加性**）

| 位置 | 变更 | 兼容性 |
| --- | --- | --- |
| `DeliveryResult` | 新增 `gate: dict` | 加性，默认 `{}` |
| `PackView`（`POST /delivery/pack` 响应） | 新增 `gate` 字段 | 加性，调用方可忽略 |
| 错误契约 | 正式包 BLOCK ⇒ `422 DELIVERY_PACK_INVALID`，`details.gate_blocks` | 新错误路径（此前无） |

## 四、新缺口（`ISSUE-057`，建议按候选①立项 `T-099`）

交付清单 `manifest.json` 与 `CFG-005` 不符：`manifest_version` 应为 `1.1.0`、须有 `artifacts` 四件套、
`self_check` 18 项、`human_review`、`quality_gate`、`retention{months≥6}`，且 `additionalProperties:false`
⇒ 现有 `files`／`counts`／`is_preview`／`preview_notes`／`service_truth` **全都不允许**。
清单是交付四件套之④（`SW-014`），形态不符在监管核对时是硬伤 ⇒ 建议按 ① 重写（**不得编造 `pass`**）。
