## 三、回归发现与处置（本批最重要的实证）

### 3.1 现象：翻默认后全量测试真实失败 13 项（非沙箱钩子）

首次全量 `pytest` 的 JUnit／点阵显示 `EXIT=1`、13 项 `FAILED`，集中在三个模块：
`test_api_smoke.py`（2）、`test_artifact_gate.py`（5）、`test_quality_gate_t086.py`（6）。

失败原因**全部相同且发生在被测断言之前**：

```
AppError: 上游剧本缺 `acts[]`（或为空），无法推导逐场调用计划
AppError: 「storyboard」段产物有 2 段零贡献（段：scene:2、scene:3）——合并后会出现无据缺口，拒绝入库
=> API 502 GENERATION_FAILED（原断言期望 200／409）
```

即：这三个模块用的是**不含 `acts[]` 的假上游剧本**，测的是「API 链路阶段顺序／产物形态闸／门禁重试回路」；
逐场编排翻默认后，服务在前置就 fail-closed 显式报错，根本走不到被测断言。
**不是产品缺陷**（真实 script 产物按 `SPEC` 必带 `acts[]`；缺 `acts[]` 显式报错本就是设计内的不静默口径）。

### 3.2 处置：测试夹具与生产默认解耦，**不改任何断言期望值**

在 `app/tests/conftest.py` 增加 autouse fixture，按模块白名单
（`test_api_smoke`／`test_artifact_gate`／`test_quality_gate_t086`）
用 `monkeypatch.setenv` 把两开关显式钉为 `false`，并 `get_settings.cache_clear()`。

- 必须走 **env 而非改单例属性**：`client` fixture 用 `create_app(Settings())` **直接构造**新实例，
  只改 `get_settings()` 单例不会影响它；env 对两者同时生效。
- 其余模块（尤其 `test_scene_orchestration.py`／`test_shot_prompt_scope.py`）**一律使用生产默认 `true`**，
  逐场编排与段级裁剪的接线测试不被遮蔽。
- 新默认本身由 `test_decision4_defaults.py` 单独断言，形成互补：「生产默认 true」＋「旧形态仍可显式复现」。

**复验**：`420 → 423 passed`；JUnit XML `tests=423 failures=0 errors=0 skipped=0`，`EXIT=0`；点阵 423 全 `.`、零 `F`。
