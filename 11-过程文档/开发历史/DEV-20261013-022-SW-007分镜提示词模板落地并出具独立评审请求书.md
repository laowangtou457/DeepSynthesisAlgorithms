## 2 本层定位（为什么它是链路里最难的一段）

### 2.1 编译表达层的边界

| 层 | 决定什么 | 产物 |
| --- | --- | --- |
| SW-006 `storyboard_v1` | **切几刀、切在哪、每镜怎么拍**（导演决策） | 结构化字段 |
| **SW-007 `shot_prompt_v1`** | **怎么把这些决策写成目标模型读得懂的话** | **投喂文本 + 补齐的结构字段** |

一句话边界：**不改变任何导演决策，只把决策翻译成表达并补全结构。**

### 2.2 两条只有本层才有的结构事实

**① 双上游**——分镜层的产出是规范字段集的**真子集**：镜头级 `style_ref`、`prompt_zh` / `prompt_en`、`aspect_ratio`、`negative_prompt` **均不在分镜层产出**（分镜层是导演决策层，不写表达）。而分镜层对锚只给**引用**（`character_refs` / `prop_refs` / `style_ref`），**锚的内容在剧本层**。故本层的变量是 `storyboard_json` + `script_json` **双必填**——**全链路 5 段中唯一如此的一段**。模板 `fallback.insufficient_input` 明写「不得只喂一份上游就硬编」。

**② 承继守恒 + 三处改写白名单**——16 类字段一律原样承继，**尤其不得改 `duration_ms`**（它是导演决策，也是与 `total_duration_ms` 一致性的凭据；语速超标属上游缺陷须回退，不得在本层悄悄改秒数）。允许的差异只有三处：**拆分光照字段**（词表值 + 中文光位说明 → 字段留纯 code、说明移入正文）／**清理 `notes` 内部标注**／**`medium` / `normal` 规范化为空串**。

### 2.3 分段策略：为什么按「生成单元」切而不是按字数

规范 §3.5 明写「**生成单元＝一次生成调用所提交的完整分镜块**」——**分段粒度与业务语义粒度本来就该一致**。按字数硬切会产生「半句话的镜头」（一个镜头的正文本被截成两次调用），而按单元切天然对齐。本案 14 镜 / 5 单元 → `package_head` + 5 个 `unit:*` = **6 次调用**。

### 2.4 刻意不做模型适配

规范 §6.1「基准唯一 + 单向投影」+ §6.3「语言倾向不得覆盖模型硬约束」+ §6.1「配置化：新增模型＝改 `model_adapters.yaml` 不改代码」→ **若把适配写进提示词模板，每接一个模型就要改一次模板**。适配在交付后的服务层完成。

### 3.2 `delivery/validate_pack.py` 的容差算法实现笔误 → 同一产物出现相反结论

| 项 | 内容 |
| --- | --- |
| **发现方式** | 把本用例的包**直接投喂**既有交付门禁脚本（这正是 SW-007 输出形态定为「直接产出交付包 JSON」的收益）——首跑报 **1 个 BLOCK** |
| **现象** | 门禁⑫ 对 **U04（2 镜 / 1 static）** 报「静止镜 1/2 > 允许 1（上限 40%）」→ `BLOCK`；而 `validate_output.py` **R19** 与参照实现 **`audit_shots.py`** 都判 **通过** |
| **根因** | 判据写作 `if metrics["静止镜占比"] > GATE["静止镜占比"]`（**比例直接比阈值**），而**报错文案却引用 `_allow(...)` 的绝对个数**——自相矛盾。容差算法的本意是 `max(1, ceil(ratio*n))`：**n=2 时允许 1 个静止镜**，若用比例判，1/2 = 50% > 40% **必判 FAIL**，容差被完全废弃 |
| **裁定依据** | 参照实现 `audit_shots.py`（在工作区之外的前序会话目录，**只读**）第 312–321 行用的是 `if st_cnt > st_allow:`（**计数比较**），其 `self_test()` 亦断言 `_allow(0.40, 2) == 1`；本工程 `validate_output.py` 的 R19 同此口径 |
| **处置** | 判据改为计数比较（`static_cnt > _allow(...)`）并统一文案；**修正后 BLOCK 1 → 0**，三处结论一致；`demo_pack.json` 回归 **BLOCK 0 不变** |
| **为何长期未暴露** | 该缺陷**只在短单元暴露**——整片 14 镜时比例判定与计数判定**凑巧同结果**。**边界样本必须进回归** |
| **性质** | 该函数 docstring 早已声明「容差算法与 `audit_shots.py` 一致」，**属实现与自述不符**——与 §3.1 同一性质：**依赖人记住的口径等于没有口径** |

> **附带发现（登记为已知边界，非缺陷）**：参照实现 `audit_shots.py` **不在本工程内**（路径为前序会话目录），而规范 v1.1~v1.3 与两个校验脚本的 docstring 都引用它。本轮的处置是**只读取其算法以裁定分歧**，未复制入工程、未改动。工程内**无该文件的副本**这一点，应在首次「对真实输出跑 `audit_shots.py --gate`」时一并解决（否则该验收项**无物可跑**）。

### 3.3 本层 R28 的中英判据尺度错配（**本层规则自身的实现缺陷**）

| 项 | 内容 |
| --- | --- |
| **现象** | R28 首跑报 **773 处命中**——14 镜几乎**每镜**都被判「正文复述外观」，规则形同失效 |
| **根因** | 外观锚串被**中英统一取 3 字符**。中文 3 字已是语义单位；**英文 3 字符只是词内片段**——锚里的 `the`（来自 "the right wrist"）、`old`（来自 "an old scar"）会出现在**任何一段英文正文**里 |
| **处置** | 两侧判据**分别定义**：中文取**连续 3 字**（仅在汉字连续段内）、英文取**连续 3 个实词**（先剔停用词再取 n-gram）。修正后 **0 命中** |
| **教训** | **跨语言规则的阈值不能按字符数平移**；且此例说明「规则自己也会错」——**正向全绿证明不了判据正确**（首跑时若只看「有命中」还会误以为规则很强） |
