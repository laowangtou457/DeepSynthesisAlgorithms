## 2 变更明细

### 2.1 `09-合规资料库/06-构建工具/init_controlled.py`（LF）

| # | 变更 | 说明 |
| --- | --- | --- |
| ① | 新增模块级纯函数 `_sum_counts(counts, kind)` | 按四类求合计条数（只读数字） |
| ② | 新增模块级纯函数 `append_sync_history(d, counts, today, status)` | `T-102` 主体：向 `history` 追加一条与既有行**同构**的留痕 |
| ③ | `sync(out)` → `sync(out, ctrl_json=None)` | 新增**仅供测试注入**的台账路径参数；生产调用保持默认模块常量 `CTRL_JSON`，CLI 行为不变 |
| ④ | `sync()` 写入顺序调整 | 计算 `status`／`today` 后，**在覆盖 `d["counts"]`／`d["status"]` 之前**调用 `append_sync_history`（否则增量恒为 0）；随后照旧写 `counts`／`status`／`last_updated` |
| ⑤ | 运行输出补如实结论 | 打印「history 已追加 1 条」或「history 未追加：计数与状态均无变化（幂等…）」 |
| ⑥ | 顶部 docstring ② 与内嵌 `CTRL_README` 模板两处 | 补「并自动追加 history 留痕」提示，使受控区 README 模板与 SOP 一致 |

**追加口径（本批关键设计）**：

- **触发条件**：仅当 `counts` 或 `status` 相对回填前发生**实质变化**才追加一条；两者均未变时**不追加** ⇒ 重复运行幂等，避免每日巡检产生噪音行；
- **行结构**：与既有 `history` 行完全同构（`date` / `action` / `lexicon_added` / `bank_added` / `refuse_added` / `operator` / `reviewer` / `note`），**不新增字段、不改写既有行**；
- **内容边界**：`*_added` 为四类合计**增量**（可为负）；**只记条数，不含任何受控内容**；`operator`／`reviewer` 脚本无从判定，沿用既有行的 `—`，由受控流程另行登记。

**未改动**：`--init` 骨架生成、`count_lex`／`count_jsonl`、达标判定阈值（200/50/20）、`CTRL_JSON` 默认路径、写文件 `LF` 与 `indent=2` 格式、`check_quota.py` 等其它脚本。
