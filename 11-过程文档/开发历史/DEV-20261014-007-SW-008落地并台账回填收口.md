## 2 `SW-008` 落地：模板、用例与判据

### 2.1 两处结构性判断（先定，再写）

| 判断 | 结论 | 依据 |
| --- | --- | --- |
| `revise` 是「下游续接」还是「并行入口」？ | **并行入口**——客户自带素材时**前四段一次不跑**，本层须在**一次调用内**承担前四段全部职责（解析 → 锚定 → 决策 → 编译 → 组装），其纪律是前四段的**并集** | `SYS-Q11` 的「5 段链路」指**节点**（不含 `revise`）；`CFG-007` 的 `stage` 5 值指**模板**——两者读法不同，不矛盾 |

### 2.3 判据盲区的**刻意**规避（两处）

1. **`detect_shape` 判 `ledger` 不采「顶层只有 `unspecified`」**——该判据下，一旦**混装**进别的键，形态即变 `None`、`R37` **永不触发**，缺陷刚好藏在判据盲区里。现判据 = 「**有 `unspecified` 数组 且无 `acts/shots/units/scenes_outline/aigc_meta`**」，使**混装**也能被抓出（`R37` 的 7 样本含「顶层混装契约外键」）。
2. **`rule_ledger_shape` 刻意不判 `reason`／`fill_fallback` 的文本质量**——二者是自由文本，契约未给长度下限，**空串在语义上是缺陷、在契约上是合法值**。判它等于自造**比契约更严的私有口径**（同 `R33` 的取舍）。该取舍已登记为**已知盲区**，交由模板 `guards` 的「台账完整性」自检与人工复核承担。

### 2.4 契约真相的订正

`design_source` **不在交付包契约里**（`characters[]`／`props[]` 均 `additionalProperties:false`）。故 `revise` 层的「客户提供 / 系统提议待确认」二分落 **台账 + `meta.notes`**——`TPL-014`、`CFG-008_manifest.yaml`、`CFG-007_SCHEMA.md` 三处**已同口径**。

## 3 本轮修复的三处缺陷（**均非外部评审提出**）

### 3.1 ⚠️ 最隐蔽的一处：YAML 语法缺陷**不让检查报错，而是让它静默中断**

| 缺陷层 | 症状 | 根因 | 修复 |
| --- | --- | --- | --- |
| `CFG-008_manifest.yaml` **第一层** | `[FAIL] 解析失败：while scanning an alias … expected alphabetic or numeric character, but found '*'` | 8 处**列表项标量以 `**` 开头**（YAML 解析为 alias） | 把强调标记移入句中；终检「全文行首 `**` 项」= 0 |
| 同文件 **第二层** | `mapping values are not allowed here (line 160, column 85)` | plain scalar 内含 ASCII `: ` | 改写该行表述 |
| 同文件 **第三层** | `expected <block end>, but found <scalar> (line 328)` | 双引号标量**提前闭合**，尾句落在引号外 | 闭合引号移到行尾；`yaml.safe_load` 复核 OK |
| `TPL-014_revise_v1.yaml`（**4 处连环**） | 依次：值以 `**` 开头 → 值内 ASCII `: ` → 值以 `{` 开头（flow mapping）→ 反引号作标量首字符 | 同类 | 逐处改写；`yaml.safe_load` OK（`guards` 13 条 / `fallback` 7 键） |

> ⚠️ **关键后果（本轮最大发现）**：`CFG-008_manifest.yaml` **一解析失败**，`validate_templates.py` 就从 **62 项检查掉到 5 项**——表面上只是「失败 1 项」，实际是**检查静默中断**。**教训**：模板校验的「通过项数」本身就是健康指标，项数骤降即等于解析中断，不能只看失败数。

### 3.2 `scan_examples()` 未逐文件重置 `UPSTREAM`（**真实误判**）

`validate_output.py` 的 R31 把**无上游**的 `CASE-005` 判「时长不守恒 3 处」——根因：`scan_examples()` **未在每个文件开始时重置 `UPSTREAM`**，`CASE-005` **静默继承**了 `CASE-002` 的分镜上游。修复：在 `for fn in files:` 循环首行重置。

### 3.3 自检脚本自身的两处误报（**未污染产物**）

- 模板校验器一度报 `TPL-014 FAIL: 分节缺失或为空：['context']`——根因是**我的自检脚本**用 `d["system"]` 取节，而 `sections` 是**字典**；真校验器随后判 `revise_v1` **五项全通过**。
- `CASE-005` §6 曾写「62 通过」（实际含本用例两 JSON 块后为 **64 通过**）→ 已订正并注明 **+2 来自本用例**。
