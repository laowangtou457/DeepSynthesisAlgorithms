## 1. 裁决 A：门禁 BLOCK 分层（`ISSUE-092`）

### 1.1 判据

**只认模型侧 0 BLOCK**。理由（`TEST-005` 实测 3/3 轮）：`human_review.missing` 与 `selfcheck` 第 18 项在自动跑测中**恒真**——人工台账只认人工录入（`_load_human_review` 明写「绝不从模型产物取」），跑测环境没有台账 ⇒ 「全量 0 BLOCK」结构上不可达。

### 1.2 落地（`app/services/delivery_service.py`）

| 字段 | 语义 |
|---|---|
| `blocked` / `block_count` | **语义不变**：全量，交付拒付依据（正式包 `422` 分支仍用它，逐行核对未改） |
| `blocked_model` / `block_count_model` / `model_block_codes` | 模型侧，**跑测验收判据** |
| `blocked_process` / `block_count_process` / `process_block_codes` | 流程项，移交 `PM-005` 真机留证 |
| `blocks[].scope` / `warns[].scope` | 逐条归属侧（`model`／`process`） |
| `scope_policy` | 口径说明（写入报告，取证时不必回读代码） |

**分类规则（单点，不另立清单）**：`_GATE_PROCESS_SCOPE_CODES = _MANIFEST_SIDE_CODES`（同一对象，测试断言 `is` 等价语义）。默认归**模型侧**——方向性错误只准往严的一侧犯。

**边界（刻意保守，已写入代码注释）**：`compliance.*`／`meta.*`／`task.*`／`provider.code` 等仍留模型侧。它们或由服务层代码直接决定（改代码即修复，与重采样无关）、或属合规材料缺项；划进流程项等于替项目方预先认定「不算验收范围」⇒ 当前只排除**清单侧**认定的流程项，其余 fail-closed，必要时另案裁决。

`validator_unavailable` 分支：三栏一律 `None`（「没判」必须能与「判过且干净」区分）。

### 1.4 负向用例（`app/tests/test_delivery.py`，5 例）

仅流程项 ⇒ `blocked=True` 但 `blocked_model=False`；混合 ⇒ 计数拆分且恒等式成立；零条目 ⇒ 三栏干净且非 `None`；**未知码必须归模型侧**（方向性锁）；落盘报告带全部新字段。另有 `_MANIFEST_SIDE_CODES` 内容锁——改集合会当场报警，提示复核分类口径。

## 2. 裁决 C：剧本元素级形态闸（`ISSUE-094`）

### 2.1 现场

真机第 3 轮：`502 上游剧本 acts[2] 不是对象，无法推导逐场调用计划`。两道形态闸（`_guard_artifact_shape` 生成后、`_admit_upstream` 使用前）都只判**顶层**形态 ⇒ 非法剧本入库，直到 `plan_scene_segments()` 才炸；而 `script` 段在 `quality_gate_retry_enabled=false` 下 `max_attempts=1` ⇒ **判出即抛、零重试**。

### 2.2 落地

| 层 | 位置 | 内容 |
|---|---|---|
| 单点判定 | `app/services/segment.py` | 抽出 `script_structure_problems()`（不抛错，返回「文案 ＋ details」清单）；`scene_nos_of()` 改为复用并抛第一条 ⇒ **文案与 details 逐字不变**（有守恒用例） |
| 前移 | `app/services/artifact_contract.py` | `check_shape()` 增**第四层**（仅 `script`）：`reason="script_structure_invalid"`，`error_details={"structure_path": …, "structure_problem_count": …}`；其它三形态零改动 |
| 重试 | `app/services/dialogue_service.py` | `_maybe_generate()` 内**就地**捕获形态闸失败 ⇒ `retry_segs=list(plan)` 全段重采；额度 = `max(质量门禁额度, shape_gate_max_attempts)`；`quality_gate_retry_enabled=false` 时质量门禁仍按 `quality_max_attempts` **独立判停**（否则会给质量门禁偷偷开重试，实测踩过） |
| 开关 | `app/core/config.py` | `shape_gate_retry_enabled=True`、`shape_gate_max_attempts=2`（含首次） |
| 留痕 | `artifact["artifact_shape_retry"]` | 有重试才写（noop 不写）；逐条 `attempt/reason/stage/shape/path/error(≤200)`；`artifact_shape` 仍是字符串（既有断言依赖） |

### 2.3 QA 证伪抓到的真洞（已修，本批）

**`acts` 键存在但不是 `list`**（`str`／`dict`／`null`／`int`）能**穿过**第四层：旧过滤只认定位键（`index`／`act_index`／`scene_nos`），而类型错只有 `acts_type` ⇒ 闸门依旧放行、下游才炸——正是 `ISSUE-094` 要消灭的形态。

修法：新增 `_is_element_level_problem()`，判定改为「有定位键 **或** `acts_type` 存在且 ≠ `"list"`」；`element_structure_path()` 对类型错返回 `acts`（不假装知道第几幕）。补参数化 4 例（`str`/`dict`/`null`/`int`）＋ 1 例分层归属（缺 `acts` **签名键** ⇒ 走第二层 `artifact_shape_mismatch`，不是第四层）。

**刻意保留的边界**：`acts: []`（合法空容器）不在第四层——「恰 3 幕」是交付层 `R6` 判据，且既有 23 个用例以 `acts: []` 构造上游夹具。已由专门用例锁住，改动须显式决策。

### 2.4 同时订正的两处文档漂移

1. **「额度独立」表述**（`config.py`／`dialogue_service.py`／`.env.example` 三处）：真相是**只有判定阈值两路各自，循环上限是共享的一个数** ⇒ 抬高任一侧都会抬高总尝试次数（`quality_gate_retry_enabled=false` 时质量门禁按 `quality_max_attempts` 独立判停）。
2. **`app/.env.example` 的 `APP_QUALITY_GATE_STAGES`**：示例写 `storyboard,shot_prompt`，代码默认 `script,storyboard,shot_prompt`（自 `2120f69`／`PRO-012` 起）⇒ 属示例陈旧，已订正并注明「改这行前先看代码默认值」。
