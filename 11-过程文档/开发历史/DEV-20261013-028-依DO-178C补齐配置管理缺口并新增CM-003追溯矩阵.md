## 3 判定：不作「依据」，只作「方法参照」

| 判据 | 内容 |
| --- | --- |
| **适用域不同** | DO-178C 是**民用航空器适航**标准（FAA / EASA 在型号合格审定中认可）；本工程为**互联网信息服务算法备案**。以适航标准作备案依据属**依据错位**，反削弱材料可信度 |
| **付费且不可分发** | DO-178C / DO-330 由 RTCA 出版发行，**非免费公开标准**，正文**不得抄录**进本项目材料 |
| **结论** | 列入 `CM-001` **§1.5.4「方法参照（非依据）」**，**不进 §1.5.1「引用标准」表**；引用**一律机制级转述、不含原文** |

> ⚠️ **如实**：机制对照系按标准**公开的目标表述与目录**整理，**未购阅标准正文** —— 文中已据实声明「只作方法参照、不作合规承诺」。

### 6.2 关键发现一：**需求有两层**，只查一层必误判

### 9.4 自检纪律的一次**自我违反**（如实登记）

**现象**：首次跑脱敏自检时，「用户名」条目**命中 1 处** —— 定位后确认，**命中源不是工程文件，而是本记录的自检表本身**：表中原写作「用户名 + **真实值** → 0」，把真实值**写进了清单**。

**性质**：违反工程既有的自检纪律 —— **「禁止清单不举真实值（与后果等价）」**。清单一旦举出真实值，它本身就**成为新的泄漏载体**，且**下一次自检必然命中自己**（自我循环）。

**范围**：全工程扫描确认，同型问题存在于 **2 份留痕共 3 处** —— `DEV-20261013-026` 的 §7.2（**2 处**：真实用户名 / 主机名词干、以及占位符的**字串原文**）与**本记录** §9.3（**1 处**：真实用户名）—— **3 处均当场订正**为**类别描述、不举原文**。

**订正后复扫**：三项真实值（用户名 / 主机名前缀 / GitHub 账号名）**全工程残留 = 0**。

> ⚠️ **可复用教训**：**自检表本身也在受检范围内** —— 自检类文档须与工程文件**同标准脱敏**。这已是本工程**第二次**在自检环节自行发现问题（前次为 `grep '\r'` 误报行尾，见 `DEV-20261013-027`）。
