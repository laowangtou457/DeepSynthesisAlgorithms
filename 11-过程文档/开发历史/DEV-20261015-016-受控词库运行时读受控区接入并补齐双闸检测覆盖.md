## 1 动作摘要

`T-005` 内容安全双闸落地时（`DEV-20261015-009`），受控 4 类（`A1-01` / `A1-02` / `A1-03` / `A1-05`）词表**盘上为空壳**，服务只能把它们登记进 `empty_categories` 并据 `fail-closed` 拒放行。本动作落实项目方当日决策**「受控内容不入库、双闸运行时读受控区」**，为双闸补上**第二个词条来源**：受控区实体留在**工程根之外**（`E:\_受控区\`，不受版本控制、不进仓库），服务**在运行时**叠加读取并与合规资料库词表**去重合并**。

效果是**检测覆盖从 27 类补齐到 31 类**（`empty_categories` 由 4 → **0**），`SW-009` / `SW-010` 的「检测覆盖不完整 ⇒ fail-closed 拒放行」**不再实际触发**——即双闸从「结构就绪但覆盖不全」变为「对全部类别均具备检测覆盖」。

| 项 | 结果 |
| --- | --- |
| 数据落点 | **受控区移出工程根**：`E:\_受控区\`（`lexicon_controlled/` · `bank_controlled/` · `refuse_controlled/`，各 **4 文件**；工程根内**已无** `_受控区/`） |
| 读取方式 | **运行时叠加**：`load_lexicon(root, controlled_root)` 第二源；合并**去重**并保留 `sources` 来源标记 |
| 安全边界 | 受控区**具体路径不出现在任何返回值／API 响应中**，只以 `Lexicon.controlled_loaded` **布尔**暴露 |
| 可配置 | 新增 `APP_CONTROLLED_LEXICON_ROOT`（留空按工程布局取默认位置），部署时无须改代码 |
| 未闭环 | 受控资产**机读台账**（`controlled_assets.json`）仍计数全 0 ⇒ `check_quota.py` 仍判「尚未达标」（`ISSUE-034`，归口 `T-058`） |
