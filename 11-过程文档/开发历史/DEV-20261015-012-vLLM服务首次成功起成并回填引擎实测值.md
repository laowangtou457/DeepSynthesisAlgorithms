## 3 ⚠️ 本轮发现的硬约束：「单卡 10 并发」在 16384 全长度下**不成立**

`GPU KV cache size: 88,032 tokens, Maximum concurrency for 16,384 tokens per request: 5.37x`

⇒ **KV Cache 只放得下 5.37 路 16384-token 请求**。而 `SYS-015` 的目标是**单卡 10 并发**。

**换算**：要满足 10 并发，须 **平均上下文 ≤ 88,032 ÷ 10 ≈ 8,803 token**。
这个数字恰好落在「`--max-model-len 16384` − `sampling.max_tokens 8192` = **8,192 输入**」的量级，**与 `TPL-009` 的声明相容** ⇒ **10 并发是可达成的，但前提是上下文预算按「≈8.8k」算，不能按 16384 算**。

**处置（已写进 `OPS-002` §5.1 与 §7.3）**：

- `T-013` 压测**必须同时记录「并发数 × 实际上下文长度」两个维度**；只报「10 并发」会**掩盖**这一约束，且会在长提示词场景下退化成排队（`max-num-seqs=16` 只约束批大小，不约束 KV 容量）。
- 若实测最长分段提示词确实逼近 16384，则**10 并发不可达**，需二选一：① 下调 `--max-model-len`（如 12288）；② 升显存预算（`--gpu-memory-utilization` 已 0.90，余量有限）。

## 4 两条影响**口径**的运行时提示（均非故障）

### 4.1 模型自带 `generation_config.json` 会覆盖 vLLM 默认采样参数

```
WARNING [model.py:1850] Default vLLM sampling parameters have been overridden by the model's
`generation_config.json`: `{'repetition_penalty': 1.05, 'temperature': 0.7, 'top_k': 20, 'top_p': 0.8}`.
If this is not intended, please relaunch vLLM instance with `--generation-config vllm`.
```

⇒ **实际生效的采样参数是这四个值**，不是 vLLM 的默认值。
**备案口径若声明了采样参数，必须以实际生效值为准**；否则须加 `--generation-config vllm` 关掉覆盖。
（本项已列入 `OPS-002` §7.4 待回填台账并标注 ✅ 实测值。）

### 4.2 WSL2 不支持 pinned memory

```
WARNING [buffer_utils.py:47] Pinned memory is not available on this platform;
falling back to device memory for UVA buffers.
```

⇒ **WSL 环境固有限制，不是配置错误**。回退到设备内存对吞吐有轻微影响。
**记入此处以免后人把它当故障排查**（它出现在启动早期，位置显眼、易被误读为异常）。
