## 2 Qwen3Guard-Gen-4B 语义闸部署（T-108 ③）

- **落点**：服务器 GPU7（该卡视频模型仅占 7.6 GiB，空闲约 16.9 GiB，不动 GPU1 生产文本服务）。
- **部署物**：ModelScope 下载 `Qwen/Qwen3Guard-Gen-4B`（8.4 GB）→ `/data/text-llm/models/Qwen3Guard-Gen-4B`；systemd 单元 `safety-guard.service`（`CUDA_VISIBLE_DEVICES=7`、端口 8001、`--max-model-len 4096`、`--max-num-seqs 16`、开机自启）。
- **坑**：`gpu-memory-utilization 0.80` 在 0.10.2 的判定是「util×总显存 ≤ 空闲显存」（0.8×23.5=18.8 > 15.44 ⇒ 拒启），降 **0.60**（14.1G）后正常。
- **隧道**：`_tunnel_text.py` 参数化（`TUNNEL_LOCAL_PORT/REMOTE_PORT` 环境变量），守卫隧道本机 18002 → 服务器 8001。
- **冒烟四例全对**：
  | 场景 | 判定 |
  | --- | --- |
  | 输入侧-炸弹制作 | `Safety: Unsafe / Categories: Violent` |
  | 输入侧-武侠打斗（正常） | `Safety: Safe / Categories: None` |
  | 输入侧-歧视演讲 | `Safety: Unsafe / Categories: Unethical Acts` |
  | 输出侧-拒答话术 | `Safety: Safe / Categories: None / Refusal: Yes` |
- **格式口径**：输入侧审核输出无 `Refusal:` 行（官方格式即如此），机读解析按场景适配。
- **对 ISSUE-070 的选型证据**：守卫把拒答话术判为 `Safe / Refusal: Yes` ⇒ **Qwen3Guard 不会像现有输出词闸那样误拦拒答话术**，支持「应用侧拒答话术走独立通道」的修复设计。
- ⚠️ **现状＝已部署待接线**：语义闸尚未接入 `app/` 运行时（`SafetyService` 集成为后续批次），当前线上三道闸行为未变。
