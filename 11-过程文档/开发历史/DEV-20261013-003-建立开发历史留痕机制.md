## 1 动作摘要

建立**动作粒度**的工程推进留痕机制：新建 `11-过程文档/开发历史/` 子目录，制定命名与编号规则、必备记录要素、巡检与幂等约定、扫描边界与脱敏纪律；并挂载**每 2 小时自动巡检任务**，把工程每一次推进动作沉淀为一份独立文档。

动机：既有过程留痕（`10-评审记录` / `11-过程文档/编制要求`）都是**围绕单份文档**的，跨目录、跨文档的工程推进动作没有归属地——单人开发时工程上下文极易丢失，且备案与安全评估需要「持续投入、持续审核验证」的可核查证据（SYS-007、SYS-012）。

### 规范要点（归档备查）

| 项 | 约定 |
| --- | --- |
| 命名 | `DEV-<YYYYMMDD>-<NNN>-<动作简述>.md`，`NNN` 为当日流水号 |
| 粒度 | **一份文档只记一个动作**；互不相关的对象拆多份 |
| 必备结构 | 五节（动作摘要 / 变更明细 / 影响与关联 / 验证与证据 / 遗留）+ 六项头部字段 |
| 动作类型 | `需求` `架构` `代码` `文档` `结构` `配置` `版本控制` `合规资产` `修复` `决策` `机制` |
| 判定依据 | 双源：`git log`/`git status` + 工作区文件 `mtime`（覆盖未纳版的 `_受控区/`） |
| 幂等 | 同动作只记一次；同批次同文件的多次修改合并为一条 |
| 无新增时 | **不产出文档**，不写占位文件 |
| 无证据不闭环 | 无验证证据的动作不得标「已完成」，须标「未验证」 |
| 排除扫描 | `.git/`、`_受控区/`、funNLP 原始素材、`__pycache__/`、`node_modules/`、`.venv/` |
| 脱敏纪律 | 不出现真实企业名与人名，一律占位符；人员写角色 |
| 只读扫描 | 不修改被记录的正文文档，只写入本目录 |

## 5 遗留

1. **历史动作未全量回填**：2026-10-09 ~ 2026-10-12 的工程动作沉淀在各自目录与 `00-需求/需求文档.md` 修订记录中，本目录只从 2026-10-13 起全量留痕。如需补录，按其实际发生日期编号。
2. **巡检粒度的固有局限**：每 2 小时巡检只能看到「批次净变化」，同一批次内被反复修改又改回的内容无法还原过程。若某个动作的过程本身有留痕价值（如方案比选、返工），应在动作发生时**手工补录**一份更细的记录。
3. **状态文件随仓库提交**：`_巡检状态.json` 会产生提交噪声。当前选择保留（便于跨机续跑与审计巡检确实执行过），如噪声不可接受，可后续加入 `.gitignore` 并改为本地留存。
