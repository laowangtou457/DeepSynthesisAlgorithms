## 0 一句话

**`SW-002` 的验收＝「判据过**且**人工抽检 ≥30 例通过」。本方案把那 30 例**具体化为一张目标清单**（谁、抽什么、验哪条失守），并定义什么时候必须抽、抽完记在哪。**

---

## 1 为什么必须有这一层（而不是继续加脚本）

评审判定得很清楚，我方**完全认同**：`SW-002` 的两项核心承诺**原理上不可机器化**——

| 不可机器化的项 | 为什么 |
| --- | --- |
| `basis` 是否**逐字**摘自客户原话 | 需客户原话原文；产物里**不含**它 |
| **「客户原话里的每个意图是否都被识别出来」**（意图识别**完全性**） | 自然语言的「意图集合」**没有客观真值**——同一句话可合法拆成不同粒度 |

⚠️ 评审的原话是：「**而不是继续在脚本侧硬凑一个近似**（那会造出'看起来很严格、实则无意义'的门槛）」。
**这层是"诚实的兜底"，不是"还没做完的脚本"。**

## 2 抽检对象与样本量

| 项 | 规定 |
| --- | --- |
| 样本量 | **≥30 例**（写入 `REQ-005` 的 `SW-002` 验收标准） |
| 对象 | `modify_v1` 的**真实产物**（含 `artifact` + `change_log` + `unresolved` + `clarification`）与其**客户原话原文**。⚠️ **人工构造的用例不算抽检样本**——它证明的是"样本自身自洽"（`CASE-006`／`CASE-007` 的 §8 已如此声明） |
| 判据 | §3 的**目标清单**（30 例的构成）+ §4 的**逐例核对表** |
| 结论 | 30 例**全部通过**方为合格；任 1 例不合格即**回退该例并登记**，且不合格率 >10% 时**暂停投产**并重评模板 |

## 3 抽检目标清单（30 例的**构成**，可增不可减）

> **怎么用**：按 `target_stage` 与输入类型，从**真实客户会话**里挑 30 例凑齐本表的组合。**每例只要求它落在指定格子里**，不预设答案。

### 3.1 按 `target_stage` 分布（30 例）

| `target_stage` | 例数 | 说明 |
| --- | --- | --- |
| `pack`（交付包） | 10 | ⚠️ **权重最高**——交付包受「八维双落地」约束，**字段→正文牵连**只在此形态发生（`MR-14`），且**只有它有 `generation_trace`**（`MR-13`） |
| `storyboard` | 8 | 数值／设定牵连的主战场（`CASE-006` 的形态） |
| `shot_prompt` | 5 | 与 `pack` 同形态、不同语义阶段，用于比对二者是否被混为一谈 |
| `script` | 4 | 台词语速≤9 字/秒等数值项在此层最易牵连 |
| `synopsis` | 3 | 无 `stage_chain` 上游概念的边界形态 |
| **合计** | **30** | |

### 3.3 覆盖度保证（本表**刻意**保证的六件事）

1. **五类 `target_stage` 全覆盖**，且 `pack` 权重最高（10/30）；
2. **六类输入全覆盖**：单意图明确 / 多意图混装 / 含糊 / 越权 / 命中锁定 / 多轮；
3. **`MR-12` 的四类越权网眼全覆盖**：放宽禁忌（A-16）· 改台词（A-15）· 换角色出演（A-07）· 改交付形态参数（A-22）；
4. **「三处不可脚本化」全被打到**：`basis` 逐字性（全部 30 例）· 意图识别完全性（A-04/A-13/A-20/A-25）· 未点名处逐字保持（A-11/A-12/A-19）；
5. **两个 `pack` 专属形态各有一例**：`MR-14` 字段→正文（A-02/A-03）· `MR-13` 溯源追加（A-10/A-23）；
6. **多轮基准（`MR-06`）有 5 例**（A-09/A-18/A-23/A-30 及任意 1 例扩展）——这条是评审认定的**条款级冲突**位，必须实抽。

## 4 逐例核对表（每例都填这一张）

| 检查 | 判定 | 记录 |
| --- | --- | --- |
| ① `change_log` 的每条 `basis` 是否**逐字**摘自客户原话 | 是／否，并**标出**非逐字处 | |
| ② 客户原话里的**每个意图**是否都被识别（`change_log` ∪ `unresolved` ∪ `questions` 是否**覆盖**原话的全部意图） | 完全覆盖／**漏了哪些** | |
| ③ `artifact` 与原件比对：**未点名处是否逐字保持** | 差异几处、是否与 `change_log` 一一对应 | |
| ④ 锚与编号（本体 8 + 引用面 4）是否**零变化** | 是／否 | |
| ⑤ 该例的**专项重点**（见 §3.2 末列） | 通过／不通过 | |
| ⑥ 判据闸门（`validate_output.py`）在该例上是否全绿 | 退出码 / 报告 | |
