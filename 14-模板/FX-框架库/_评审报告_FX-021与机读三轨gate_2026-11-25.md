## 0. 一页结论

**作为 M1-01 单型金标准样例：通过。** 三轨（人读 md / 机读 yaml / JSON 投影）深度同构、逐值一致，self-check 八条算式全部复算成立，evidence 32 条 E| + 5 条 U| 三轨编号集合一致，gate 带 `--baseline 90` 可稳定复现 `FAIL=0 WARN=0`。`E17` 版本号修正（`v3.0.1→v2.1.1`）已彻底，机读轨零残留。这套产物的严谨度值得保留。

**作为「可复制到剩余 9 型的模板」或「可交后端加载的工程资产」：不通过。** 三个结构性判断：

1. **gate 是单型专用实现，却用了通用命名。** 脚本自注释「当前服务于 M1-01 金标准评审」，但 P03 硬编码 `draft`、P07 需手传 90、P08 依赖 M1-01 的 code 命名、P09 把「≥」写成「==」。10 型复用时必然误杀或漏检。
2. **三轨一致性靠人工维护，没有程序保证。** gate 的 `import` 只有 `json / re / sys`，**不读取 `fx_framework.yaml`**；字段白名单、枚举、阈值、词表全部硬编码在脚本里，而 yaml 另有 `profile_template`。两份各自维护，正是字段规范漂移的根因。
3. **「遵守骨架」的论证对齐了脚本，而非唯一事实源。** 机读四方（json / yaml / `profile_template` / `TOP_FIELDS`）14 键完全同构，档案 §一 也含 `verification` 与 `hooks.extra`；真正缺这两项定义的是骨架 `FX-030` §七 字段规范表。**即：这 4 个文件内部没有失同步，欠账在外部骨架文档**。但档案 §一 写「与 `profile_template` 逐字对齐」、32 条 evidence 中 11 条把机读轨/脚本列为「出处」，构成双轨权威性倒置。

**因此建议**：M1-01 可留作金标准样例；**不得直接复制为其余 9 型**。先做本报告 §6 的「可独立执行」整改（改 gate 与档案即可，不动骨架），再随骨架 1.1.0 处理「须等骨架」项，然后才批量生产。

## 4. 问题清单

分级：**A** = 阻断「作为 9 型模板 / 后端资产复用」；**B** = 脚本工程性；**C** = 档案内容与权威性；**D** = 次要。

### 4.1 A 类（5 项，复用阻断）

**A-01 · gate 单型专用实现却用通用命名**
脚本自注释「当前服务于 M1-01 金标准评审」，但文件名 `check_profile_gate.py` 与 `FX-060` 门层定位都暗示通用。P03 硬编码 `draft`、P07 依赖手传 `90`、P08 依赖 M1-01 的 `BEAT_*` 命名、P09 用 `==`。10 型复用时必然误杀或漏检。
**关闭条件**：同一脚本对 10 型骨架态档案均可运行且结论合理；`status` / `baseline` / 钩子码命名均由配置驱动。

**A-02 · 三轨一致性无程序保证，字段/阈值双份硬编码**
gate 的 `TOP_FIELDS` / `NESTED` / `BEAT_KEYS` / `HOOK_KEYS` / `CODE_RE` / `MENTAL_RE` / `ADJECTIVE_RE` / 阈值全部写死在脚本里，**不读取 `fx_framework.yaml`**；而 yaml 另有 `profile_template` 与 `routing.thresholds`。两处各自维护，必然漂移 —— 这正是 `FX-030` §七 欠账与脚本口径分叉（`MENTAL_RE` 10 词 vs `R-S6` 6 词）的根因。
**关闭条件**：gate 以 `fx_framework.yaml` 为唯一字段/枚举/阈值源，脚本内不再出现第二份定义。

**A-03 · P08 判据对象错位**（T-05 / T-12 / T-13 实证）
见 §3.1。骨架 `R-S3/R-S4` 要求「末场/首场带 `hook_code` 且 ∈ 钩子枚举」，gate 却校验 `beat_sheet` 节拍码字符串。
**关闭条件**：T-05 / T-12 / T-13 三者均得到期望判定。

**A-04 · 判据方向错误**：P09 把 `R-S1` 的「≥」写成「==」（T-01）；档案为迁就 gate 特意让「`is_payoff` 标记数」与 `min_per_ep` 相等（E09 明载），属于**用数据迁就错误判据**。`min_per_ep` 语义是下限，标 2 处兑现应合法。
**关闭条件**：T-01 PASS。

**A-05 · 铁律一 / 铁律二在 gate 无 FAIL 级实现**：P01 单向白名单（T-06）、P15 仅 WARN 且只扫 `sample_line`（T-04）、P14 不查注册表（T-03）、P11 只收 `open/close` 的码（T-07）、`CODE_RE` 不覆盖 `beat_sheet`/`redlines`（T-08/T-09）、P16 不验 `E|` 行（T-10）。
**关闭条件**：T-03/04/06/07/08/09/10 全部被 FAIL 拦截。

**A-06 · 默认调用下最硬判据失效**：P07 的 `--baseline` 可选，不传时 WARN、`exit=0`、结论仍为「可提交人工评审」（T-14）。而 `R-S7` 是「严格相等、禁止约等于」的硬约束。
**关闭条件**：baseline 从 yaml 必填读取或 CLI 必填；T-14 不再判「可提交」。

### 4.3 C 类（档案内容与权威性，6 项）

**C-01 · 双轨权威性倒置（本轮新发现，最重要）**
32 条 `E|` 中有 **11 条**把 `fx_framework.yaml` 或 `check_profile_gate.py` 列为「出处」：`E01/E02/E03/E04/E07/E08/E14/E18/E22/E25/E26`。其中 `E04`（`verification`）**唯一出处**就是 `fx_framework.yaml §四`，`E07`（`beat_sheet.code`）唯一代码依据是 `check_profile_gate.py P08/P11`。按 README §四「md 为唯一事实源、yaml 由 md 派生、冲突以 md 为准」，机读轨与脚本只能作为**实现位置**，不能作为**参数依据**；`K-03` 建立的证据链因此不适合直接用于评审/备案举证。
**建议**：这 11 条回指 `FX-010`/`FX-030` 的对应条款，机读轨降为「实现位置」附注。

**C-02 · `verification` 字段的合规论证对齐了脚本**
机读四方 14 键同构、`FX-021` §一 也列了 `verification`，但骨架 `FX-030` §七 未定义（§2.3）。`L-02`「铁律一保持」的结论成立与否，取决于骨架是否补定义，而不是 gate 是否接受。另 `verification` 的取值枚举与 `draft→verified` 升级条件未定义（`L-03`），档案只能恒为 `unverified`。

**C-03 · 「实测」类别可被无意抬高**
四分类中「实测」仅 1 条（`E17`），而它实为 `TPL-008 v2.1.1` 历史实测教训的**转述**，不是本工程真机实测。四分类未定义「实测」是否限本项目真机，`K-03` 的防退化效果被削弱。

**C-04 · 字符数 / 汉字数双口径**
md §四标注的两套数字**全部准确**（已逐条复算），问题是**口径选择**：用「汉字数 11/11/8/7 ≤12」论证满足开场 12 字口径，而 gate P12 与 `line.max_chars` 用 `len(s)`（含标点，`14/13` 其实超 12）。数字无误，论证用了较宽松的一套。

**C-05 · `SCALE-90-120` 只在人读轨，机读轨不可用**
伸缩规则（含端点表、插值算式）仅写在 `FX-021` §二，yaml / json 无任何伸缩参数；后端加载 yaml 只能得到 90 秒基准表，而 `FX-010` 给的是 `episode_seconds: [90,120]`。算式本身还有三处未定：补余数与 `at_s` 重算的先后顺序、`Σd[i] + r = T` 在补余数后重复计数、`T` 未约束为整数/5 秒倍数。复算显示 T=91/100/119 时余数全给拍 6，使「兑现拍」长于三个「升级拍」，与 §2.3「仅拍 3/4/5/6 拉伸」的意图不完全一致。

**C-06 · 实测结论与人工复算并列表述**
`FX-021` §3.2 把 gate 的 17 条输出与「附加复算」8 项并列。但「顶层键 == `profile_template` 键」「`style_bible_ref` 命中注册表」「20 码全局唯一」「`SCALE` 三点复算」**均不在 gate 判据内**（本报告 §2 已独立复算，结论成立），属人工复算。读者易误认为全部由脚本保证。

**C-07 · 遗留问题与合法空值靠文档兜底**
`hooks.extra=[]`（`L-02`）、`verification=unverified`（`L-03`）、12 条 `L-*` 均无优先级/责任层/关闭条件；复制到 9 份档案会重复登记同一批骨架欠账。

### 4.4 D 类（次要）

md §一「字段清单与 `profile_template` 逐字对齐」实为 25 项路径 vs 14 个顶层键，非同一层级，表述不严谨；gate 输出里保留「取值是否注册需对照 `style_refs`」这类人判提示却标为 PASS；`fx_profile_M1-01.json` 的 `evidence` 为单行长字符串（人读性差，但机器解析无误）。
