# FX-030 剧本框架 · 骨架与注入点

> **层**：F2 剧本　**版本**：`1.1.0`　**建立**：2026-11-25
> **本文不重写 `TPL-008`**。字段清单、判据水位（R1~R40）一律引用原模板；本文只做两件事：
> ① 定义**类型档案往骨架里注入的槽位**；② 定义**小说→剧集**的改编规则（现有模板完全缺失的一环）。

---

## 一、骨架定义（承继，不复制）

剧本产物的字段契约 = `TPL-008_script_v1` 的 `output` 段，摘要如下（**原文为准**）：

```
{ title, logline, genre, style_bible, characters[], props[],
  acts[].scenes[]{ no, location, time_of_day, present[], props_present[],
                   action, dialogue[]{type,speaker,text}, purpose, est_seconds, sfx_hint },
  forbidden_items[], total_est_seconds, unspecified[] }
```

**这些字段全类型共用，任何类型档案都不得增删。** 类型差异只体现在 §三 的注入点上。

---

## 二、骨架的三条不变量

| # | 不变量 | 判据来源 | 为什么不能按类型变 |
| --- | --- | --- | --- |
| 1 | 台词单句 ≤ 15 字；**字数 ÷ 秒数 ≤ 9** | `R15` | 语速是生理上限，与题材无关 |
| 2 | 每场 ≥ 8 秒；`total_est_seconds` = 各场之和 | `R4` / `SR-08` | 时长守恒，否则下游分镜必然不自洽 |
| 3 | 场景 `no` 沿用梗概、角色 `character_id` 全链不改号 | `CFG-007` ②③ | 改号即断链，下游引用全部失效 |

> 实测教训（`TPL-008` v2.1.1）：曾有产物 15 秒塞 224 字台词，语速 14.9 字/秒超限 65%。
> 根因不是条款没写，而是条款是散文、缺「照着算」的动作。故本框架所有约束一律给算式。

## 三、注入点全表（类型档案 → 骨架槽位）

| # | 参数 | 参数类型 | 注入到 | 具体作用 |
| --- | --- | --- | --- | --- |
| 1 | `beat_sheet` | `list[{at_s, dur_s, code, purpose, is_payoff}]` | `acts[].scenes[].purpose` + `est_seconds` | 决定每场功能与秒数分配——**这是类型的核心指纹** |
| 2 | `hooks.open` | `list[{code, formula, sample_line}]` | `scenes[0].action` + `dialogue` | 0–3 秒开场形态 |
| 3 | `hooks.close` | `list[{code, formula, sample_line}]` | 末场末镜的 `action`/`dialogue` | 集尾断点位置与形态 |
| 4 | `payoff` | `{min_per_ep, escalate_every_s}` | 门判据 + `scenes[].purpose` 标注 | 爽点/甜点兑现频率 |
| 5 | `cast` | `{max_speaking, max_on_screen}` | `characters[]` 规模、`scenes[].present[]` | 控人物数防崩脸 |
| 6 | `line` | `{max_chars, char_per_sec, tone_codes[], banned[]}` | `dialogue[]` | 台词句长、语速、语气码、禁用词 |
| 7 | `style_bible_ref` | `STY-*` 引用 | `style_bible` | 画风锚，下游逐字承继 |
| 8 | `asset_bias` | `{prop_focus[], scene_pool[]}` | `props[]`、`scenes[].location` | 该类型高频道具与场景池 |
| 9 | `redlines` | `list[{code, rule, fallback}]` | `forbidden_items[]` | 题材特有审核红线 |
| 10 | `adapt` | `{chars_per_ep, keep[], merge[], rewrite[]}` | 改编阶段（§四） | 小说→剧集的换算与处置规则 |

> **注入点的排他性**：档案只能在上述 10 个槽位写值。想加第 11 个？那是骨架变更，走主版本 + 重跑全部档案，不许就地扩展。

> **P1-1 命名归一（骨架 1.1.0，2026-11-25）**：本表 10 个注入点的编号与槽位语义未变，仅把参数名与 beat 键统一到机读轨 `fx_framework.yaml profile_template` / `check_profile_gate.py NESTED` 的唯一准名（`hooks.open` / `hooks.close` / `line`、5 键 `{at_s, dur_s, code, purpose, is_payoff}`）。`hook_open` / `hook_close` / `line_style` 与 4 键写法作废，仅作历史别名，关闭 `L-07` / `L-08`。

## 四、小说 → 剧集：改编映射（本框架新增，现有模板无此环）

小说是**阅读节奏**，剧集是**观看节奏**，两者不能直接对齐。四个必须做的转换：

### 4.1 体量换算：先按事件，再按字数

```
粗算：集数初值 N₀ = ceil(正文字数 ÷ chars_per_ep)      # chars_per_ep 由档案给区间
精修：以「集尾钩子」重切边界，允许 ±30% 偏离 N₀
```

**禁止**按章节数直接换算。网文章节长度差异极大（1000~5000 字/章），按章分会得到「有的集 30 秒、有的集 5 分钟」。

### 4.2 章节边界 ≠ 集边界，必须重切

| 小说章尾常见 | 剧集尾必须 | 处置 |
| --- | --- | --- |
| 悬念小钩（下章揭晓） | 冲突最高点 | 若章尾冲突强度不足，**向前补一场升级**再断 |
| 情节收束（阶段性完结） | 不能收束 | 把收束点后移，断在「更大的麻烦刚露头」 |
| 抒情/感悟段 | 不可拍 | 删；情绪改由前一场的视觉动作承载 |

**实操**：先在小说上标出全部「冲突峰值点」，再按目标集数均匀取 N 个峰值作为集尾，中间的章节按峰值合并。**先定断点，再定内容**——反过来必失败。

### 4.3 三分类处置（每章必须归入且仅归入一类）

| 类别 | 判定 | 处置 |
| --- | --- | --- |
| **keep 保留** | 主线冲突、关键转折、名场面、金手指觉醒 | 原样改编，只做视觉化改写 |
| **merge 合并** | 同类重复（连续多次打脸、多段日常）、次要支线 | 2~5 个情节点压成 1 场，保留最强的那次 |
| **rewrite 新写** | 开场钩子、集尾钩子、视觉化瞬间 | 小说里没有，必须新写 |

**硬规则**：每集至少 1 处 `rewrite`。
> 依据：小说的章尾钩子几乎不能直接当剧集尾用（`MD-011` §五「结尾必须断在冲突最高点」）。指望「照搬小说」就能有钩子，是本框架拦下的最常见失败。

### 4.4 删减优先级（从上往下删，删到够为止）

```
① 支线剧情  →  ② 次要配角  →  ③ 环境描写  →  ④ 心理描写  →  ⑤ 主线冲突（不动）
```

前四项删到集数达标即停。**心理描写不是「优先删」，是「必须删」**——它不可拍，只能转成外部动作：

| 小说原文 | 禁止直接进剧本 | 正确改写 |
| --- | --- | --- |
| 她心里一阵发凉，原来一切都是骗局 | ❌ `action: "她心里发凉"` | ✅ `action: "她握着茶杯的手停在半空，指节泛白"` |
| 他暗自决定要报复 | ❌ `action: "他暗下决心"` | ✅ `action: "他把照片翻过来扣在桌上"` |

### 4.5 视角归一

小说允许全知视角与内心独白，剧本只允许**摄像机能看到的东西**。
多视角段落必须选一个「承载视角」落到 `scenes[].present[]` 的第一位，其余角色的信息改用对话或动作释放。

## 五、机械约束（承继 + 新增）

### 5.1 承继（不改，原文见 `validate_output.py`）

`R1`~`R6`、`R15`（语速）、`R20`~`R22`、`R4`（时长守恒）、`R6`（三幕结构）。

### 5.2 新增（本框架补的类型侧判据）

| 编号 | 约束 | 校验方式 | 依据 |
| --- | --- | --- | --- |
| `R-S1` | 每集爽点/甜点兑现 ≥ `payoff.min_per_ep` | 计 `beat_sheet[*].is_payoff == true` 的拍数（`purpose="兑现"` 为等价人读标注） | 男频「三件套」纪律：不允许整集只铺垫 |
| `R-S2` | 单集有台词角色 ≤ `cast.max_speaking` | 集合计数 | 人多必崩脸（`MD-022`） |
| `R-S3` | 末场必须带 `hook_code`，且 ∈ `hooks.close[].code` | 枚举比对 | 钩子不可校验＝等于没有 |
| `R-S4` | 首场 `est_seconds ≤ 3`，且带 `hook_code ∈ hooks.open[].code` | 数值 + 枚举 | 黄金 3 秒（`MD-011`） |
| `R-S5` | 每集 `rewrite` 标记 ≥ 1 | 计数 | §4.3 硬规则 |
| `R-S6` | `action` 字段零心理动词 | 词表扫描（想／觉得／心里／暗自／不禁／仿佛） | 不可拍描写 |
| `R-S7` | 差值校验：`Σ est_seconds` 与 `total_est_seconds` 严格相等 | 算式复算 | `R4` 强化，禁止「约等于」 |

> `R-S3`/`R-S4` 成立的前提是**钩子必须有 code**。故 §三 槽位 2/3 的 `hooks.open`/`hooks.close` 强制含 `code` 字段——没有 code 的钩子库是不可校验的散文，不予收录。
> **P1-1 口径归一**：以上 4 处仅统一字段准名与等价复算表述，`R-S1`~`R-S7` 的约束水位、阈值与判据编号**均未变更**，故按 `FX-000 §四` 版本规则属次版本 `1.1.0`。

## 六、F2 门（G2 剧本门）

```
┌ 结构门 ── 场次字段齐全、no 连续、present 与 characters 对得上
├ 语言门 ── R15 语速逐场复算 ≤9；单句 ≤15 字；R-S6 无心理动词
├ 类型门 ── R-S1 爽点次数、R-S2 人物上限、R-S3/R-S4 钩子命中、R-S5 新写标记
├ 守恒门 ── R-S7 时长严格相等
└ 红线门 ── redlines 全部落进 forbidden_items，未出现违规内容
```

**打回规则**：任一门不过 → 判定到具体场号 → **只重跑该集**，不牵连其他集（`G7`）。
已通过 G2 的集不得被下游就地修改（`G8`），要改回 F2 重生成。

## 七、参数档案字段定义（`FX-P01~FX-P10` 的填写规范）

每份档案必须填满下表，**空值标 `null` 并标 `unverified`**，不得留空不得编造：

| 字段 | 类型 | 必填 | 填写规则 |
| --- | --- | --- | --- |
| `genre_id` | 枚举 | ✅ | 取自 `FX-010` 词典，不得自造 |
| `name` | 字符串 | ✅ | 与词典一致 |
| `status` | `skeleton/draft/approved` | ✅ | 未经门检不得标 `approved` |
| `verification` | 枚举（取值待定义） | ✅ | 核验状态标记；当前档案一律 `unverified`。取值枚举与升级条件见 `L-03` / `R1 C-2`，**本版不定义**（不得自造枚举值） |
| `beat_sheet` | list | ✅ | `at_s` 递增且 ≤ 单集秒数；`dur_s` 之和 = 单集秒数；**不得有重叠或空隙** |
| `hooks.open` | list | ✅ | ≥ 3 条，每条带唯一 `code` |
| `hooks.close` | list | ✅ | ≥ 3 条，每条带唯一 `code` |
| `hooks.extra` | list | ✅ | 副类型注入位（`FX-010` §五 S5）；**允许空列表 `[]`**；非空时每条须带唯一 `code`，结构同 `hooks.open` |
| `payoff.min_per_ep` | 整数 | ✅ | 与 `beat_sheet` 的 payoff 标记数一致 |
| `payoff.escalate_every_s` | 整数 | ✅ | 冲突升级间隔 |
| `cast.max_speaking` | 整数 | ✅ | 参考 `MD-002` 的「每集 ≤3 个有台词角色」 |
| `cast.max_on_screen` | 整数 | ✅ | 同框上限，含群演 |
| `line.max_chars` | 整数 | ✅ | 默认 15，重台词类型可下调 |
| `line.char_per_sec` | `[min,max]` | ✅ | 默认 `[4,6]`，硬顶 9 |
| `line.tone_codes` | 枚举列表 | ✅ | 语气码，供配音与字幕对齐 |
| `line.banned` | 字符串列表 | ⬜ | 该类型禁用词 |
| `style_bible_ref` | `STY-*` | ✅ | 见 `FX-050` |
| `asset_bias.prop_focus` | 列表 | ⬜ | 高频道具（如战神：虎符、军牌） |
| `asset_bias.scene_pool` | 列表 | ⬜ | 高频场景（AI 出图稳定的优先写） |
| `redlines` | `list[{code,rule,fallback}]` | ✅ | 每条必须给 `fallback`（踩线时怎么改），只写「禁止」不算完 |
| `adapt.chars_per_ep` | `[min,max]` | ✅ | 单集等效正文字数 |
| `adapt.keep` | 字符串列表 | ✅ | 保留类判定要点，不是具体情节 |
| `adapt.merge` | 字符串列表 | ✅ | 合并类判定要点，不是具体情节 |
| `adapt.rewrite` | 字符串列表 | ✅ | 新写类判定要点，不是具体情节 |
| `evidence` | 字符串 | ✅ | 参数依据：实测 / 对标爆款 / 古典母题编号 |

> **P1-1 字段规范统一（骨架 1.1.0）**：本表 25 行 / 25 路径，与 `profiles/FX-P01_M1-01_战神归来.md` §一、`fx_profile_M1-01.json` / `.yaml`、`fx_framework.yaml profile_template`、`check_profile_gate.py TOP_FIELDS + NESTED` **五方叶子路径集合差集为空**（14 个顶层字段 / 25 个叶子路径）。补入的 `verification` 与 `hooks.extra` 在机读轨本就存在，属文档补齐，**不是新增字段**，不触发 `FX-000 §四` 主版本升版。
