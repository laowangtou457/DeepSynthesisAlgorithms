# FX 框架库（漫剧视频自动化 · 骨架与参数）

> **定位**：`14-模板/` 下的 **MD 系列**是「给人读的范文库」，本目录 **FX 系列**是「给机器执行的框架库」。
> MD 教人怎么写；FX 规定**系统必须怎么写、写完怎么验**。
> 建立：2026-11-25　**骨架版本**：`1.1.0`（2026-11-25 P1 次版本升版；`fx_framework.yaml schema_version` 同步）。

---

## 一、为什么要有这一层

现有资产已经证明了一件事（本工程真机实测反复验证）：

> **散文式条款对模型无效，「照着算」的三步动作才有效。**

`MD-002~007` 六份题材模板是**范文**——模型读了只能模仿字面，拿不到参数；
`MD-010` 的机械约束之所以有效，是因为每条都可复算。

所以本库把「类型知识」从散文改造成**受控参数**，让「任何类型小说 → 标准产出」成为可执行的算法，而不是靠提示词祈祷。

## 二、三层分离（本库的宪法）

```
        ┌─────────────────────────────────────┐
        │  参数层（可变 · 按类型）             │  FX-010 题材档案
        │  节拍表 / 钩子库 / 镜头密度 / 画风锚  │  FX-P01~FX-P10 各型档案
        └─────────────────────────────────────┘
                          ↓ 注入
        ┌─────────────────────────────────────┐
        │  骨架层（不变 · 全类型共用）          │  FX-030 剧本骨架
        │  场次结构 / 镜级字段 / 时长守恒       │  FX-040 分镜骨架
        │  语速算式 / 锚点承继 / 转场规则       │  FX-050 提示词骨架
        └─────────────────────────────────────┘
                          ↓ 产出
        ┌─────────────────────────────────────┐
        │  校验门（客观 · 不合格即打回）        │  FX-060 三层闸
        └─────────────────────────────────────┘
```

**铁律一：骨架唯一。** 任何类型共用同一套字段与机械约束。类型差异**只能**通过参数表达，**不得新增字段**——一旦允许为某类型加字段，骨架就开始腐烂。

**铁律二：参数封闭。** 类型档案的每个参数必须是受控类型（枚举 / 数值区间 / 引用），**不得出现自由散文**。写「节奏明快」等于没写，写 `cut_per_min: [22, 28]` 才能被校验。

**铁律三：门在上游。** 哪一层不合格就在哪一层打回，不允许「先凑合、后面修」。实测教训：母图不满意硬着头皮往下走，后面全是废卡。

## 四、双轨交付约定

| 轨 | 载体 | 读者 | 权威性 |
| --- | --- | --- | --- |
| 人读轨 | `*.md` | 评审、导演、备案举证 | **唯一事实源** |
| 机读轨 | `schema/*.yaml` | 天枢后端、校验脚本 | 由 md 派生 |

- 两者冲突时**以 md 为准**，并立即回改 yaml。
- 本目录**不生成 xlsx**（`14-模板/*.xlsx` 由 `md2xlsx.py` 同步的是 MD 系列，FX 系列不进该流水线）。
- yaml 的 `schema_version` 与总纲版本号同步升级。
