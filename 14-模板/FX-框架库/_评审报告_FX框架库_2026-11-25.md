## 0. 一页结论

FX 框架库是目前这批材料里工程化程度最高的一套设计：三层分离、参数封闭、双轨交付、逐参数 evidence 四分类、UNVERIFIED 单列、12 条遗留问题自登记，都远超普通「范文模板库」。`M1-01` 档案本身质量很高，`fx_framework.yaml` 与 MD 判别词表逐字一致，gate 带 `--baseline 90` 也确实跑出 `FAIL=0 WARN=0`。

但实跑验证后，结论是：**骨架尚未定型，机读轨已与 MD 失同步，而 gate 的「FAIL=0」不足以作为通过证据**。五个阻断项里，有两个是框架自身逻辑不可满足或判据错位，两个是双轨/流程一致性问题，一个是路由算法阈值失效。当前状态下批量铺剩余 9 型，会把同一批骨架矛盾和 12 条遗留问题复制 9 份。

**核心治理判断**：`FX-000` 立了「骨架唯一、门在上游」，但实际是「骨架未定型就先铺参数档案」。`FX-021` §十一 列的 12 条遗留问题中，`L-01 / L-04 / L-06 / L-07 / L-08` 都是**骨架缺陷**；档案遵守铁律一「只提不改」是对的，代价却是骨架带着已知不可满足的判据继续充当唯一事实源。正确顺序是先用 M1-01 单型把骨架与门链打磨定型，再复制。

## 3. 实跑留痕

### 3.1 gate 两种调用

```
带 --baseline 90 ： FAIL=0  WARN=0  → 可提交人工评审
不带 baseline   ： FAIL=0  WARN=1  → 可提交人工评审   [WARN] P07 时长守恒 未传 --baseline，无法判定
```

**两者都判「可提交人工评审」**。即最硬的一条守恒判据 `R-S7` 在默认调用下退化为 WARN，而准入条件只看 `FAIL == 0`。

### 3.2 反向探针（6 组，构造变体 JSON 投喂 gate）

## 4. 问题清单

分级定义：**BLOCKER** = 不改则后续 9 型必然返工或门链不可通过；**MAJOR** = 影响目标达成或机读可执行性；**MINOR** = 可随版本修订一并处理。

### 4.1 BLOCKER（5 项）

**B-01 · F2 门不可满足（G2 必 FAIL）**
- 位置：`FX-030` §二 不变量 2（每场 ≥ 8 秒，`R4`/`SR-08`）vs §五 `R-S4`（首场 `est_seconds ≤ 3`）；§六 G2 门把两者同列为必过项。档案拍 1=3s、拍 2=7s、拍 8=5s 均 <8s。
- 影响：任何按本框架生成的剧本在 G2 语言门/守恒门必然打回，「门在上游」变成「永远过不了门」。`L-04` 记为「待裁决优先级」是**低估严重性** —— 这是约束集无解，不是风格分歧。
- 建议：给钩子场（首场/末场）设显式例外，或把「每场 ≥ 8 秒」改为「非钩子场 ≥ 8 秒」，并在 `R-S3/R-S4` 与 G2 门描述中同步。
- 关闭条件：一份样例剧本在 G2 五项门上可同时通过，且首场 ≤3s、末场定格成立。

**B-02 · 双轨失同步，违反自身宪法**
- 位置：README §四定「MD 唯一事实源、冲突立即回改 yaml」；实测 4 处不一致：
  1. MD §七 13 顶层字段 vs gate/yaml 14，多出的 `verification` **在 MD 中不存在** —— 而 `FX-021` §一 正是以「14/14 全填、零多余字段」论证「铁律一保持」，对齐对象是脚本而非唯一事实源；
  2. §三 注入点名 `hook_open/hook_close/line_style` vs yaml `hooks.open/hooks.close/line`（`L-08`）；
  3. `beat_sheet` §三 4 键 `{at_s, code, purpose, dur_s}` vs §七/profile_template 5 键含 `is_payoff`（`L-07`）；
  4. yaml `profiles` 10 个仍 `skeleton`，档案已 `draft`。
- 影响：后端按 yaml 加载、评审按 MD 举证，同一 `genre_id` 会得到不同字段契约；铁律一「禁止新增字段」的合规性无法自证。
- 建议：骨架 1.1.0 统一为唯一一套字段与命名，MD §七 补 `verification`（或明确其为 gate 层元数据并写进 md），profiles 状态同步。
- 关闭条件：`set(MD §七 顶层键) == set(profile_template 键) == set(TOP_FIELDS)`，且三处命名一致。

**B-03 · 编号溢出未处置**
- 位置：`FX-021~029` 仅 9 位却要装 10 型，顺延撞 `FX-030_剧本框架`；README §三、FX-000 §六、FX-010 §一均写「10 份 / 10 型」。
- 影响：`L-01` 判断准确，但三处骨架文档口径均未回改；第 2 份档案落盘即撞号或超界，历史产物溯源指向错误类型。
- 建议：立即裁决编号方案（另起 `FX-0A*` 段 / 骨架整体改号 / 双位编号），一次性回改 README、FX-000、FX-010、FX-030 四处，并在词典登记「新增型 = 升主版本 + 同时交付档案」的落号规则。
- 关闭条件：10 型各有唯一编号，且与骨架文档编号段无交集；索引表可机械校验。

**B-04 · gate 判据错位与漏检**
- 位置：`R-S3/R-S4` 要求 `hook_code ∈ hooks.open[].code / hooks.close[].code`；gate P08 实际检查 `beat_sheet.code` 是否含字符串 `OPEN`/`CLOSE`。当前档案末拍 `BEAT_CLOSE_HOOK` 含 `CLOSE` 但**不在** `hooks.close` 码集，被判 PASS。
- 叠加缺陷：P09 把 `R-S1` 的「≥」写成 `==`；P01 只查缺失不查多余（探针 F 新增字段零告警）；P14 只查 `STY-` 前缀不查注册表（探针 C）；P15 铁律二仅 WARN 且只扫 `sample_line`（探针 D）；P03 硬编码 `draft`（探针 B）。
- 影响：「FAIL=0 WARN=0」实际只证明字段齐全与算术自洽，**不能作为「可提交评审」的充分条件**；合法输入被误杀（探针 A/B），违规输入被放行（C/D/E/F）。
- 建议：按 §5 阶段 1 重写 gate。
- 关闭条件：本报告 6 组探针全部得到预期判定，且探针集纳入回归。

**B-05 · F0 路由阈值失效**
- 位置：`FX-010` §四 S2 按词频累加 `raw(g)`，S4 用绝对阈值 `score ≥ 6` 与 `lead ≥ 3`，未做长度归一化；位置加权是否作用于排除词、S3 结构加成是否计入 `score`、命中按词频还是布尔，三处均未定义。
- 影响：仿真已证长文本分数线性膨胀，`confidence` 恒 `high`、`decision` 恒 `auto`，`need_user_choice` 永不触发；「类型选错后面全错、必须回 F0 重跑」的保险失效；算法规格不完整，违背 `FX-000`「每条判据可机械复算」。
- 建议：改为归一化口径（每千字命中 / 单词命中封顶 3 次 / 相对占比），补三项规格定义，并按维护规则 3 建回归样本集后重调阈值。
- 关闭条件：同一批样本在 1k / 10k / 30k 字三档长度下路由结果一致；构造混合型文本能触发 `need_user_choice`。

### 4.2 MAJOR（6 项）

**M-01 · 目标与交付范围落差，且缺「单集 → Clip」契约**
库的目标是「任何小说 → 视频短剧」，但 `FX-020`（F1）、`FX-040`（F3）、`FX-050`（F4）、`FX-060`（F5）**全部待建**，当前只覆盖 F0 路由与 F2 节拍参数。更关键：`episode_seconds: [90,120]` 与 `beat_sheet` 里 15 秒的「升级拍」，在单次生成约 5–10 秒的生视频模型上**无法一次出片**；框架内没有「单集 = N 个 Clip」的切分规则，也没有跨 Clip 的角色外观锁 / 光线 / 道具 / 方向连续性契约（`FX-000` §五定义了「锚」，但未落到 F4）。`K-01` 已登记方言未实测，却未体现在范围表里。
建议：先做模型族能力矩阵实测，明确单 Clip 时长上限与首尾帧能力，再定义 Clip 切分与跨 Clip 锚点承继，最后补 FX-040/050/060。

**M-02 · 机读轨结构信号退化成 OR 词表**
`fx_framework.yaml` `routing.structural_signals` 把 MD 的语义条件压成字面词表：`dual_identity` 丢了「同时出现 A 与 B」的 AND；`rebirth_opening` 丢了「回到了 + 时间点」的组合；`rule_list.patterns` 含 `第几条` 这类小说中不会出现的字面串，且 `min_items: 3` 与 `patterns` 没有绑定关系；`watch_ratio` 字段写了 0.1 但无实现说明。后端加载 yaml 也执行不出 MD 的判据。
建议：改用正则 + 共现条件 + `min_items` 绑定，并给出可执行伪码或参考实现。

**M-03 · 参数命名三套并存**
`override_style`（FX-010 S5）/ `style_ref`（§五表、S6、yaml）/ `default_style_ref`（yaml genres）；`extra_hook_codes`（S5）/ `hooks.extra`（yaml、档案）；`hook_open·hook_close·line_style`（FX-030 §三）/ `hooks.open·hooks.close·line`（§七、yaml）。`L-08` 只覆盖了 FX-030 那一套。
建议：在骨架 1.1.0 定唯一命名表，所有文档与代码按表回改。

**M-04 · 两处算式不完整，违背「照着算」**
1. `FX-030` §四 4.1 `N₀ = ceil(正文字数 ÷ chars_per_ep)`，而 `chars_per_ep` 是区间 `[2000,3000]`，除以区间的结果未定义；`±30% 偏离 N₀` 对区间更无从复算。
2. `FX-021` §2.3 伸缩算式：「补余数给拍 6」与「`at_s[i] = Σ_{j<i} d[j]`」的先后顺序未定；`Σ d[i] + r = T` 在补余数后重复计数；`T` 未约束为整数或 5 秒倍数。
建议：给出 `N₀` 的区间取法（如取中值或产出区间），明确补余数在 `at_s` 重算之前完成，并把 SCALE 规则作为受控参数落进机读轨。

**M-05 · 参数封闭铁律二在 gate 无 FAIL 级实现**
`ADJECTIVE_RE` 只给 WARN，且 P12 只扫 `hooks.*.sample_line`；`formula / name / rule / fallback / asset_bias / adapt / evidence` 里的散文表述与心理动词均不拦截；P01 不查多余字段。探针 D、F 已实证。
建议：铁律二升为 FAIL 级全字段扫描，字段白名单改为双向（缺失 + 多余都 FAIL）。

**M-06 · evidence 等级与计量口径**
`E17` 把「模板中转述的历史实测教训（`TPL-008 v2.1.1`）」标为「实测」，与 `K-03` 想建立的证据等级冲突，应归为「沿用现有模板条款（含历史实测记录）」；`FX-021` §四用**汉字数**（11/11/8/7）论证满足「开场 12 字口径」，而 gate P12 与 `line.max_chars` 用的是**字符数**（含标点，14/13 其实超限）。两套口径混用，用较宽松的一套证明合规。
