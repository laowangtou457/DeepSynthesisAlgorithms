# FX-010 题材受控词典与路由规则

> **层**：F0 题材路由　**版本**：`1.1.0`　**建立**：2026-11-25
> **解决的问题**：`genre` 在全链路上是自由字符串，系统无法据此选择节奏参数。本文件把它变成**封闭枚举 + 打分路由**。

---

## 一、编号体系

```
{盘码}{大类序号}-{型序号}        例：M1-01 = 男频 · 逆袭（第1大类）· 战神归来（第1型）
```

| 盘码 | 含义 | 大盘序号 | 大类 |
| --- | --- | --- | --- |
| `M` | 男频 | `M1` | 逆袭打脸 |
| `M` | 男频 | `M2` | 玄幻修仙与末世（第二批） |
| `F` | 女频 | `F1` | 大女主复仇 |
| `F` | 女频 | `F2` | 甜宠古言 |
| `F` | 女频 | `F3` | 年代种田（第二批） |
| `S` | 中性/悬疑 | `S1` | 悬疑怪谈 |
| `S` | 中性/悬疑 | `S2` | 治愈沙雕（第二批） |

> **编号一经分配永不回收**。下线的型保留编号并标 `deprecated`，不得复用给新型——否则历史产物的溯源会指向错误的类型。

**封闭性**：本词典是封闭集。新增一个型 = 升**主**版本 + 必须同时交付该型的参数档案（`FX-P01~FX-P10` 独立号段，映射见 `README §3.1`），否则不予收录。

**排除词的用法**：命中的排除词直接从该型得分中扣 4 分。目的是压住「词面撞车」——「战神」在玄幻文里也常出现，但同一篇里出现「灵根/宗门」说明它是玄幻，不是都市战神。

## 四、路由算法（五步，可机械执行）

```
输入：小说全文 text，可选 override_genre（用户手选，最高优先）
输出：{ primary, secondary?, confidence, evidence[], decision }
```

**S0 · 用户手选优先**
若调用方传入 `override_genre`，直接采用，`decision = "user_override"`，跳过 S1~S4。
> 不让算法覆盖人的判断——用户已明确选型时，路由只做记录不做决策。

**S1 · 归一化**
剥离：书名页、作者感言、章节标题行（`第\d+章`）、广告尾注。只留正文用于打分。
> 不剥离会污染打分：有的书正文 3 万字，作者感言 5 千字。

**S2 · 词面打分**

```
raw(g) = Σ(命中强词 × 3) + Σ(命中一般词 × 2) + Σ(命中弱词 × 1) − Σ(命中排除词 × 4)
```

再乘**位置加权**：命中出现在全文**前 10%**位置的词，权重 ×1.5。
> 依据：网文开头是「定调位」，作者在前 10% 就会把类型标签全打出来。越靠后越可能是插叙或玩笑。

**S3 · 结构信号（不依赖词，防止词表漏网）**

| 信号 | 判定条件 | 加成 |
| --- | --- | --- |
| 重生开局 | 前 10% 出现「再次睁眼 / 回到了 + 时间点 / 死前」句式 | `F1-02` +5 |
| 规则清单 | 出现编号式规则条目（「第一条」「规则三：」）≥ 3 条 | `S1-02` +5 |
| 身份双轨 | 前 10% 同时出现「废物/瞧不起」与「实为/真实身份」 | `M1-01` +3 |
| 案件开场 | 前 10% 出现尸体/报案/勘查现场描写 | `S1-01` +3 |
| 婚约开场 | 前 10% 出现婚约/退婚/嫁娶冲突 | `F2-01` +3 |

**S4 · 裁决**

```
主类型 primary = argmax(score)
通过条件：score[primary] ≥ 6  且  score[primary] − score[second] ≥ 3
```

- **通过** → `confidence = high`（差距 ≥ 6）/ `medium`（差距 3~5），进入 S5。
- **不通过** → `decision = "need_user_choice"`，返回 **Top3 候选 + 各自命中词证据**，**停止流水线，等用户选**。

> ⚠️ **路由不猜**。类型选错，后面节拍表、钩子库、镜头密度、画风锚全是错的，而且改不回来——必须回 F0 重跑全部下游。宁可停一次问人，不要错一条流水线。

**S5 · 副类型（混合型处理）**

若 `score[second] ≥ score[primary] × 0.6` 且属于不同大类，记 `secondary`。
副类型的权限**只有两项**：`override_style`（画风）、`extra_hook_codes`（追加钩子）。
**节拍表、镜头密度、爽点频率一律以主类型为准**——两套节拍叠加必崩。

**S6 · 输出契约**

```json
{
  "primary": "M1-01",
  "secondary": "M1-03",
  "confidence": "high",
  "decision": "auto",
  "evidence": [
    {"genre_id": "M1-01", "score": 27, "hits": ["战神×3", "北境×2", "军令×1"]},
    {"genre_id": "M1-03", "score": 11, "hits": ["神医×2", "针灸×1"]},
    {"genre_id": "M1-02", "score": 4,  "hits": [], "excluded_by": ["军令"]}
  ],
  "profile_ref": "FX-P01#M1-01",
  "style_ref": "STY-KR-WEBTOON"
}
```

`evidence` 必须留存——它是「为什么判成这一型」的审计凭证，剧本出问题时要能回溯到路由决策。

## 五、参数覆盖规则

档案的默认值可被三层覆盖，优先级从高到低：

| 优先级 | 来源 | 允许覆盖的字段 | 说明 |
| --- | --- | --- | --- |
| 1 | 用户显式指定 | 全部 | 在项目配置里写死，路由与档案都不得改 |
| 2 | 副类型 | `style_ref`、`hooks.extra` | 仅此两项，见 S5 |
| 3 | 题材档案默认值 | — | 兜底 |

**禁止**：运行时凭「这条小说感觉不太一样」临时改节拍表。要改就改档案，走版本流程。

## 六、维护规则

| # | 规则 | 理由 |
| --- | --- | --- |
| 1 | 判别词只增不删，废弃的标 `deprecated` 并保留 | 删词会让历史路由结果无法复现 |
| 2 | 新增判别词需附「来自哪本/哪类样本」 | 防止凭感觉加词，越加越糊 |
| 3 | 每次调整判别词后，必须用同一批回归样本重跑，记录命中率变化 | 改词会连带影响其他型，不做回归等于盲改 |
| 4 | 单型判别词总数控制在 20 个以内 | 词太多等于没有判别力 |
| 5 | 排除词必须是**另一型的强判别词**，不能自造 | 排除词的作用是型间互斥，自造词无判别力 |
