# 提示词模板 · 样例与评测

> 本目录存放每个模板的「输入 → 输出 → 评测结论」用例，是备案材料中**二次开发痕迹**的直接证据。
> 建立 2026-10-13。

---

## 一、本目录解决什么问题

模板本体（`../templates/*.yaml`）只能证明「写了什么」，**证明不了「验证过」**。

备案审查关注的是：这套提示词是否经过**自主设计—实测—迭代**，而不是从开源库复制。本目录的三段式记录（输入／输出／评测）就是这条证据链。

| 记录项 | 证明什么 |
| --- | --- |
| 输入 | 面对什么业务场景 |
| 输出 | 模板实际产出（或目标产出） |
| 评测结论 | 逐条对照该需求的验收标准，结论可核查 |

---

## 二、命名与文件约定

| 项 | 约定 |
| --- | --- |
| 文件名 | `<模板id去版本>-case<两位序号>.md`，如 `synopsis-case01.md` |
| 一份文件 | 只记一个用例，不合并 |
| 用例来源 | 优先用**真实业务场景**（脱敏后）；无真实场景时用构造用例，但须在文件内注明 |
| 采样参数 | 必须记录（temperature / max_tokens），否则结果不可复现 |

## 三、必备结构

每个样例文件必须含以下五节，缺一不可：

1. **用例信息** —— 用例编号、对应需求编号（SW-xxx）、模板 id 与 version、用例来源
2. **输入** —— 变量的实际取值，按模板 `variables` 逐项列出
3. **输出** —— 模型实际输出；尚无实测时放**目标输出样例**并标「待回填」
4. **评测结论** —— 逐条对照该需求的「验收标准」字段，给通过／不通过与理由
5. **验证状态** —— `已实测` / `未验证` / `已实测待复核`

> **纪律**：未跑过模型的，验证状态一律写 **未验证**。项目规范明确「无验证证据不得标已完成」——把「人工构造的期望输出」冒充成「实测输出」是留痕造假。

## 四、评测的执行方式

| 层 | 手段 | 可自动化的部分 |
| --- | --- | --- |
| 结构合规 | JSON Schema 校验（`delivery/validate_pack.py` 同源思路） | ✅ 全自动 |
| 覆盖完整性 | `covered_points` 与输入要点逐条比对 | ✅ 可脚本化 |
| 无编造 | 抽取输出中所有专名 → 回溯输入，找不到来源即失败 | ✅ 可脚本化 |
| **缺口交接**（2026-10-13 新增） | 核查「下游必填字段的缺失是否被标记」：凡字段值为「未指定」者，须在 `unspecified` 中有对应条目；**视觉锚点类**（角色外观／年龄段、场景空间与时相、风格线索、道具外观）的缺失须单列且 `fill_stage=script`；**剧本层起，「待客户确认」类缺口的 `owner` 必须为『客户』且 `fill_stage` 回归本层 `script`**（下游无人能补，见 R21） | ✅ 可脚本化 |
| **镜头语言质量门**（2026-10-13 新增，SW-006 起） | 11 项量化阈值（运镜/景别覆盖 100%、静止镜 ≤40%、运镜类型数 ≥`min(5,max(2,⌈镜数/4⌉))`、单一运镜 ≤35%、角度 ≥40%、光学 ≥30%、构图 ≥50%、轴线 ≥30%、光线 ≥40%、画面结果 ≥60%）；**整片与逐生成单元各判一次**。阈值与容差算法直接引用 `audit_shots.py` 的 `GATE` | ✅ 全自动（`validate_output.py` R19） |
| 内容质量 | 人工阅读（叙事是否成立、文风是否合适） | ❌ 须人工 |

> ⚠️ **质量门的两个层次不要混**：`validate_output.py` 判的是**结构化字段是否有值**（SW-006 的产物）；
> `audit_shots.py` 判的是**适配投喂文本**（SW-007 的产物）。两者对象不同——上游判定通过**不等于**下游文本判定通过，
> SW-007 完成后必须对文本再跑一次（规范 §4.8）。

三层里的前两层必须**脚本产出结论**，不得只写「人工看过没问题」——这是本项目在镜头语言质量门上已经确立的口径（「靠人记着做的事，等于没人做」）。

**已落成的校验脚本**（均在 `03-工程代码/prompts/` 下，2026-10-13 起）：

| 脚本 | 校验对象 | 规则 |
| --- | --- | --- |
| `validate_templates.py` | 模板与清单（`manifest.yaml` / `templates/*.yaml` / 本目录 `*.md`） | 五节结构齐备、变量引用一致性、必备字段与 file 指向 |
| `validate_output.py` | **产物 JSON**（本目录用例内的构造产物，或模型真实输出） | **R1~R22 共 22 条**：<br>· 梗概/剧本层 8 条——`purpose` 封闭枚举、`fill_stage` 枚举、场号连续性、时长求和、必备顶层字段、三幕归属、**`dialogue.type` 三值枚举**（R20）、**缺口台账 `owner` 责任归属**（R21：`owner=客户` 者 `fill_stage` 必须为本层 `script`）、**场时长下限 ≥8 秒**（R22）<br>· **分镜层 13 条**（2026-10-13 新增）——`shot_id` 格式与唯一、场内镜号连续、单元↔镜头双向链接、**单元成员 2–3 镜**、**单元内运镜不重复**、整秒、**时长区间 4–15s**、时长求和、**台词语速 ≤9 字/秒**、景别/运镜枚举、`static`/`pov` 禁带幅度速度、**转场单侧表达**、**11 项质量门（整片 + 逐单元）** |

> 两个脚本**职责不重叠**：前者管「模板写了什么」，后者管「产物长什么样」。
> 模型就绪后，对真实输出执行 `validate_output.py --file <输出.json>` 即可产出机器可读报告；
> 分镜层还可用 `--duration-bounds 4-15` 覆盖单镜时长区间（默认即 H3 口径）。
> **两个脚本均已做过反向测试**（故意构造越界样本，确认规则真的会触发）——只跑通过样本证明不了校验器有效。

**关于「缺口交接」层（依导演视角评审 D-03/D-07/R-02，2026-10-13 依 `SR-02`/`SR-03` 扩充）**：梗概层的「未指定」机制若只覆盖叙事层，视觉层的空白就会**既不可见也不可追溯**，只能由下游自行编造或各自决定。故该层评测须回答四问：① `unspecified` 里是否含视觉锚点类条目？② 每个「未指定」字段是否有对应条目？③ **「待客户确认」类缺口的 `owner` 是否为『客户』、`fill_stage` 是否回归本层 `script`？**（若一律前移到下游阶段，台账的**记录功能成立、交接功能不成立**——下游既无权补、也不必停）④ **每条是否给出 `upstream_field`（上游原始字段路径）**，使跨层路径映射可机器比对（上游是 `protagonist.name`、本层是 `characters[0].name`，路径改写了但映射须写明）？四问皆「是」才算通过。
