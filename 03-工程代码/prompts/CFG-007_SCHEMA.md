#       ⑦ 提示词解析重构阶段（stage=revise，SW-008）是**重构入口层**（Restructuring /
#          Reverse-Entry Layer）——**链路的第二个起点**，2026-10-14 建立。一句话边界——
#          **把客户已有的东西，解析成我们有锚、有决策、有表达的标准交付包**：
#          **不重写客户的故事，不替换客户已定的镜头意图，只做结构化、补齐与规范化**。
#          ⚠️ **它不是下游续接，是并行入口**：客户自带素材（提示词清单／剧本／旧交付包／混合）时，
#            前四段**一次都不跑**，故本层在**一次调用内**承担了前四段的全部职责
#            （① 解析 parse＝本层独有 ② 锚定 anchor＝SW-005 ③ 决策 decide＝SW-006
#             ④ 编译 compile＝SW-007 ⑤ 组装 assemble＝SW-007），
#            其 `system`／`guards` 是**前四段纪律的并集**。
#          两条独有纪律（对应其他层的「承继守恒」）：
#            · **素材守恒**（第一条）：素材中**已明确**者只结构化、不改写——事实类
#              （人名／地名／年代／数值／**台词原文**）一字不改；镜头意图原样承接为决策字段；
#              风格描述原样承继为 `style_bible` 的锚。**只有素材未给定的部分才补**。
#            · **粒度守恒**（第二条）：**不得改变素材已定的镜头数量与时序**，不得重写台词与结局；
#              仅 `source_kind=script`（素材未切镜）时可由本层补切镜并在 `meta.notes` 留痕。
#              ⚠️ 改客户的故事不是「重构」而是「另做」，属新需求、须走前四段。
#          **六类必改＝本层允许「不照抄素材」的全部情形**（比 SW-007 多三类，因输入是**自由文本**
#          而非结构化 JSON、且**没有上游可承继**；`v1.2.0` 依 `RR-02` 由「五类」扩为六类）：
#          ① 形态改写（文本→字段，本层存在的理由）；② 规范化（取值归一词表，
#          如「推镜头」→`push_in`、「空镜」→按语义映射为 `shot_size` 值；词表外说法按语义映射
#          最近值并在 `meta.notes` 写明依据，**禁自造 code**）；③ 拆分（「决策+说明」同句→字段取
#          code、说明移入正文）；④ 删冗余（制作备注／内部批注／平台参数指令如 `--ar 16:9`
#          **不得进正文**）；⑤ 补缺口（**设计类锚**由本层提议）；⑥ **补镜头决策**（素材未明确处的
#          时长／`camera.height`／`roll`／`optics`／构图／轴线／画面结果——**不算改写客户内容**，
#          但须在 `meta.notes` 声明**补出范围**）。**不属这六类的改写一律禁止**——
#          尤其**不得「顺手润色」客户的台词或镜头描述**。
#          **缺口台账必须由本层自己产出**（与链路前段的**最易漏**差别）：交付包**没有**
#          `unspecified` 段（规范 §3.1 顶层八段无台账段），而链路前段的台账「留在上游产物自身」——
#          **本层没有上游可依附**，故必须**另行产出**独立产物 `<pack_id>.unspecified.json`
#          （七项字段与链路前段同构），`segment` 为此**独有一个粒度 `gap_ledger`**。
#          ⚠️ **不得把台账塞进交付包**——会被判据 **R36** 与 schema 的
#             `additionalProperties:false` 拒收（R36 的字段集直接读交付 schema）。
#          ⚠️ **`fill_stage` 一律取 `revise`**（本层即台账的责任阶段，**无处可推**，见枚举登记）。
#          **`stage_chain` 照实填 `["revise"]`、`templates` 只含 `revise_v1`**——
#            本层没有跑过那四段模板，填它们＝**伪造溯源**。
#            ✅ **曾暴露的契约侧缺口 `ISSUE-017` 已闭环（2026-10-14）**：交付 schema 的
#              `stage_chain.items.enum` 原只有 `synopsis｜script｜storyboard｜shot_prompt` 四值，

#                           校验：`validate_output.py` **R38**（形态 `modify`）／**R39**（形态 `drift_report`）；
#                                 `target_stage` 的取值域与两种形态的枚举见【封闭枚举登记】。
#   R40 DRIFT_ARCHIVE_SHAPE **漂移报告归档件的形态与轮次命名**（`v1.3.0` 依项目方对 `PRO-004` §7 的
#                           裁决新增）。与 R39 判的是**同一份产物**，但**对象不同**：R39 判
#                           「报告本身合不合规」，R40 判「**归档件**合不合规」。判据三条：
#                             ① **文件名须含轮次号**——`<pack_id>.drift.r<N>.json`（`N` 为 ≥1 正整数、
#                                **无前导零**）。评审硬要求：「没有轮次号，'时间序列'这个说法就不成立」；
#                             ② **声明与内容形态一致**——文件名声明了归档身份，内容形态就必须是
#                                `drift_report`；误把别的产物改成这个名（或反之）在此暴露
#                                （降级产物等情形会同时带上其本形态的判据，两条结论**并列不掩盖**）；
#                             ③ **顶层恰好 5 键**——与 R39 **同源同值**（共用 `DRIFT_TOP_KEYS`）。
#                                此处**独立复检**而非"R39 已判过就跳过"的理由：归档件是**会被单独
#                                摘出送检**的东西（从交付包 `qa/` 或服务层留档目录调取**单份**），
#                                送检时不能假定 R39 已在别处跑过。
#                           ⚠️ **触发条件是声明式的**：basename 含 `.drift.` 即以归档件论处——
#                              **不是**「扫目录看有没有归档」。⚠️ 该判定**必须放在所有形态分支之前**
#                              （`pack`／`ledger`／`modify` 三个分支各自 `return`，放后面则
#                              「声明为归档件但形态不符」会落进**判据盲区**——首版实现即踩此坑，
#                              由归档件负向样本当场暴露并修正）。
#                           ⚠️ **刻意不判存在性**：不回答「这一轮到底有没有落盘」。该义务由**声明性
#                              义务**承担（规范 §1.4 的**条件必须** ＋ `manifest.json` 的「列出全部
#                              文件」既有义务），**不硬凑脚本近似**——与 **R37** 的既有取向一致。
#                           ⚠️ **能力边界**：本条判**形态与声明一致性**，**判不了**「该轮报告的内容
#                              对不对」（那是 R39 与人工抽检的事），也**判不了**「归档有没有发生」。
#                           校验：`validate_output.py` **R40**（触发＝文件名含 `.drift.`；
#                                 五形态样本见 `tests/negtest_pack_rules.py` 的 `DRIFT_ARCHIVE_CASES`）。
