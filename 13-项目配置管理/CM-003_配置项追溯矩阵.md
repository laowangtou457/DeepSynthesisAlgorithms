## 0 一句话

本矩阵回答两个方向的同一个问题：**每个已建产物能不能上溯到一条需求**（反向可溯，防「无源实现」），**每条已确认的需求有没有下游承载**（正向可追，防「纸面需求」）。
**缺口如实登记、并落台账编号**，不粉饰为已满足。

## 1 追溯模型与口径

### 1.1 追溯链（六段）

```
需求（F-xxx / SW-xxx）
  → 规范与契约（SPEC-008 交付规范 · CFG-005/006 交付 schema · CFG-007 枚举真值来源）
    → 实现资产（TPL-xxx 提示词模板 · CFG-008 模板登记）
      → 用例与样例（CASE-xxx 用例 · CFG-003/004 示例包）
        → 机器验证（validate_templates · validate_output R1~R40 · validate_pack 门禁 · negtest 负向 95 项）
          → 同行评审（REV-<对象标号>-<序号> 三件套）
```

**双向读法**：**正向**（§2）从左往右查需求是否落地；**反向**（§3）从右往左查产物是否有据。

### 1.2 需求的两层来源（不可互相替代）

| 层 | 文档 | 编号形态 | 覆盖对象 |
| --- | --- | --- | --- |
| **顶层能力需求** | `REQ-006_需求文档.md`（**V2.13**）§3 | `F-xxx` 功能 · `N-xxx` 非功能 | 算法能力、提示资产、安全合规、接口 —— **通用模板的依据在此层** |
| **软件级需求** | `REQ-005_软件级需求文档.md`（**V2.6**）§2 | `SW-xxx` · `SW-I0x` · `SW-D0x` · `SW-1xx` | 功能模块、接口、数据、非功能 —— **AI 漫剧链路的依据在此层** |

⚠️ **两层分工实测**：9 份通用文本处理模板在 `REQ-005` 中**无对应条目**，其依据只在 `REQ-006` §3.1~§3.3；AI 漫剧链路 5 段（含其**支撑模板** `SW-002` 对话式修改）在 `REQ-006` 中仅有交付物级登记（`D-002` / `D-017`），其**功能依据只在 `REQ-005`**。**只查一层必然误判为「孤儿」**。

### 1.3 状态口径（防误读，重要）

需求文档中条目的「状态」列**指服务化实现状态**，**不含提示词资产**：

| 标记 | 含义 |
| --- | --- |
| ⬜ **服务未开发** | `REQ-005` 标「待开发」—— 指后端服务 / 接口未实现 |
| ✅ **资产已建** | 该需求对应的**提示词模板 / 契约 / 用例已建成品并通过机器校验** |
| ✅ **运行态（离线工具，2026-10-14 新增口径）** | 指**离线生成 / 校验工具**可跑通并**实际产出交付件**（如 `SW-025` 的 `tools/export_models.py` → `exports/<model>/<model>.txt`）。⚠️ **仍不等于服务化**——工具是**生成期离线件**，`REQ-005` 的服务实现状态**不变**。此项为 `T-072` 落地后设，**防把「工具可跑」误读为「服务已通」** |
| 🟨 **服务代码已实现·未上机（2026-10-15 新增口径）** | 指**后端服务代码已写就绪且单测全绿**，但**推理后端尚未实际运行**（如 `SW-004`~`SW-008` 依赖的 vLLM 服务未起）。⚠️ **不得读作「服务已通」**——`REQ-005` 的服务实现状态**仍为「待开发」**，本口径只补记「代码侧就绪」这一事实。**三项未上机条件**：① `WSL2` 组件未安装（需管理员，`ISSUE-030`）；② `OPS-002` §7 上机清单未回填；③ `SW-I03`／`I04`／`I05`／`I08` 仍显式 501、无内容安全（`T-005` 未接入）。此项为 `T-004` 引擎侧接线后设，**与上一条的区别＝离线工具 vs 在线服务代码** |

故 `SW-002` 与 `SW-004`~`SW-008` 呈「**资产已建 + 服务未开发**」的复合态 —— **两者不矛盾**，本矩阵据实并列，不合并为单一状态。`SW-025` 自 2026-10-14 起呈「**资产已建 + 运行态（离线工具）+ 服务未开发**」**三态并列**；`SW-004`~`SW-008` 自 2026-10-15 起追加第 **4** 态「**服务代码已实现·未上机**」——**仍不合并为单一状态**。

## 5 维护规则

1. **随动作同步**：需求新增／变更、产物新增／改名、评审闭环 → **同一动作内**更新本矩阵（与 `CM-002` 取号同步登记）。
2. **缺口即登记**：扫描出的断链**必须落台账编号**（`ISSUE-*`）或明确「当前阶段不适用」，**不得只写在矩阵里**。
3. **禁止「凑满」**：反向追溯**不得为消除孤儿而虚构依据** —— 无依据就写「无依据」（本工程纪律：事实类不得编造）。
4. **口径随需求文档**：状态列以 `REQ-006`／`REQ-005` 为准，本矩阵**不另立状态口径**，避免两处不一致。
5. **覆盖面随范围演进**：本矩阵当前覆盖**提示资产与交付契约**；`D-005` 工程骨架开工后**须扩至服务化实现**（追溯链增加「接口／模块」一层），届时本文件升主版本。
